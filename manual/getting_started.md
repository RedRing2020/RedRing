# 動かす

RedRing のプレビュー版は、Windows 用の配布物（zip）を使うか、ソースからビルドして起動します。配布物は v0.1.3 から添えています。

## 動く環境

- OS: Windows で動作を確かめています（Linux・macOS は、GPU の描画の基盤 wgpu が対応するため動く見込みですが、確かめていません）
- GPU: Vulkan・DirectX 12・Metal のいずれかに対応する GPU
- ソースからビルドする場合: Rust（[rustup](https://rustup.rs/) で入れます。版はリポジトリの `rust-toolchain.toml` で決めていて、ビルドするときに rustup がその版を使います）と Git

素材の精度を細かくする（例えば 0.01 mm）と、メモリと GPU の負荷が大きくなります。最初は既定の精度（0.05 mm）で試してください。

ピックフィードを細かくする・工具を小さくするなどで、ツールパスが大きくなる条件では、工程リストの「計算」「再計算」「全工程を計算」（「適用と同時に計算する」を含む）を押したときに、計算を始める前にツールパスの生成に使うメモリを見積もります。

- 確かめる目安（既定は 2 GB）以上になる工程があるときは、工程ごとの見積もりを出して、計算するかを確かめます。上限に近い（上限の 8 割以上）工程には、途中で止まることがあると添えます。「やめる」を選ぶと計算しません（全工程を計算では、どの工程も計算しません）
- 計算に使うメモリの上限（既定は、PC の物理メモリの半分と 8 GB の小さい方）を超える工程は、計算しません。ステータスバーに見積もりの大きさを出します。ピックフィードなどの条件を見直してください
- 見積もりは、走査ラインの一部を実際に計算して全体に掛け戻したもので、目安です
- 確かめる目安と上限は、ジョブマネージャーの設定のファイルで変えられます（下の「ジョブマネージャー」の、ツールパスの大きさの目安と上限）

見積もりが外れて、計算の途中でツールパスの点が多くなりすぎたときも、ツールパス生成はメモリを使い切る前に止まります。ジョブマネージャーでは、そのジョブの失敗の理由に「ツールパスの点が多すぎるため、計算を止めました」と出ます。CAD/CAM のアプリでも、その工程を選ぶと、ステータスバーの右に同じ理由と、ピックフィードなどの条件を見直すことを出します。

## 配布物から起動する（Windows）

1. [GitHub のリリース](https://github.com/RedRing2020/RedRing/releases) から、`redring-<版>-windows-x86_64.zip` と `SHA256SUMS.txt` を取ってきます
2. zip を確かめます（下の「配布物を確かめる」）
3. zip を、書き込みのできるフォルダ（例えばドキュメントの下）に展開し、`redring.exe` をダブルクリックして起動します。ログは起動したときの作業フォルダ（ダブルクリックで起動した場合は展開したフォルダ）の `logs` に書くため、`Program Files` の下には置かないでください。ショートカットから起動する場合は、ショートカットの「作業フォルダー」を展開したフォルダにしてください

実行ファイルにはまだコード署名がないため、初めて起動するときに Windows の SmartScreen が「Windows によって PC が保護されました」と出します。配布物を確かめたうえで、「詳細情報」→「実行」で起動してください。

### 配布物を確かめる

取ってくる途中で壊れていないことは、zip の SHA-256 が `SHA256SUMS.txt` の値と同じであることで確かめます。PowerShell で次を実行し、`True` と出れば同じです（`<値>` には `SHA256SUMS.txt` の zip の行の値を入れます）。

```powershell
(Get-FileHash .\redring-v0.1.3-windows-x86_64.zip -Algorithm SHA256).Hash -eq '<値>'
```

zip が置き換えられていないこと（RedRing のリポジトリの CI で、リリースのタグからビルドしたものであること）は、[GitHub CLI](https://cli.github.com/) で確かめます。リリースの資産ごと置き換えられた場合はチェックサムも置き換えられるため、こちらで確かめるのが確実です。

```powershell
gh attestation verify .\redring-v0.1.3-windows-x86_64.zip --repo RedRing2020/RedRing
```

リリースには、使っている依存のクレートの一覧（SBOM。CycloneDX の形式の `.cdx.json`）も添えています。

## ソースからビルドして起動する

```bash
git clone https://github.com/RedRing2020/RedRing.git
cd RedRing
git checkout v0.1.3
cargo build --release
cargo run --release -p redring
```

- `cargo build --release` で、アプリと一緒にジョブマネージャー（`redring-job-manager`）とランナー（`redring-batch-runner`）をビルドします。この 2 つがないと、ツールパス生成と切削シミュレーションを計算できません（形状の読み込み・表示はできます）。`cargo run` は、アプリ（`-p redring`）を指定して起動します
- `--release` を付けると、ツールパス生成と切削シミュレーションが速くなります（付けないと、計算に何倍も時間がかかります）
- 最初のビルドは、依存のクレートを取ってくるため数分かかります
- 起動すると、メニューバーのあるウィンドウが開きます。続けて [画面と操作](./screen_and_controls.md) と [切削シミュレーション](./cutting_simulation_demo.md) を参照してください

## ジョブマネージャー

ツールパス生成と切削シミュレーションの計算は、アプリとは別のジョブマネージャー（`redring-job-manager`）が行います。配布物の zip には、アプリ（`redring.exe`）・ジョブマネージャー・ランナー（`redring-batch-runner.exe`）が入っています。3 つは同じフォルダに置いたまま使ってください。

- ジョブマネージャーは、最初に「計算」したときにアプリが起動します（そのときはウィンドウを出しません）。計算の間もアプリの画面は止まりません
- `redring-job-manager.exe` を起動すると、ジョブの一覧のウィンドウを開きます。ジョブの状態・失敗の理由・ログを確かめられます。すでに動いているときは、動いているジョブマネージャーのウィンドウを開きます
  - 計算中のジョブは、状態の欄に、進み具合の割合を書いたバーと、残りの時間の目安（「残り 1:35」。1 時間以上は「残り 1:02:05」）を出します。割合は、ツールパス生成は計算を終えた走査線の数、切削シミュレーションは素材から削り終えた工具の動きの数で数えます。計算の始めの準備と終わりの後始末の間は、割合が進みません。残りの目安は、計算を始めてしばらくの間（進み具合が 1% 以上・4 秒以上進むまで）と、終わりの後始末の間は出せないため、バーの右の端に回る印を出します。目安は、今までの進む速さから見積もるため、計算の途中で変わることがあります
- ジョブマネージャーが動いている間は、タスクトレイに赤い輪のアイコンを出します。アイコンを左クリックすると、ウィンドウを開きます。右クリックのメニューには、次の項目があります
  - 「ウィンドウを開く」
  - 「Windows の起動のときに起動する」: チェックすると、Windows にサインインしたときに、ウィンドウを出さずに起動します
  - 「言語」: ジョブマネージャーの画面の言語（日本語・English）を選びます
  - 「終了」: ジョブマネージャーを終了します。計算中のジョブがあるときは、終了してよいかを確かめます（計算を止め、そのジョブは中断になります）
- 計算が終わると、タスクトレイのアイコンから吹き出しを出します。ツールパス生成と切削シミュレーションは続けて計算するため、両方が終わったとき（失敗したときは、失敗したとき）に 1 回だけ出します。吹き出しを押すと、ウィンドウを開きます。吹き出しが出ている間は、Windows がアイコンのクリックをジョブマネージャーに渡さないため、アイコンを押してもウィンドウは開きません（吹き出しを押すか、吹き出しが消えてからアイコンを押します）。ジョブマネージャーが計算の途中で止まった（異常終了・Windows の再起動など）ときは、次に起動したときに、中断にしたジョブを吹き出しで示します
- ジョブマネージャーの「終了」・「停止」・異常終了・Windows の再起動で計算が止まったジョブは「中断」になります。中断のジョブは、自動では計算しません。ジョブマネージャーの「計算再開」か、アプリの工程リストの「計算再開」で、計算待ちに戻します。中断のツールパス生成は、止まった所の近く（直前に書き残した走査線）から続けて計算します（切削シミュレーションは、最初から計算し直します）。続けて計算したジョブの経過の時間は、中断する前までの時間を含みます。中断のツールパス生成の結果を使う切削シミュレーションは、計算待ちのまま待ちます
- アプリの工程リストの「ジョブマネージャーを開く」でも、ジョブマネージャーのウィンドウを開けます
- アプリを新しい版にしたときに、前の版のジョブマネージャーが動き続けていると、計算などの操作で「ジョブマネージャーの版が違う」と出ます。タスクトレイのメニューの「終了」で前の版のジョブマネージャーを終えてから、もう一度操作してください（新しい版のジョブマネージャーが起動します）
- ジョブマネージャーの画面の言語は、アプリとは別に選びます（ウィンドウの右上の「言語」、またはタスクトレイのメニューの「言語」）。選ぶとすぐに替わり、次に起動したときも同じ言語になります。まだ選んでいないときは、Windows の表示言語に合わせます（日本語のときは日本語、それ以外は英語）。選んだ言語は、利用者ごとの設定のファイル（Windows では `%APPDATA%\RedRing\job_manager.json`）に保存します
- ツールパスの大きさの目安と上限：計算の前にツールパスの大きさを確かめる目安と、計算に使うメモリの上限は、設定のファイル（Windows では `%APPDATA%\RedRing\job_manager.json`）の項目に、GB（10 億バイト）の数で書けます。画面では設定しません
  - `toolpath_confirm_gb`：確かめる目安。既定は 2
  - `toolpath_limit_gb`：上限。既定は、PC の物理メモリの半分と 8 の小さい方（メモリの少ない PC で、ほかのアプリや Windows を巻き込まないように）。ツールパス生成も、計算の途中でこの上限を超えたら止まります。物理メモリより大きな値は、ほかのアプリや Windows を巻き込むことがあるため、勧めません
  - 例：`{"toolpath_confirm_gb": 4, "toolpath_limit_gb": 16}`。ファイルにほかの項目（`language`・`store`）があれば、残したまま項目を足します
  - ジョブマネージャーは、起動したときに読みます。書き替えたら、タスクトレイのメニューの「終了」でジョブマネージャーを終えてから、もう一度起動してください（アプリで計算すると起動します）
  - 項目がない・値が正しくない（数でない・0 以下・目安が上限より大きいなど）ときは、既定の値を使い、その理由をジョブマネージャーのログ（`%LOCALAPPDATA%\RedRing\logs\job_manager.log`）に書きます。使っている目安と上限も、起動したときにログに書きます
- 選んだジョブの詳細には、CL を空間モデルに取り込んだジョブに「CL を空間モデルに取り込みました」と出します
- 一覧でジョブを選び、ウィンドウの上のボタンで操作します。状態で操作できるボタンだけを押せます。`Ctrl` を押しながらクリックするとジョブを足し外し、`Shift` を押しながらクリックすると範囲を選べます（複数を選んだときに押せるのは「削除」だけです）
  - 「計算再開」: 中断のジョブを計算待ちに戻します。そのジョブが結果を使うツールパス生成も中断なら、あわせて戻します
  - 「停止」: 計算中のジョブの計算を止めて、中断にします。後から「計算再開」で続けられます（ツールパス生成は、止まった所の近くから続けて計算します）。ほかの計算中のジョブは止めません
  - 「▲ 上げる」「▼ 下げる」: 計算待ちのジョブの優先順位を変えます（ツールパス生成を変えると、その結果を使う切削シミュレーションも変わります）。優先順位の大きいジョブから計算します
  - 「再計算」: 計算失敗・取り消し・中断のジョブを計算待ちに戻し、最初から計算します。ツールパス生成と、その結果を使う切削シミュレーションは、計算失敗・取り消し・中断のものをあわせて戻します
  - 「取り消し」: 計算待ち・中断のジョブを取り消します。計算中のジョブは、計算を止めます
  - 「削除」: 選んだジョブを消します。ツールパス生成を消すと、その結果を使う切削シミュレーションも一緒に消えます（残しても、計算も取り込みもできないため）。切削シミュレーションだけを消すときは、ツールパス生成を残します（アプリの「計算」で、その下に切削シミュレーションだけを計算し直せます）。計算待ち・計算中のジョブと、一緒に消える切削シミュレーションが計算待ち・計算中のツールパス生成は消さずに残し、その番号を出します（中断のツールパス生成と、それを待つ計算待ちの切削シミュレーションは消せます）。複数のジョブ・一緒に消えるジョブがあるときは、消すジョブの番号を出して確かめます
  - 「まとめて削除…」: 次のものを選んで、まとめて消します。消すジョブの数を出して確かめます。ツールパス生成を消すと、その結果を使う切削シミュレーションも一緒に消えます。計算待ち・計算中のジョブは消しません
    - 前の改訂の結果: 同じ加工工程に、別の条件で後から投入して正常に終わったジョブがあるもの（最後に正常に終わった条件のジョブを残します。複製したモデルファイルを交互に使っているときは、使っている結果も対象になることがあります）
    - 取り込み済みの CL の元: アプリで切削シミュレーションの結果を取り込み、その CL を空間モデルに入れたツールパス生成（一緒に、その切削シミュレーションも消えます。消した後も、アプリの「投入」で、空間モデルの CL から切削シミュレーションだけを計算し直せます。別のモデルファイルや、保存していない変更で取り込んだものも対象になります。取り込んだ後に、同じツールパス生成の下で別の切削シミュレーションを計算していれば、対象にしません）
    - 古いジョブ: 入れた日数（はじめは 30 日）より前に投入した、終わったジョブ（後から投入した切削シミュレーションがその結果を使うツールパス生成は残します。中断のジョブは、続けて計算できるため含めません）
    - 取り込めなかった投入: アプリの版の違いなどで、ジョブマネージャーが取り込めなかった投入
- アプリを閉じても、ジョブマネージャーは計算を続けます。ジョブマネージャーのウィンドウを閉じても、タスクトレイに残って計算を続けます。止めるときは、タスクトレイのメニューの「終了」を使います（アプリで加工手順を開いても、ジョブマネージャーは起動しません。計算・取り込み・「ジョブマネージャーを開く」をしたときに起動します。計算待ちのジョブを残してジョブマネージャーを終えると、次にそれらの操作をするまで計算は止まります）
- ジョブの記録と結果は、ジョブの保存先に置きます。はじめは、Windows では `%LOCALAPPDATA%\RedRing\jobs` です。ジョブマネージャーのログは、Windows では `%LOCALAPPDATA%\RedRing\logs\job_manager.log` です（保存先を替えても同じ場所です）。保存先の場所は、ウィンドウの上の「保存先: …」にマウスを乗せると出ます
- 保存先は、ウィンドウの右上の「保存先を変更…」で替えられます（計算待ち・計算中のジョブがある間は替えられません）
  - フォルダを選ぶと、替えてよいかを確かめます。替えると、ジョブマネージャーを起動し直し、新しい保存先のジョブを一覧に出します。前の保存先のジョブとファイルは、そのまま残ります（前の保存先に戻すと、また一覧に出ます）
  - モデルファイルは、保存先を覚えていません。アプリは、今の保存先のジョブを、工程ごとに探して状態を出します（モデルファイルを開くのと保存先を替えるのは、どちらが先でも同じです）。そのため、保存先を替えると、前の保存先で計算した工程は、アプリでは計算していない状態になります。「計算」を押すと、新しい保存先で最初から計算し直します（今の条件の CL を取り込んであれば、切削シミュレーションだけを計算します）。中断の工程を続きから計算するときは、前の保存先に戻してから「計算再開」を押します
  - 前に保存先として使ったフォルダを選ぶと、そのジョブを一覧に出します。ジョブの保存先でないファイルがあるフォルダを選ぶと、確かめの画面でそのことを示します。空のフォルダ、またはジョブの保存先に使ったフォルダを選んでください
  - 次のときは替えられず、ウィンドウの上にその理由を出します
    - 計算待ち・計算中のジョブ、または取り込みを待つ投入がある（中断のジョブと、それを待つジョブは除きます。今の保存先を読めないときも替えられません。保存先のフォルダが見つからない（外したドライブなど）ときは替えられます）
    - 今の保存先と同じフォルダ
    - 今の保存先の中のフォルダ、または今の保存先を中に含むフォルダ（たとえば、はじめの保存先 `%LOCALAPPDATA%\RedRing\jobs` を含む `%LOCALAPPDATA%\RedRing`）
    - ネットワークのフォルダ（`\\サーバー\…` やネットワークのドライブ。ネットワークのフォルダを指すリンクも含みます）
    - 利用者ごとの権限を付けられないドライブのフォルダ（FAT32・exFAT の USB メモリなど）
    - ほかの利用者も読み書きできるフォルダ（下を参照してください）
    - 読み書きできないフォルダ
    - ジョブの保存先ではないのに、中に保存先と同じ名前のもの（`inbox` フォルダ・`jobs` フォルダ・`manager.lock` ファイル）があるフォルダ（ほかのデータと混ざらないように。`inbox` と `jobs` の両方があるフォルダは、前に使った保存先として使えます）
    - 選んだ保存先を、設定のファイルに保存できない
  - 保存先は、自分だけが読み書きできるフォルダを選んでください（保存先には、製品形状を含むジョブの入力と結果を置き、ジョブマネージャーはそれを入力として計算するため）。ほかの利用者・グループ（`Users`・`Everyone`・`Authenticated Users` など）が読み書きできるフォルダは選べません。`C:\` の直下に作ったフォルダは、ふつう `Users` などが読めるため、そのままでは選べません。自分のフォルダ（`%USERPROFILE%` の下など）を選ぶか、次の手順で自分だけが読み書きできるようにしてから選んでください
    1. エクスプローラーでフォルダを右クリックし、「プロパティ」の「セキュリティ」の「詳細設定」を開きます
    2. 「継承の無効化」を押し、「継承されたアクセス許可をこのオブジェクトの明示的なアクセス許可に変換します」を選びます
    3. 自分・`SYSTEM`・`Administrators` のほかの行（`Users`・`Everyone`・`Authenticated Users` など）を削除し、「OK」を押します
  - はじめの保存先は、ジョブマネージャーが自分だけが読み書きできるフォルダとして作ります。ほかの利用者も読み書きできるようになっていれば、起動のときに自分だけが読み書きできるように直します。選んだ保存先がほかの利用者も読み書きできるようになっていたとき（後から権限を変えたときなど）は、ジョブマネージャーは起動せず、その理由を出します。上の手順で直すか、設定のファイルの項目 `store` を消して、はじめの保存先に戻してください
  - 選んだ保存先は、設定のファイル（`%APPDATA%\RedRing\job_manager.json`）に保存し、次に起動したときも使います。アプリは、ジョブマネージャーの保存先を自動で使います（アプリの設定は要りません）

## 用意するデータ

- 製品形状は STL ファイル（バイナリ・ASCII）か STEP ファイル（AP203・AP214・AP242 の B-rep の形状）で用意します。STL の単位は mm として扱い、STEP はファイルの単位を mm に直して読みます
- STEP の形状も加工の対象にできます。曲面の面は、ツールパス生成のトレランスで三角形に分けてから計算します（[既知の制約](./known_issues.md) を参照してください）
- 加工は上（+Z）から近づく 3 軸のスキャン加工です。製品形状は、削る面が上を向く向きで用意します

## ログ

- ログは、起動したときの作業フォルダ（配布物をダブルクリックで起動した場合は展開したフォルダ、ソースからでは上の手順のリポジトリのルート）の `logs/redring.log` に書きます。起動のたびに新しく書き始め、前の回までのログは、番号付きの名前で 5 回分を残します（1 つ前が `redring.1.log`、2 つ前が `redring.2.log` …。ジョブマネージャーのログも同じです）。アプリやジョブマネージャーが止まった後に起動し直しても、止まる前のログを確かめられます
- `--release` を付けたビルドは、コンソールのウィンドウを開きません。`--release` を付けないビルドは、同じ内容をコンソール（起動したターミナル）にも出します
- ログのファイルの場所は、「ヘルプ」→「バージョンの情報」でも確かめられます
- 操作の結果と、操作できなかったときの理由は、画面の下のステータスバーにも出します
- 思わぬ異常で終わるときは、ログのファイルの場所を書いたエラーメッセージの画面を出します
- キーの割り当ての一覧は、`F1`・`h` キー、または「ヘルプ」→「操作の一覧」で開きます
- 不具合を報告するときは、ログのファイルを添えてください

## 終わる

- 「ファイル」→「終了」、`Esc` キー、またはウィンドウの閉じるボタンで終わります。保存していない変更があるときは、保存するかを確かめます
