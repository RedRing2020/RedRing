# 動かす

RedRing のプレビュー版は、Windows 用の配布物（zip）を使うか、ソースからビルドして起動します。配布物は v0.1.3 から添えています。

## 動く環境

- OS: Windows で動作を確かめています（Linux・macOS は、GPU の描画の基盤 wgpu が対応するため動く見込みですが、確かめていません）
- GPU: Vulkan・DirectX 12・Metal のいずれかに対応する GPU
- ソースからビルドする場合: 最新の stable の Rust（[rustup](https://rustup.rs/) で入れます）と Git

素材の精度を細かくする（例えば 0.01 mm）と、メモリと GPU の負荷が大きくなります。最初は既定の精度（0.05 mm）で試してください。

## 配布物から起動する（Windows）

1. [GitHub のリリース](https://github.com/RedRing2020/RedRing/releases) から、`redring-<版>-windows-x86_64.zip` と `SHA256SUMS.txt` を取ってきます
2. zip を確かめます（下の「配布物を確かめる」）
3. zip を、書き込みのできるフォルダ（例えばドキュメントの下）に展開し、`redring.exe` をダブルクリックして起動します。ログは起動したときの作業フォルダ（ダブルクリックで起動した場合は展開したフォルダ）の `logs` に書くため、`Program Files` の下には置かないでください。ショートカットから起動する場合は、ショートカットの「作業フォルダー」を展開したフォルダにしてください

実行ファイルにはまだコード署名がないため、初めて起動するときに Windows の SmartScreen が「Windows によって PC が保護されました」と出します。配布物を確かめたうえで、「詳細情報」→「実行」で起動してください。

### 配布物を確かめる

取ってくる途中で壊れていないことは、zip の SHA-256 が `SHA256SUMS.txt` の値と同じであることで確かめます。PowerShell で次を実行し、`True` と出れば同じです（`<値>` には `SHA256SUMS.txt` の zip の行の値を入れます）。

```powershell
(Get-FileHash .\redring-v0.1.3-windows-x86_64.zip -Algorithm SHA256).Hash -eq '<値>'
```

zip が置き換えられていないこと（RedRing のリポジトリの CI で、リリースのタグからビルドしたものであること）は、[GitHub CLI](https://cli.github.com/) で確かめます。リリースの資産ごと置き換えられた場合はチェックサムも置き換えられるため、こちらで確かめるのが確実です。

```powershell
gh attestation verify .\redring-v0.1.3-windows-x86_64.zip --repo RedRing2020/RedRing
```

リリースには、使っている依存のクレートの一覧（SBOM。CycloneDX の形式の `.cdx.json`）も添えています。

## ソースからビルドして起動する

```bash
git clone https://github.com/RedRing2020/RedRing.git
cd RedRing
git checkout v0.1.3
cargo build --release
cargo run --release -p redring
```

- `cargo build --release` で、アプリと一緒にジョブマネージャー（`redring-job-manager`）とランナー（`redring-batch-runner`）をビルドします。この 2 つがないと、ツールパス生成と切削シミュレーションを投入できません（形状の読み込み・表示はできます）。`cargo run` は、アプリ（`-p redring`）を指定して起動します
- `--release` を付けると、ツールパス生成と切削シミュレーションが速くなります（付けないと、計算に何倍も時間がかかります）
- 最初のビルドは、依存のクレートを取ってくるため数分かかります
- 起動すると、メニューバーのあるウィンドウが開きます。続けて [画面と操作](./screen_and_controls.md) と [切削シミュレーション](./cutting_simulation_demo.md) を参照してください

## ジョブマネージャー

ツールパス生成と切削シミュレーションの計算は、アプリとは別のジョブマネージャー（`redring-job-manager`）が行います。配布物の zip には、アプリ（`redring.exe`）・ジョブマネージャー・ランナー（`redring-batch-runner.exe`）が入っています。3 つは同じフォルダに置いたまま使ってください。

- ジョブマネージャーは、最初に「投入」したときにアプリが起動します（そのときはウィンドウを出しません）。計算の間もアプリの画面は止まりません
- `redring-job-manager.exe` を起動すると、ジョブの一覧のウィンドウを開きます。ジョブの状態・失敗の理由・ログを確かめられます。すでに動いているときは、動いているジョブマネージャーのウィンドウを開きます
- ジョブマネージャーが動いている間は、タスクトレイに赤い輪のアイコンを出します。アイコンを左クリックすると、ウィンドウを開きます。右クリックのメニューには、次の項目があります
  - 「ウィンドウを開く」
  - 「Windows の起動のときに起動する」: チェックすると、Windows にサインインしたときに、ウィンドウを出さずに起動します
  - 「言語」: ジョブマネージャーの画面の言語（日本語・English）を選びます
  - 「終了」: ジョブマネージャーを終了します。計算中のジョブがあるときは、終了してよいかを確かめます（計算を止め、そのジョブは失敗になります）
- 計算が終わると、タスクトレイのアイコンから吹き出しを出します。ツールパス生成と切削シミュレーションは続けて計算するため、両方が終わったとき（失敗したときは、失敗したとき）に 1 回だけ出します。吹き出しを押すと、ウィンドウを開きます
- アプリの加工条件のウィンドウの「ジョブマネージャーを開く」でも、ジョブマネージャーのウィンドウを開けます
- ジョブマネージャーの画面の言語は、アプリとは別に選びます（ウィンドウの右上の「言語」、またはタスクトレイのメニューの「言語」）。選ぶとすぐに替わり、次に起動したときも同じ言語になります。まだ選んでいないときは、Windows の表示言語に合わせます（日本語のときは日本語、それ以外は英語）。選んだ言語は、利用者ごとの設定のファイル（Windows では `%APPDATA%\RedRing\job_manager.json`）に保存します
- 一覧でジョブを選び、ウィンドウの上のボタンで操作します。状態で操作できるボタンだけを押せます
  - 「取り消し」: 計算待ちのジョブを取り消します。計算中のジョブは、計算を止めます
  - 「やり直し」: 失敗・取り消しで終わったジョブを計算待ちに戻します。ツールパス生成と、その結果を使う切削シミュレーションは、失敗・取り消しで終わったものをあわせて戻します
  - 「削除」: 終わったジョブを消します。後のジョブがその結果を使うときは、消してよいかを確かめます（ツールパス生成を消すと、その結果を使う切削シミュレーションは計算も取り込みもできなくなります）
  - 「▲ 上げる」「▼ 下げる」: 計算待ちのジョブの優先順位を変えます（ツールパス生成を変えると、その結果を使う切削シミュレーションも変わります）。優先順位の大きいジョブから計算します
- アプリを閉じても、ジョブマネージャーは計算を続けます。ジョブマネージャーのウィンドウを閉じても、タスクトレイに残って計算を続けます。止めるときは、タスクトレイのメニューの「終了」を使います（アプリの加工条件のウィンドウが計算待ち・計算中の状態を出している間は、アプリがジョブマネージャーを起動し直します）
- ジョブの記録と結果は、Windows では `%LOCALAPPDATA%\RedRing\jobs` に置きます。ジョブマネージャーのログは、そこの `manager.log` です

## 用意するデータ

- 製品形状は STL ファイル（バイナリ・ASCII）で用意します。単位は mm として扱います
- 加工は上（+Z）から近づく 3 軸のスキャン加工です。製品形状は、削る面が上を向く向きで用意します

## ログ

- ログは、起動したときの作業フォルダ（配布物をダブルクリックで起動した場合は展開したフォルダ、ソースからでは上の手順のリポジトリのルート）の `logs/redring.log` に書きます。起動のたびに書き直します
- `--release` を付けたビルドは、コンソールのウィンドウを開きません。`--release` を付けないビルドは、同じ内容をコンソール（起動したターミナル）にも出します
- ログのファイルの場所は、「ヘルプ」→「バージョンの情報」でも確かめられます
- 操作の結果と、操作できなかったときの理由は、画面の下のステータスバーにも出します
- 思わぬ異常で終わるときは、ログのファイルの場所を書いたエラーメッセージの画面を出します
- キーの割り当ての一覧は、`F1`・`h` キー、または「ヘルプ」→「操作の一覧」で開きます
- 不具合を報告するときは、ログのファイルを添えてください

## 終わる

- 「ファイル」→「終了」、`Esc` キー、またはウィンドウの閉じるボタンで終わります。保存していない変更があるときは、保存するかを確かめます
