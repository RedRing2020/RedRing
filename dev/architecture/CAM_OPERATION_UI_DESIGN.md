# CAM の操作の画面 設計書

**作成日**: 2026年11月4日
**ステータス**: 設計中
**関連Issue**: #988（本書）, #933, #914, #887, #306, #1056, #1068

---

## 1. 目的

加工手順・加工工程（`CAM_PROCESS_ENTITY_DESIGN.md`）を画面で並べ、工程の条件の設定、計算（ジョブの投入）、結果の取り込みを、工程の一覧から行う。ジョブの実行と管理は、CAD/CAM のアプリとは別の実行ファイルのジョブマネージャーが行い、CAD/CAM のアプリを閉じていても、時間のかかる CAM の計算を続けられるようにする。今のキー操作（`Shift+M`・`Shift+L`）と加工条件のウィンドウを、この画面に置き換える。

## 2. 背景

- 今は、加工手順 1 つ・加工工程 1 つを Application が持ち、加工条件のウィンドウ（`Shift+M`）がその工程の中身と手順の素材を編集する（#1051）。投入はウィンドウの「投入」で行い、計算はアプリの外のジョブマネージャー（画面なし）が行う。ウィンドウに今の条件の計算の状態（計算待ち・計算中・計算完了・失敗・取り消し）を出し、取り込みは「取り込み」・`Shift+L` で行う（#1078）
- 加工の対象は、表示中の製品形状のすべての面にしている。補助面や型の形状など、加工に関係ない面も空間モデルには含まれるため、加工の対象は面を選んで決める必要がある
- ジョブの一覧は画面に出ず、取り消し・やり直し・順番の変更の手段がない。ジョブマネージャーを止めるには、タスク マネージャーを使う（#988 の背景。同じプロセスの中の実行で画面が止まる問題は #1078 で解消した。一覧と操作は #1079 でジョブマネージャーのウィンドウに足した）
- ジョブマネージャーを別のアプリケーションにする方針は、`BATCH_COMPUTE_PLATFORM_DESIGN.md` 14 章・`APPLICATION_ORCHESTRATION_LAYER_DESIGN.md` 4.2 にあり、ジョブのキュー・入力・成果物をプロセスの外に出すことを #914 で扱う

## 3. 画面の構成

```text
+--------------------------------------------------------------+
| メニューバー                                                  |
+--------------------------------------------------------------+
|                                                              |
|                       モデル表示画面                          |
|                                                              |
+-------------------+------------------------------------------+
| 加工プラン         | [工程手順] [フィーチャー]  （タブ）          |
| （ツリー。         +------------------------------------------+
|  段階 3 で作る）    | ツールバー（手順の名前・計算・比べる範囲）   |
|                   +------------------------------------------+
|                   | 工程リスト（1 行が 1 工程。上から加工の順）  |
|                   | またはフィーチャーのツリー                  |
+-------------------+------------------------------------------+
```

- 画面の下に、CAM の操作の領域を置く。左が加工プランのツリー、右が工程の表示（工程手順・フィーチャーのタブ。3.8）
- 下の領域は、ドッキングできるウィンドウ（パネル）とし、境界を動かして大きさを変えられ、畳めるようにする。モデル表示画面は、残りの領域に広がる
- 加工プランのツリー（左）は、加工プランを持つ段階 3（`CAM_PROCESS_ENTITY_DESIGN.md` 5）まで作らない。それまでは工程リストだけを置く

### 3.1 加工プランのツリー（段階 3）

- ツリーの根は、空間モデル（CAD の物理ファイルとして定義するモデルファイル）とする。加工手順は空間モデルに結び付け、加工プランは、空間モデルと加工手順の間に後から挟み込む
  - 空間モデル（モデルファイル `.rrm`）の内容・形式・ID の保ち方は `SPACE_MODEL_FILE_DESIGN.md`（#1068）で決めた。実装するまでは、Application の製品形状の保管先（`ProductShapeStore`）を空間モデルの代わりとする
- ツリーの右クリックから、加工方案（ワークサイクルの集合。`CAM_PROCESS_ENTITY_DESIGN.md` 3）を設定する。加工方案は、ワークサイクルの登録（段階 3）とツールライブラリ（#887）の後に置き、それまでは右クリックのメニューに出さない
- ツリーの手順の行からも、手順の設定（3.4）を開けるようにする

### 3.2 工程リスト（「工程手順」タブ）

- 選んだ加工手順の加工工程を、加工の順に 1 行ずつ並べる。並びの順が、加工手順の工程の順になる
- 列: 順番・名前・加工の段階（荒・中・仕上げ）・加工の種類・工具・状態
- 状態: ジョブマネージャーのジョブの状態と、空間モデルの CL の状態から決める

  | 状態 | 決め方 |
  |---|---|
  | 再計算待ち | 工程の今の改訂（CL を編集した場合は今の CL の編集の番号）の結果がない（`CAM_PROCESS_ENTITY_DESIGN.md` 4.5） |
  | 待機中・計算中 | ジョブマネージャーのジョブの状態 |
  | 計算済み | 今の改訂のジョブが済み、まだ取り込んでいない |
  | 取込済み | 空間モデルの CL が、今の改訂から取り込んだもの |
  | CL 編集済み | 空間モデルの CL を、取り込んだ後に編集した |
  | 失敗・取り消し | ジョブマネージャーのジョブの状態（理由を出す） |
  | シミュレーション省略 | 工程の「切削シミュレーションをする」が切（その工程の削り込みは確かめていない） |
- 工程の行の右クリックのメニュー
  - 工程の設定（3.3）を開く
  - 計算: この工程だけ・手順の全体（`CAM_PROCESS_ENTITY_DESIGN.md` 4.4）
  - 取り込み: 工程の最も新しい改訂の結果を、モデル表示画面に重ねて再生する（手順の切削シミュレーションの、その工程の区間から再生する。時間軸は手順の全体）
  - 工程の追加・挿入・複写・削除、上へ・下へ（並べ替え）（段階 2）
- 行を選んだ状態は、複数選べる形に広げられるようにする（3.5）
- ヘッダーに「手順の全体の結果を比べる」トグルを置く。入のときは、表示中の工程の結果に代えて、手順の最後の工程の最後の時点の素材（手順の全体の加工の結果）を、手順の加工の対象と比べて削り込み・削り残しを色分けする（#1073）。加工領域を絞った工程を見ていても、手順の全体の削り残しを確かめられる

### 3.3 工程の設定のウィンドウ

工程の行の右クリックから開く。2 つの頁を持つ。

| 頁 | 項目 | 持つ所 |
|---|---|---|
| 加工条件 | 工具（種類・径・工具長）、加工の種類と条件（走査線の条件: ピックフィード・送り・走査線の角度・送り方・工具の移動範囲）、加工の段階、精度プロファイル | 加工工程 |
| 加工領域・加工対象 | 加工領域（工具パスを作る範囲。今は矩形、稜線を投影した範囲は後続） | 加工工程 |
|  | 素材を使う（入のとき、加工領域の中で、前の工程の削った後の素材が残っている所だけを削る。`CAM_PROCESS_ENTITY_DESIGN.md` 4.4） | 加工工程 |
| 加工条件 | 切削シミュレーションをする（切のとき、手順の切削シミュレーションでこの工程の区間を計算しない） | 加工工程 |
|  | 加工の対象（空間モデルから選んだ面の集合） | 加工手順 |

- 加工の対象は、手順で持ち、手順の中の工程で共有する（`CAM_PROCESS_ENTITY_DESIGN.md` 4.1・4.3）。工程の画面で変えると、同じ手順のすべての工程が再計算待ちになることを、頁の中で知らせる
- 穴の周りだけを仕上げるような工程は、加工領域で工具パスを作る範囲を絞る。加工の対象（手順の面の集合）は、工具が削り込まないかを確かめる面として、工程でもすべて使う
- 加工の対象は、空間モデルの面を選んで決める（空間モデル全体を対象にしない。補助面・型の形状など、加工に関係ない面があるため）。今の「表示中のすべての面」は、面の選択ができるまでの扱いとする
- 条件の誤りは、該当する欄の横に出す（`CUTTING_SIMULATION_DESIGN.md`「入力の誤りの知らせ方」と同じ）

### 3.4 手順の設定のウィンドウ

- 工程リストのヘッダー（手順の名前を出す所）の右クリックから開く。加工プランのツリーができたら、ツリーの手順の行からも開く
- 項目: 手順の名前、素材（製品形状を囲む箱からの余裕と、切削シミュレーションの精度）
- 素材を変えると、手順のすべての工程が再計算待ちになる（`CAM_PROCESS_ENTITY_DESIGN.md` 4.5）

### 3.5 計算の操作

- 工程の行の右クリックのメニューで、計算（この工程だけ・手順の全体）を選ぶ
- 工程リストのヘッダーに計算のアイコンを置き、選んだ工程を計算する。最初は選んだ 1 工程とし、複数の工程を選んで計算できる形に広げる
- 計算は、工程から投入する（`CamSimulationWorkflow::submit_operation`）。実行はジョブマネージャーが行う（3.6）。CAD/CAM のアプリは投入の後も止まらない

### 3.6 ジョブマネージャー（別の実行ファイル）

ジョブの実行と管理を、CAD/CAM のアプリとは別の実行ファイルのジョブマネージャーに置く。

| | CAD/CAM のアプリ | ジョブマネージャー |
|---|---|---|
| 持つもの | 空間モデル、加工手順・加工工程（工程の ID と改訂の番号） | ジョブのキューと状態、ジョブごとの入力と成果物（CL・切削シミュレーションの結果）とログ。ジョブは投入元（工程の ID と改訂の番号）を持つ |
| 画面 | 工程リスト（工程ごとの状態）、工程・手順の設定、取り込み | ジョブの一覧（種類・投入元の工程・状態・投入した時刻・所要時間・失敗の理由）、実行の開始・取り消し・やり直し |
| 動き | 工程から投入する。投入の後は待たない | アプリを閉じていても、キューのジョブを実行し続ける |

- CAD/CAM のアプリを閉じて開き直したときは、空間モデルとともに保存した加工手順・加工工程（工程の ID と改訂の番号）から、ジョブマネージャーのジョブを引き直し、工程リストの状態と取り込める結果を出す。そのため、加工手順・加工工程は、工程の ID と改訂の番号ごと空間モデルに保存する（`SPACE_MODEL_FILE_DESIGN.md` 5 章・9 章）
- 工程リストの状態の列は、ジョブマネージャーから受け取ったジョブの状態から決める。ジョブの一覧はジョブマネージャーの画面に置き、CAD/CAM のアプリには置かない
- 取り込みは、CAD/CAM のアプリが、ジョブマネージャーの置き場所の成果物を読んで行う（#914 の決めること 7）
- 最初は、CAD/CAM のアプリはジョブの状態を見るだけとし、実行の取り消し・やり直しはジョブマネージャーの画面で行う。CAD/CAM のアプリから取り消しを頼めるようにするのは、必要になった時点で足す（取り消しを頼んでから止まるまでの状態を扱う必要があるため）
- 同じ PC の上のジョブマネージャーから始める。別の計算機（`BATCH_COMPUTE_PLATFORM_DESIGN.md` のバッチの基盤）で実行する形は、その後に広げる

### 3.7 ジョブマネージャーの画面

BitTorrent のクライアントの画面の形を参考にする。時間のかかる処理をいくつもキューに入れて裏で動かし、進み具合を見守る点が同じためである。

```text
+------------------------------------------------------------------+
| [取り消し] [やり直し] [削除] [▲ 上げる] [▼ 下げる]    保存先: 12.3 GB |
+------------+-----------------------------------------------------+
| 絞り込み     | 番号  投入元(工程)  種類        状態     経過     投入した時刻 |
| ○ すべて    | 12   工程 1      CAM の計算   計算完了  0:42    11/08 10:02 |
| ○ 計算待ち   |  └13 工程 1      切削シミュ    計算中   1:10 ▓▓░  11/08 10:02 |
| ○ 計算中    | 14   工程 2      CAM の計算   計算待ち   -       11/08 10:05 |
| ○ 計算完了   |  └15 工程 2      切削シミュ    計算待ち   -       11/08 10:05 |
| ○ 失敗      +-----------------------------------------------------+
| ○ 取り消し   | [詳細] [ログ]                                          |
|            | 状態・失敗の理由・入力と成果物のファイルと大きさ・ログ       |
+------------+-----------------------------------------------------+
```

| 部分 | 内容 |
|---|---|
| ジョブの一覧 | 1 行が 1 ジョブ。番号、投入元の工程、種類（CAM の計算・切削シミュレーション）、状態、優先順位（大きいほど先）、経過時間、投入した時刻。ツールパス生成の下に、その成果物を使う切削シミュレーションを字下げして並べる（依存関係）。状態の言葉は CAD/CAM のアプリと同じ（計算待ち・計算中・計算完了・失敗・取り消し） |
| ツールバー | 選んだジョブの操作。状態で操作できるものだけを押せる。取り消し（計算待ちは取り消し、計算中はランナーを止める）、やり直し（失敗・取り消しのジョブを計算待ちに戻す。依存関係でつながる、失敗・取り消しで終わったジョブもあわせて戻す）、削除（終わったジョブのフォルダを消す。後のジョブが成果物を使うときは確かめる）、優先順位の上げ下げ（計算待ちのジョブと、それを待つ計算待ちの後のジョブの優先順位を 1 ずつ変える）。結果を待つ間は操作できない。計算は自動で始まるため、開始は置かない。ジョブの追加は CAD/CAM のアプリからの投入で行うため、置かない |
| 絞り込み | 状態ごと。空間モデル（プロジェクト）ごとの絞り込みは、空間モデルの定義（#1068）の後 |
| 詳細 | 選んだジョブの状態・失敗の理由、入力と成果物のファイルと大きさ、ログ（`runner.log`） |
| 進み具合 | 計算中の行は、動いていることが分かる表示にする。割合と残りの目安は、計算の側が進み具合を返す仕組みを足してから出す（#1156。今のランナーは始まりと終わりだけを書く） |
| 保存先の大きさ | ジョブの保存先の大きさの合計を出す。まとめて消す操作（前の改訂の結果・取り込み済みの CL の元・古いジョブ）は後で足す（#1157。`JOB_MANAGER_STORAGE_DESIGN.md` 7 章） |

タスクトレイと起動:

- ウィンドウを閉じてもタスクトレイに残り、キューのジョブを実行し続ける
- トレイのメニューは「ウィンドウを開く」「OS の起動のときに起動する」（チェック。ジョブマネージャーの設定）「終了」。終了は、計算中のジョブがあれば確かめてから行う（計算中のジョブは、次に起動したときに失敗になる。`JOB_MANAGER_STORAGE_DESIGN.md` 3.2）
- CAD/CAM のアプリから起動されたとき・OS の起動のときに起動したときは、トレイだけに出し、ウィンドウは開かない。トレイのアイコン・メニュー、または CAD/CAM のアプリの加工条件のウィンドウの「ジョブマネージャーを開く」で、ウィンドウを前に出す
- ジョブが終わったときは、トレイのアイコンの吹き出しで示す（吹き出しを押すと、ウィンドウを開く）。続けて計算するジョブ（ツールパス生成と、その成果物を使う切削シミュレーション）の途中では示さず、正常に終わったときは最後のジョブだけ、失敗したときは失敗したジョブだけを示す（その失敗で計算できなくなった後のジョブ・取り消したジョブは示さない）
- CAD/CAM のアプリの加工条件のウィンドウの「ジョブマネージャーを開く」は、ジョブマネージャーをウィンドウを出す形で起動する。動いていれば、起動したものが動いているジョブマネージャーのウィンドウを開いて終わる（2 つ目の起動と同じ）
- ジョブマネージャーは 1 つの PC（利用者）に 1 つだけ起動する。2 つ目の起動は、動いているジョブマネージャーのウィンドウを前に出すように頼んでから終わる。CAD/CAM のアプリからの起動（`--background`）の 2 つ目は、何もせずに終わる
- 作り（Windows）: トレイのアイコンは、メッセージを受けるだけの見えないウィンドウに結び付け、Windows の API（`windows-sys`）で直接置く（`tray-icon` は、Windows で MPL-2.0 のライセンスの依存を、ほかの OS で保守の終わった依存を含み、依存クレートの検査を通らないため使わない）。見えないウィンドウの名前は保存先から決め、2 つ目の起動はその名前でウィンドウを探して頼む。OS の起動のときの起動は、レジストリの `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に値 `RedRing Job Manager`（`--background` を付けたコマンド）を書き、メニューのチェックはその値があるかで出す
- 作り（Windows）: `--background` のときは、トレイから開くように頼まれてからウィンドウ（eframe）を作る（eframe は最初の描画でウィンドウを必ず出すため、作ってから隠すと一度出てしまう）。ウィンドウを閉じる操作は取り消して隠し、開くときは egui の画面への頼み（`ViewportCommand`）で出す。終了は、サービスが実行中のランナーを止めて失敗にしてから、プロセスを終える
- Windows 以外の OS では、トレイを置かない（ウィンドウを閉じても、ジョブの管理は続ける）

CAD/CAM のアプリとの分担:

- CAD/CAM のアプリは、加工条件のウィンドウに今の条件の計算の状態を出し、今の条件の最新の結果を取り込む。工程リスト（3.2）ができたら、工程の行の状態と取り込みに置き換える
- 取り込むジョブを選ぶ操作は、ジョブマネージャーの一覧には置かない。取り込みは工程の結果として、CAD/CAM のアプリの工程から行う（前の改訂の結果を取り込む操作は、工程リストとあわせて決める）
- 取り消し・やり直し・削除・順番の変更は、ジョブマネージャーの画面だけで行う（CAD/CAM のアプリは状態を見るだけ）

参考の画面と違う点:

- ジョブには依存関係がある（切削シミュレーションはツールパス生成の成果物を使う）。一覧では字下げで出し、前のジョブが失敗・取り消しで終わると後のジョブは実行されずに失敗になることを、失敗の理由（`dependency job N failed` など）で分かるようにする
- 一時停止は持たない。CAM の計算を途中で止めて続けるには、計算の途中の状態を保存する仕組みが要るため、取り消しだけとする
- 通信の相手・速度の列に当たるものはない

作り（#1079）:

- 画面は、View の層の新しいクレートに置き、実行ファイル `redring-job-manager` をそこに移す。egui（`eframe`）でウィンドウを作り、タスクトレイは Windows の API、OS の起動のときの起動は Windows のレジストリの「Run」キーに書く（外部のクレートを使ってよい。タスクトレイの作りは「タスクトレイと起動」）
- 画面のクレートは、Model の層の `job_manager`（サービス）と `job_runtime`（ジョブの記録の型）に直接依存する。CAD/CAM の ViewModel を通さないのは、ジョブマネージャーが CAD/CAM の画面とは別の小さなアプリで、間に ViewModel の層を挟むほどの変換がないため（依存の決まりの例外として `scripts/_arch_rules_data.ps1` に書く）
- サービス（`JobManagerService`）の 1 回分の仕事（`tick`）は画面の周期とは別に一定の間隔で行い、ウィンドウを閉じても止めない。画面の操作（取り消し・やり直し・削除・優先順位）は、サービスを通してジョブの記録を書く（記録を書くのはロックを持つサービスだけ）。操作はサービスのスレッドに渡し、受け取ったらすぐに行って次の回の仕事をし、画面は結果が返ったら記録を読み直す

### 3.8 工程手順とフィーチャーのタブ

右の工程の表示を、「工程手順」と「フィーチャー」のタブで切り替える。同じ加工手順・加工工程を、2 つの見方で並べる。

| タブ | 並べ方 | 答える問い |
|---|---|---|
| 工程手順 | 加工手順 → 加工工程（加工の順。3.2 の工程リスト） | いつ、何を、どの順で削るか（素材の受け継ぎと NC の出力の順はこちらで決まる） |
| フィーチャー | フィーチャー → それを削る加工工程（加工の順） | どの形状が削り終わっているか、どの工程がその形状に当たっているか |

- フィーチャーは、空間モデルの面のまとまり（と種類）に名前を付けたもの。穴・ポケット・平面のような 2.5 次元の加工の特徴の形状と、キャビティ・見切り面・リブのような 3 次元の曲面の面のまとまりを扱う。空間モデルに、名前と種類を付けた面の ID の集まりとして持つ（段階 3 で足す。`SPACE_MODEL_FILE_DESIGN.md` 10 章）
- 工程は、加工の対象・加工領域がどのフィーチャーを指すかの参照を持つ。表示の切り替えは見せ方だけを変え、工程のエンティティの持ち方（手順が工程を加工の順に持つ。`CAM_PROCESS_ENTITY_DESIGN.md` 4.3）は変えない
- タブにする理由: 今どちらを見ているかとほかの表示があることが見出しで分かる。選んだ行・スクロールの位置・ツリーの開き具合をタブごとに保てる。ドッキングでタブを引き離し、2 つの表示を並べて見る形に広げられる
- 2 つのタブの選択を連動させる（フィーチャーを選ぶと、それを削る工程が工程手順のタブでも選ばれる）
- 計算のアイコンと「手順の全体の結果を比べる」トグルは、タブの上の共通のツールバーに置く。計算は、どちらのタブでも選んだ工程に対して行う
- フィーチャーのタブでは、フィーチャーごとの削り残しを確かめられるようにする（#1073 の比べる結果を、フィーチャーの面ごとにまとめる）
- フィーチャーの種類ごとに加工方案（ワークサイクル）を当てて工程を作る使い方は、段階 3 の加工方案の設定とあわせて扱う。フィーチャーを形状から自動で認識する機能は、必要になった時点で別に扱う

### 3.9 加工条件のウィンドウを分ける（段階 2 の最初の形。#1204）

今の加工条件のウィンドウ（工程の一覧・選んだ工程の条件・手順の素材・計算の操作・表示中の結果の条件を、上から並べた 1 つのウィンドウ）を、3.2〜3.5 の形に近づけて 3 つの画面に分ける。導線は「工程リストで工程を選ぶ → その工程の設定を開く」とする。加工プランのツリー（3.1）・フィーチャーのタブ（3.8）・ドッキングのクレート（6 章）は後に回す。

| 画面 | 置き場所・開き方 | 中身 |
|---|---|---|
| 工程リスト | 画面の下のパネル（モデル表示画面との境界を動かして高さを変えられる）。加工手順を開くと出し、閉じると消す。開いている間は `Shift+M`・「加工」→「工程リスト」で出す・隠す | ツールバー（手順の名前、手順の設定・工程の設定を開くボタン、計算の操作（3.5。投入・やり直し・手順の全体を投入・CL 取込・切削シミュレーション取込・ジョブマネージャーを開く）、工程の追加・複写・削除・上へ・下へ）、最後の操作の結果・選んだ工程の計算の状態・空間モデルの CL の状態の行、工程の表（列: 順番・名前・加工の段階・加工の種類・工具・状態） |
| 工程の設定のダイアログ | 工程の行のダブルクリック・右クリックのメニュー・ツールバーのボタン・「加工」→「工程の設定」で、選んだ工程の設定を開く（#1201） | 頁「加工条件」: 名前・加工の段階・工具・加工の種類と種類ごとの条件・精度プロファイル。頁「加工領域・加工対象」: 加工の対象（手順で共有する）・加工領域。表示中の結果の条件（その工程の切削アニメーションを出しているとき） |
| 手順の設定のダイアログ | ツールバーのボタン・「加工」→「手順の設定」で開く（#1201） | 手順の名前（今は出すだけ。変える操作は後で足す）、素材（余裕・精度） |

- 工程の行の右クリックのメニュー: 工程の設定を開く、投入・やり直し・CL 取込・切削シミュレーション取込、追加・複写・削除・上へ・下へ
- 条件の編集（#1201）: 2 つの設定は、ダイアログ（モードレス。タイトルの行で動かせる）で編集し、「適用」するまで工程・手順に入れない。条件を触っただけで工程の改訂が上がり、再計算待ちになることを避ける（利用者が適用・投入した後で、計算の結果を見て条件を変えるのは自然な流れのため、投入した条件の保存・戻す操作は持たない）
  - 下に「適用」「キャンセル」を置く。工程の設定では、その右に「適用と同時に投入する」の選択を置く（選んだ状態は、次に開いたときも保つ）
  - ダイアログを開いている間は、見る操作（カメラ・切削アニメーションの再生とコマ送り・表示の設定）だけを受ける。工程リスト（工程を選ぶ・一覧の操作・計算の操作）は押せないようにし、「加工」の項目・「ファイル」の終了のほかの項目・ファイルの操作のキー（`Ctrl+N` など）・`Shift+M`・`Shift+L`・ファイルのドロップは受けない（選んだ工程や文書が替わると、編集している条件と食い違うため。保存も、編集している条件が入らないため止める）
  - 閉じるボタン・`Esc` はキャンセルと同じにする（`Esc` でアプリを終えない。入力欄の編集中の `Esc` は、入力欄を離れるだけにする）
  - 適用は、今と同じ中身なら工程・手順を替えない（工程の改訂を進めない）。名前だけを替えたときも改訂を進めない
  - 条件の誤りは、編集している条件で確かめ、ダイアログの該当する欄の下に出す（適用する前に分かる。文書の工程・手順は替えずに、写しで確かめる）。適用した条件の誤りは、工程リストにも出し、投入・やり直しを押せない
- 選んだ工程は、工程リストの選んだ行・工程の設定のダイアログ・モデル表示画面の CL の線（#1200）で、いつも同じ工程を指す
- 加工手順を閉じると（#1205）、工程リストとダイアログを閉じる（編集している条件は適用しない）
- 手順の設定のダイアログには、素材を変えると手順のすべての工程が再計算待ちになることを書く（3.4）。工程の設定のダイアログの加工の対象の頁には、加工の対象は手順で共有し、変えると手順のすべての工程が再計算待ちになることを書く（3.3）
- 工程の名前は、工程の設定のダイアログで変える（今の一覧の下の名前の欄から移す）
- 加工の種類ごとの項目
  - 工程の設定のダイアログの頁「加工条件」を、共通の欄（名前・加工の段階・工具・精度プロファイル）と、加工の種類の欄に分ける。加工の種類の欄は、工程の加工の種類（`OperationSpec` の種類）ごとに作る。加工の種類を足すときは、その種類の欄を足す
  - 加工の種類を選ぶ欄を置く（今はスキャン加工だけ）。種類を替えたら、種類ごとの条件はその種類の既定の値にする（前の種類の条件は残さない。工程の中身が変わるため改訂が上がる）
- 画面の文言は、キー・メニューの名前を出さない（具体的な手順はマニュアルに書く）
