# ツールライブラリ 設計書

**作成日**: 2026年11月18日
**ステータス**: 設計（実装はまだ。実装の Issue は 9 章）
**関連Issue**: #887（本書）, #1394〜#1399（実装）, #933, #1047, #881, #947, #680

## 1. 目的

工具（後にホルダーを含めたツールセット）をツールライブラリのファイルに登録し、加工工程の工具をライブラリから選べるようにする。同じ工具を工程ごとに入力し直さず、ライブラリの工具を直したときに、その工具を使う工程を見つけてそろえられるようにする。

使う人は、工作機械ごとに 100 本以上のツールセットを使う。ツールライブラリは、工具を管理する側の台帳とし、1 つのライブラリを複数の工作機械から使える。どの工作機械の何番（T 番号）にどのツールセットを入れたかは、工具を使う側が、工作機械の設定の T 番号の表で持つ（4.5）。複数のクライアントの環境では、共有フォルダに置いて、複数の PC から同じファイルを参照できるようにする。モデルファイル（後に加工プラン）とツールライブラリのファイルがあれば、別の PC でも同じ条件で計算できるようにする。

v0.2.0（加工の管理。`RELEASE_VERSION_PLAN.md` 2.2）では、モデルファイル（`.rrm`）を初めて配布する。工程が工具をどう持つかを、モデルファイルの形式として v0.2.0 で決める。

## 2. 背景

- 加工工程は、計算の条件の組（`MachiningOperationConditions`）に工具の値（`cam_core::Tool`）をそのまま持つ。モデルファイルの区画 `MSEQ` にも、工程ごとに工具の値（種類・径・コーナー R・工具長・工具の識別子）を書く（`SPACE_MODEL_FILE_DESIGN.md` 4.1）
- 工具の識別子（`Tool::id`）は、工具の種類と径から作る値（例: `ball_endmill_6mm`）で、利用者が付ける名前ではない。ツールパスの `tool_id` と、切削シミュレーションの入力の工具の一致の確かめ（`cam_sim` の Preflight）に使う
- 工程の設定のダイアログの工具の欄は、種類（ボール・フラットエンドミル）・径・工具長を直接入力する（`CAM_OPERATION_UI_DESIGN.md` 3.3）
- `cam_core::toolset` に、工具・ホルダー・シャンク・参照点・干渉用のオフセット形状を持つ `ToolSet` があるが、試験のほかに使う所はない（`CUTTING_SIMULATION_DESIGN.md`「ツールセット定義（工具 + ホルダー）」）
- 加工プラン（工作機械を選び、加工手順をまとめるもの）は、まだない（`CAM_OPERATION_UI_DESIGN.md` 3.1。段階 3）

## 4. ツールライブラリ

### 4.1 ファイルの単位と置き場所

- ツールライブラリのファイル（拡張子 `.rrtl`）は、工具を管理する側のツールセットの台帳とする。工作機械に縛らず、1 つのライブラリを複数の工作機械から使える。工作機械ごとにファイルを分けて持つ運用もできる（ライブラリはいくつでも持てる）
- どの工作機械の何番にどのツールセットを入れたかは、ライブラリに持たず、工作機械の設定の T 番号の表に持つ（4.5）
- ファイルの場所は、利用者が選ぶ。スタンドアロンの環境ではローカルのフォルダに置き、複数のクライアントの環境ではネットワークのフォルダ（共有フォルダ）に置いて、複数の PC から同じファイルを使う運用を想定する
- 使うライブラリのファイルの一覧（ファイルの場所）は、PC ごとのアプリの設定（`%APPDATA%\RedRing\settings.json`）に持つ。ライブラリのファイルを開く・新しく作る・一覧から外す操作を、ツールライブラリの画面に置く（6.1）。一覧から外しても、ファイルは消さない
- 工具は、使う人が持っている物で、どの製品の加工でも同じものを使う。モデルファイルごとに工具を登録し直さないため、ライブラリはモデルファイルの外に置く（`CAM_PROCESS_ENTITY_DESIGN.md` 3 の加工技術ファイルの考え方。工具・ホルダ・工具セットを、使う人ごとのデータとしてプログラムから分ける）
- ライブラリのファイルにつながらないとき（共有フォルダが見えない・PC を持ち出したとき）も計算・表示できるように、工程は計算に使う工具の値の写しを持つ（5 章）。ライブラリそのものは、モデルファイルに入れない

### 4.2 ライブラリとツールセットの項目

ライブラリのファイルは、ライブラリの情報と、ツールセットの項目の列を持つ。

| 項目 | 内容 |
|---|---|
| ライブラリの ID | ランダムな UUID。ファイルを作るときに決め、ファイルを移しても・名前を替えても変わらない |
| ライブラリの名前 | 利用者が付ける名前（例: 「金型仕上げ用」「マシニングセンター 1 号機」）。空にはしない |

| ツールセットの項目 | 内容 |
|---|---|
| ツールセットの ID | ランダムな UUID。作るときに決め、中身を変えても変わらない |
| 名前 | 利用者が付ける名前（例: 「R3 ボール 突き出し 30」）。空にはしない。重なってもよい（見分けは ID で行う） |
| 工具 | `cam_core::Tool`（種類・径・コーナー R・工具長）。v0.2.0 では、種類はボールエンドミル・フラットエンドミルとする（今の CAM の計算で使える種類） |

- ライブラリ・ツールセットは、ファイルの場所ではなく ID で引く。共有フォルダを PC ごとに違うドライブの文字・道筋で見ていても、同じライブラリとして扱う
- 使うライブラリの一覧に、同じライブラリの ID のファイルが 2 つあるとき（ファイルを写したときなど）は、後から足したものを使わず、理由を出す
- ファイルを写して別のライブラリを作るときは、ライブラリの ID とツールセットの ID を作り直す操作（「別のライブラリとして複写」）で行う（6.1）
- 項目の型は Model に置く（ID の型・工程からライブラリの項目への参照 `ToolSetReference`・ツールセットの項目 `ToolSetEntry` は、加工工程の ID と同じく `cam_entity` に置いた）。ライブラリの読み書きと保持は `application` に置く（`application::tool_library`。区画の並びとバイトの読み書きは、モデルファイルと共有する）
- 今の `cam_core::ToolSet` は、ホルダーとシャンクを必ず持つ形で、v0.2.0 の項目には使わない。ホルダーの干渉を入れるとき（8 章）に、ホルダーを持たないツールセットも表せる形に直して、項目に足す
- 項目の並びは、利用者が並べた順とする

### 4.3 ファイルの形式

モデルファイルと同じく、成果物と共通のヘッダ（`ARTIFACT_BINARY_IO_CONTRACT_DESIGN.md`）を使い、種類 `RRTL` を足す。ヘッダの後は、モデルファイルと同じ区画の並び（区画の種類・版・印・長さ・中身。`SPACE_MODEL_FILE_DESIGN.md` 4.1）とする。

| 区画の種類 | 中身 | 必須 |
|---|---|---|
| `LINF` | ライブラリの情報（ライブラリの ID・名前・保存したプログラムの版・保存した時刻） | はい |
| `TSET` | ツールセットの項目の列（ID・名前・工具） | はい |

- 工具のバイトの並びは、区画 `MSEQ` の工具と同じ書き方を使う（読み書きの関数を共有する）
- 項目を足す変更（ホルダーなど）は、区画 `TSET` の版を上げ、前の版の区画も読めるようにする（`SPACE_MODEL_FILE_DESIGN.md` 4.2）。知らない必須でない区画は、そのまま書き戻す（新しい版のアプリと前の版のアプリが同じファイルを共有しても、知らない内容を失わない）
- 読み込みは、信用できない入力として読む（`SPACE_MODEL_FILE_DESIGN.md` 11 章と同じ）。ID が重なっていない・名前が空でない・工具の値が妥当（`Tool::validate_parameters` と、径・工具長が正）を確かめる
- ツールセットが 100 本を超えても、1 本あたり 100 バイトほどで、ファイル全体を読み書きして足りる

### 4.4 共有と読み書きの決まり

- アプリの起動のときと、ツールライブラリの画面・工程の設定のダイアログを開くときに、使うライブラリのファイルを読み直す（ファイルの更新の時刻と大きさが前に読んだときと同じなら、読み直さない）。ほかの PC が書いたことを、ファイルの見張りでは知らせない
- 読めないファイル（つながらない・壊れている・知らない必須の区画・読めない版）は、上書きしない。そのライブラリは、前に読めた内容があればそれを読むだけで使い、なければ使えないものとして理由を出す（画面の下の行とログ）。利用者のデータを、読めないまま上書きしないため
- 書けないファイル（読むだけの権限・読むだけの共有）は、読むだけで使い、ライブラリの画面で編集をできなくする。共有のライブラリを決まった人だけが直す運用は、フォルダの権限で行う
- 書くときは、次の順にする（登録・編集・削除・並べ替えの 1 つの操作ごと）
  1. ファイルの横にロックのファイル（`<ファイル名>.lock`。書いている PC の名前・利用者・時刻を入れる）を、ないときだけ作る形で作る。あれば、短く待って何度か試し、だめなら「ほかの PC が書いている」と出して操作をやめる
  2. ファイルを読み直し、読み直した内容に今の操作を 1 つだけ当てる（項目ごとに、後から書いた方を残す。読み直した内容にない項目を直す・消す操作は、なかったものとして知らせる）
  3. 同じフォルダの一時ファイルに書いてから名前を替える（書いている途中で止まっても、前のファイルが残る）
  4. ロックのファイルを消す
- 書いている PC が止まってロックのファイルが残ったときは、ロックのファイルの時刻が古ければ（5 分。時刻の読めないロックも古いとみなす）、利用者に確かめてから消して書く
- 読み直した内容は、画面のライブラリにも映す
- 実装: 書き込みは `application::tool_library` の `edit_tool_library`（操作 `ToolLibraryEdit`・ロック `ToolLibraryLock`）、使うファイルの一覧は `ToolLibraryCatalog`（変わったファイルの読み直し・前に読めた内容・読むだけ・ID の重なり）。ロックは、書けるかを確かめてから作る（書けないファイルでロックを作らない）。ロックがあるときは 50 ミリ秒の間で 20 回まで試す

### 4.5 工作機械の T 番号の表（v0.4.0 で足す）

工具を管理する側（ライブラリ）と、工具を使う側（工作機械に工具を入れる人）を分けるため、T 番号はツールセットに持たせず、工作機械の設定に持たせる。

| 置き場所 | 持つもの | 直す人 |
|---|---|---|
| ツールライブラリ | ツールセット（ID・名前・工具。後にホルダー） | 工具を管理する側 |
| 工作機械の設定 | T 番号の表: T 番号ごとに、ライブラリの ID とツールセットの ID の組 | 工具を使う側（機械に工具を入れる人） |

- 1 つの工作機械の表の中で、1 つの T 番号は 1 行とする（番号の重なりを、表の形で防ぐ）
- 同じツールセットを、複数の工作機械の表から、機械ごとに違う T 番号で指せる
- 機械の工具を入れ替えたときは、その T 番号の行の指し先を替える。ツールセットの中身は替えない
- 表はツールセットを ID で指すため、ライブラリでツールセットの名前・値を直しても、指し先は変わらない
- 工作機械の設定の置き場所（加工プランの中か、機械ごとのファイルか）と、NC の工具の長さ補正の番号は、NC のポスト処理（#680〜#683）の工作機械・コントローラの設定とあわせて決める

## 5. 加工工程との結び付き

### 5.1 工程が持つもの

| 置き場所 | 項目 | 変えたとき |
|---|---|---|
| 工程の属性（`MachiningOperationAttributes`） | ライブラリの ID とツールセットの ID の組（ない場合がある） | 改訂を進めない |
| 工程の計算の条件（`MachiningOperationConditions`） | 工具の値（今の `tool: Tool<f64>`。ライブラリから選んだときの写し） | 改訂を進める（計算し直し） |

- 計算に使うのは、工程の工具の値の写しだけとする。ライブラリ・ツールセットの ID は、どの項目から選んだかの記録で、計算に使わない。そのため属性に置く（`CAM_PROCESS_ENTITY_DESIGN.md` 4.2 の決まり。計算に使う項目と改訂を進める項目を、型の上で一致させる）
  - 同じ値の別のツールセットに選び替えても、改訂は進まない（計算の結果は変わらないため）
  - ライブラリを直しても、工程の写しは変わらないため、工程の改訂の番号・改訂の鍵の決まり（`SPACE_MODEL_FILE_DESIGN.md` 5.1）はそのまま成り立つ。工程の外の入力として、ライブラリの版を別に記録する必要はない（`CAM_PROCESS_ENTITY_DESIGN.md` 4.5 の検討の材料）
- 工具の識別子（`Tool::id`）は、今と同じく工具の種類と径から作る値のままとする。利用者に見せる名前は、ツールセットの名前とする（`CAM_PROCESS_ENTITY_DESIGN.md` 4.2 の「属性に分けるかを決める」は、名前を属性の側のツールセットに持つことで決まる）
- 加工プランができたら、加工プランが工作機械を持ち、工程の工具は、その工作機械の T 番号の表にあるツールセットから選ぶ（4.5・6.3）。それまでは、使うライブラリのどれからでも選べる

### 5.2 工程の工具とライブラリの比べ方

工程の工具は、使うライブラリと比べて、次のどれかになる。

| 状態 | 条件 | 画面 | 利用者が行えること |
|---|---|---|---|
| ライブラリと同じ | ライブラリとツールセットがあり、工具の値が工程の写しと同じ | ツールセットの名前 | ― |
| ライブラリと違う | ライブラリとツールセットがあり、工具の値が工程の写しと違う | 名前と、違うことの印 | ライブラリの値にそろえる（写しを替え、改訂を進める） |
| ライブラリにない | ライブラリはあるが、ツールセットの ID がない（消された） | 工具の値から作った表示（例: 「ボール φ6」）と、ないことの印 | 写しからそのライブラリに登録する（同じツールセットの ID で） |
| ライブラリが見つからない | ライブラリの ID が、使うライブラリの一覧にない、または読めない | 前に読めたときの名前（なければ工具の値の表示）と、見つからないことの印 | ライブラリのファイルを開く（一覧に足す）。または、写しを、使うライブラリのどれかに登録する |
| ライブラリから選んでいない | 工程が ID の組を持たない（前の版のモデルファイル・ライブラリが空のときに作った工程） | 工具の値の表示と、印 | 写しを、使うライブラリのどれかに登録する（新しいツールセットの ID で） |

- どの状態でも、工程はそのまま計算できる（計算は工程の写しで行うため）。状態は、工程の計算の状態（`CAM_OPERATION_UI_DESIGN.md` 3.2 の未計算・計算済みなど）とは別に出す
- ライブラリの項目を直しても、開いているモデルの工程を自動では替えない。直した項目を使う工程は「ライブラリと違う」になる。保存したモデルの CL を、開いただけで消さないため（共有のライブラリをほかの PC で直したときも同じ。そのモデルに入れるかを利用者が決める）
- 手順のすべての工程を、まとめてライブラリの値にそろえる操作を、工程リストに置く（ライブラリの工具を直した後に、そのモデルに入れるため）
- ライブラリの項目は、使っている工程があっても消せる（ほかのモデルファイルが同じ項目を使っているかは分からないため）。消した項目を使う工程は「ライブラリにない」になり、写しから登録し直せる
- 写しからの登録は、工具のツールセットがすでに使えるライブラリにある工程（「ライブラリと同じ」「ライブラリと違う」）ではしない（ライブラリの値を工程の写しで上書きしない）。登録する名前は、画面が決めて渡す
- 実装: `application::tool_library` の `ToolLibraryCatalog::operation_tool_status`（状態）、`select_operation_toolset`（選び替える）、`align_operation_tool`・`align_sequence_tools`（そろえる。名前も今の名前にする）、`register_operation_tool`（写しから登録する）。どれも加工手順の保管先を受け取り、工程の中身を替える（改訂は、工具の値が変わったときだけ進む）

### 5.3 別の PC で同じ条件にする

- モデルファイル（後に加工プラン）と、使うツールライブラリのファイルを渡す（または、共有フォルダの同じファイルを使う）。工程はライブラリとツールセットを ID で引くため、ファイルの場所が違っても同じ工具として扱い、すべての工程が「ライブラリと同じ」になる
- 渡す先の PC のライブラリが、渡したモデルを作った後に直されていれば「ライブラリと違う」になり、どちらの値で計算するかを利用者が決める
- ライブラリを渡さなくても、工程の写しで同じ値の計算はできる（ライブラリとの結び付きだけが「見つからない」になる）

### 5.4 ジョブ・CL への影響

- ジョブ（CAM の計算・切削シミュレーション）の入力は、これまでどおり工程の工具の値を持つ。ジョブの入力・成果物の形式は変えない
- ツールパスの `tool_id` と、切削シミュレーションの Preflight の工具の一致の確かめは、これまでどおり `Tool::id` で行う
- 切削シミュレーションは、今は工程の工具の値（写し）だけを使い、ツールセットのほかの項目（ホルダーなど）は使わない。切削シミュレーションでツールセットをどう扱うかは、まだ決めていない（10 章）

## 6. 画面

### 6.1 ツールライブラリの画面

- 「加工」→「ツールライブラリ…」で開くウィンドウとする（モデルを開いていなくても開ける）
- 左に、使うライブラリの一覧（名前・ファイルの場所・読むだけか・読めないときの理由）と、ライブラリの操作（新しく作る・ファイルを開く・一覧から外す・別のライブラリとして複写・名前を替える）を置く
- 右に、選んだライブラリのツールセットの表（列: 名前・工具の種類・径・コーナー R・工具長）と、ツールバー（追加・複写・削除・上へ・下へ）を置く
  - 100 本を超えるため、名前の絞り込みの欄と、工具の種類・径での絞り込みを置き、列の見出しで並べ替えられるようにする（並べ替えは見せ方だけで、ファイルの並びは変えない）
- 表の行を選ぶと、表の下の欄で名前・種類・径・工具長を編集できる。「適用」でライブラリに書く（工程の設定のダイアログと同じく、入力の誤りは欄の横に出し、誤りがある間は適用できない）
- 読むだけのライブラリ（4.4）は、編集・追加・削除をできなくし、理由を出す
- 開いているモデルに、選んだ項目を使う工程があれば、その数を出す（消す・直すときに、どの工程が「ライブラリと違う」「ライブラリにない」になるかが分かるように）
- 新しく作るときは、場所を選ぶ画面で選んだファイルの名前（拡張子を除く）をライブラリの名前にする。すでにあるファイルには作らない（ほかのライブラリを上書きしない）
- 書けない・ほかの PC が書いているときは、理由をウィンドウの下と画面の下の行に出す。古いロック（4.4）のときは、書いている PC と利用者を出して確かめ、消して書き直す
- 実装: `viewmodel::tool_library_session`（一覧とツールセットの行・編集する値の誤り・操作と失敗の理由）、View の `tool_library_ui`（ウィンドウ）と `app_state::tool_library`（ファイルを選ぶ画面・確かめの画面・設定への保存）。ロックの書き手は、利用者と PC の名前（`platform_foundation::identity`）。絞り込み・並べ替え・別のライブラリとして複写・使う工程の数・同じ値の印は #1404 で足した（`viewmodel::tool_library_session` の `ToolSetFilter`・`filtered_toolsets`・`toolset_usage`・`duplicate_library`。値の比べ方は `application::tool_library::same_tool_values`。幾何の距離の許容差で比べ、後でホルダーを足したら比べる項目に含める）

### 6.2 工程の設定の工具の欄

- 工程の設定のダイアログ（`CAM_OPERATION_UI_DESIGN.md` 3.3・3.9）の工具の欄を、ライブラリの項目からの選択にする。ライブラリを選び、その中のツールセットを、名前の絞り込みの付いた一覧（種類・径・工具長を名前の横に出す）から選ぶ。選ぶと、工程の写しをその項目の値にし、ライブラリとツールセットの ID を置く
- 欄の横に、5.2 の状態と、状態ごとの操作（ライブラリの値にそろえる・ライブラリに登録する・ライブラリのファイルを開く）を出す
- 工具の値を直接入力する欄は置かない。工具を足す・直すのは、ツールライブラリの画面で行う（ボタンで開く）
- 工程リストの工程の表の工具の列は、5.2 の「画面」の表示（名前または工具の値と、印）にする
- 新しい工程を作るときは、選んでいた工程のツールセットと写しを引き継ぐ（手順には、いつも選んでいる工程がある）。新しいモデルの最初の工程は、今の既定の工具の値で、ID の組のない工程とする（「ライブラリから選んでいない」になり、そこから選ぶ・登録できる）
- 実装: ダイアログの工具の欄の操作（選ぶ・そろえる・登録する）は、ダイアログで編集している工程の中身を作り替え、「適用」で工程に入れる（`application::tool_library` の `content_with_toolset`・`aligned_operation_content`・`register_operation_tool`）。登録は、押したときにライブラリに書く。工程リストの「工具をライブラリにそろえる」は、手順のすべての工程を直接そろえる（`align_sequence_tools`）。マニュアルは「ツールライブラリ」の頁

### 6.3 T 番号を足した後の工具の欄（予定）

工作機械の T 番号の表（4.5）を足したら、工程の工具は T 番号で見て選べるようにする。

- 工程リストの工程の表の工具の列と、工程の設定のダイアログの工具の欄に、加工プランの工作機械の表で引いた T 番号を出す（例: 「T12 R3 ボール 突き出し 30」）。工作機械の表にないツールセット・ライブラリから選んでいない工程は、今の表示（6.2）のままとし、表にないことの印を出す
- 工具の欄で T 番号を入力すると、工作機械の表のその番号のツールセットを選ぶ。一覧は T 番号の順に並べ、T 番号でも絞り込めるようにする
- 工程リストの工具の列からも（セルを選んで）、同じ選び方で工具を替えられるようにする

## 7. モデルファイル

- 区画 `MSEQ` の版を上げ、加工工程の属性に、ライブラリの ID とツールセットの ID の組（有無の印 `u8` と、UUID の 16 バイト 2 つ）と、そのとき読めたツールセットの名前（ライブラリが見つからないときの表示用）を足す。工具の値の書き方は変えない
- 前の版の `MSEQ`（ID の組がない）は、すべての工程を ID の組なしとして読む。開くと「ライブラリから選んでいない」になり、写しから登録できる（`CAM_PROCESS_ENTITY_DESIGN.md` 6.1 の「工程の工具の値をライブラリへ登録する」は、この登録の操作で行う）
- 区画 `MSEQ` は必須の区画のため、前の版のアプリは、版を上げた後のモデルファイルを開かない（`SPACE_MODEL_FILE_DESIGN.md` 4.2）。v0.2.0 で初めてモデルファイルを配布するため、版を上げるのは v0.2.0 の前に済ませる

## 10. 決めていないこと

- ライブラリの中の分類（フォルダ・タグ）。ライブラリを分けた上で、まだ要るかを使う人に確かめる
- ライブラリから、工作機械の T 番号の表にあるツールセットだけを、別のライブラリへ写す（工作機械の単位で部分的に取り込む）機能。MVP では作らず、要るときに検討する
- 工作機械の T 番号の表が、使うライブラリにない・消されたツールセットを指すときの扱い（4.5）
- 同じ名前の項目を、作るときに知らせるか
- 共有フォルダのファイルを、PC に写して持ち出す（つながらないときにも、最後に読めた内容で選べるようにする）か。今は、そのアプリの間だけ前に読めた内容を使う（4.4）
- 切削シミュレーションでのツールセットの扱い（ホルダー・シャンクを削る形・干渉に含めるか、どの段階で入れるか）。後に、ツールライブラリを工作機械のデータと結び付けて管理し、工作機械とツールセットを含めた実際の加工のシミュレーションに広げる予定があり、それとあわせて決める
