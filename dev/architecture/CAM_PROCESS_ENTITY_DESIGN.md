# CAM の工程のエンティティ 設計書

**作成日**: 2026年11月3日
**ステータス**: 設計中（レビュー待ち）
**関連Issue**: #933（本書）, #887, #988, #914, #883, #913

---

## 1. 目的

加工の対象・工具・加工の条件をまとめた「工程」を Model のエンティティとして持ち、ジョブ（CAM の計算・切削シミュレーション）と結び付ける。工程から投入したジョブと取り込める成果物を引けるようにし、工程を変えたときのジョブ・成果物の扱いを決める。v0.2.0（加工の管理。`RELEASE_VERSION_PLAN.md` 2.2）の土台とする。

## 2. 背景

- 工程のエンティティはない。ViewModel（`CuttingSimulationSession`）が「次に投入する条件」（`CuttingSimulationConditions`。工具・走査線の条件・素材の余裕・精度）を 1 組持ち、加工条件のウィンドウはそれを編集する（`CUTTING_SIMULATION_DESIGN.md`「条件の持ち方」）
- 投入（`CamSimulationWorkflow::submit_product_shapes`）は、表示中の製品形状の面と条件から、CAM の計算のジョブ（`CamProcess`）と、その子の切削シミュレーションのジョブ（`CuttingSimulation`）を登録する。ジョブはどの工程のものかを持たず、取り込みは最も新しい結果だけ
- 工程テンプレート（`ProcessTemplate`）とオペレーションの定義（`OperationDefinition`）は、精度プロファイルと加工の種類の既定値を決めるだけで、工程の並びは持たない
- `cam_entity::CAMEntity` は、ツールパスと加工の属性を持つ表示用の型として作ったが、使われていない
- ジョブの関係の決まり: 切削シミュレーションは CAM の計算のジョブの子として、1 つの CAM の工程に 1 件だけ置ける（`BATCH_COMPUTE_PLATFORM_DESIGN.md` 14.8）。親のジョブを再実行すると、子孫のジョブは再計算待ちになる（14.7）

## 3. 参考にするデータ構造

1 本の CL を最小単位に、加工の順序と方法で CL を順序付きで集める。

| 単位 | 内容 |
|---|---|
| 加工プラン | 複数の加工手順を束ねる |
| 加工手順 | 加工の順序を意図した複数の加工工程の組。加工対象形状（形状データへの参照）を持つ。例: 領域の加工は荒・中・仕上げの順、稜線の加工は工具径の大きい順 |
| 加工工程 | 1 つの加工領域を、1 本の工具で、1 つの加工機能で加工する単位。加工機能を動かすパラメタを持つ |
| 経路・基本経路 | 加工工程の結果の工具経路 |

使う人に依存するデータ（加工方法・加工条件・工作機械・コントローラ）は、加工技術ファイルとしてプログラムから分ける。加工技術ファイルは、ワークサイクル（加工工程の集合。加工手順のひな形）、加工方案（ワークサイクルの集合）、工具・ホルダ・アタッチメント・工具セット、工作機械・コントローラの仕様、加工条件（素材の材質と工具から算出する主軸回転数・切削速度）を持つ。加工手順をデータベースに入れて、似た部品の加工に使う。

## 4. 方針

### 4.1 単位

- **加工工程を、工程のエンティティの最小の単位**とする。1 つの加工領域を、1 つの工具（ツールセット）で、1 つの加工の種類（`operation_type`）で加工する
  - 理由: CAM の計算のジョブ 1 つと、その成果物の CL 1 つに対応する。工具・加工の種類・領域のどれかが変われば、別の CL になる
- **加工手順を、加工の対象と、加工工程の順の並び**とする。加工の対象（製品形状の面の参照の集合）と素材は加工手順が持ち、手順の中の工程で共有する
  - 理由: 荒・中・仕上げのように、同じ対象を順に削る工程は、前の工程の削った後の素材を次の工程が受け継ぐ。対象と素材を手順で持つと、工程ごとに食い違わない
- 加工プラン（複数の加工手順を束ねる）は、v0.2.0 では持たない。1 つの製品に複数の段取り（向きを変えて置き直す）や、複数の部品を扱うときに加える

### 4.2 加工工程の中身

| 項目 | 内容 | 今の値の出どころ |
|---|---|---|
| 工程の ID | 全体で一意で安定 | なし |
| 名前 | 利用者が付ける | なし |
| 加工の段階 | 荒・中・仕上げ（`machining_stage`） | `OperationDefinition::machining_stage` |
| 加工の種類と、その条件 | スキャン加工と走査線の条件（ピックフィード・送り方・工具の移動範囲）。種類ごとに条件の型を持つ | `OperationSpec::Scanline(ScanlineParams)` |
| 工具 | ツールセットの ID で参照する（#887）。ツールライブラリができるまでは、工具の値を持つ | `CuttingSimulationConditions` の工具 |
| 加工領域 | 加工範囲（`MachiningBoundary`。指定しなければ対象の XY の範囲） | `OperationDefinition::boundary` |
| 精度プロファイル | ツールパス生成のトレランス（`tolerance_profile`） | 工程テンプレートの既定値 |
| 加工の条件 | 送り（後に主軸回転数）。ツールライブラリの工具ごとの推奨値を初期値にする（#933 のコメント） | `ScanlineParams::feed_rate` |
| 改訂の番号 | 中身を変えるたびに増える（4.5） | なし |

### 4.3 加工手順の中身

| 項目 | 内容 |
|---|---|
| 手順の ID・名前 | 全体で一意で安定な ID と、利用者が付ける名前 |
| 加工の対象 | 製品形状の面の ID の集合（`PRODUCT_SHAPE_ENTITY_DESIGN.md` 3.4）。選ばなかった面は対象外 |
| 素材 | 製品形状を囲む箱からの余裕と、切削シミュレーションの精度。最初の工程の素材になる |
| 加工工程の並び | 加工の順の、加工工程の ID の列 |

- 加工工程は 1 つの加工手順に属する。工程を別の手順でも使いたい場合は複写する（参照を共有すると、片方の変更がもう片方の結果を変える）

### 4.4 ジョブとの結び付き

- **加工工程ごとに、CAM の計算のジョブ（`CamProcess`）を 1 つ投入する**。入力は、手順の加工の対象と、工程の工具・加工の種類と条件・加工領域・精度プロファイル
- **切削シミュレーションは、加工工程の CAM の計算のジョブの子として 1 件置く**（14.8 の決まりのまま）。素材は、手順の最初の工程では手順の素材、2 番目からは前の工程の切削シミュレーションの最後の時点の素材とする（成果物の最後の時点は、次の工程の入力の素材になる。`CUTTING_SIMULATION_STOCK_MODEL_DESIGN.md` 5.2）
  - そのため、2 番目からの工程の切削シミュレーションは、前の工程の切削シミュレーションにも依存する。前の工程を再計算すると、後の工程の切削シミュレーションは再計算待ちになる
  - 前の工程の素材は、切削シミュレーションの入力の参照（`stock_ref`。`BATCH_COMPUTE_PLATFORM_DESIGN.md` 22.1。残り加工で使う予定の項目）で渡す。素材の受け渡しの形式（トリデクセルの最後の状態）は、実装の段階で決める
- **ジョブは、工程の ID と改訂の番号を持つ**。工程から、投入したジョブと、取り込める（正常に終わった）成果物を引く。取り込みは「最も新しい結果」ではなく「選んだ工程の、最も新しい改訂の結果」にする
- 手順の全体の計算（すべての工程を順に投入する）と、工程だけの計算を選べる（大野、1995 の「全計算」と「工程計算」）

### 4.5 工程の内容を変えたとき

- 中身を変えると、工程の改訂の番号が増える。前の改訂で投入したジョブと成果物は消さずに残し、「前の条件の結果」として取り込める（見比べるため）
- 工程の画面では、最も新しい改訂の結果がない工程を「再計算待ち」と表す
- 手順の素材・加工の対象を変えると、手順のすべての工程が再計算待ちになる。工程の並びを変えると、変わった位置より後の工程の切削シミュレーションが再計算待ちになる（素材の受け継ぎが変わるため）
- 製品形状の面の参照が切れた場合（面を削除した等）は、手順を誤りとして表し、投入できないようにする（`PRODUCT_SHAPE_ENTITY_DESIGN.md` 7 の「引き継げなかった参照の扱い」）

### 4.6 置き場所

- 加工手順・加工工程のエンティティは `cam_entity` に置き、使われていない `CAMEntity` を置き換える
- 保管先は Application の工程の保管先とし、製品形状の保管先（`ProductShapeStore`）と同じく呼び出し元が持つ。ViewModel は、選んだ工程の条件を編集する
- 永続化（ファイル）は、ジョブの保存先をプロセスの外に出すこと（#914）と合わせて決める

## 5. 段階

| 段階 | 範囲 | 完了条件 |
|---|---|---|
| 1 | 加工手順 1 つ・加工工程 1 つを Application が持ち、加工条件のウィンドウは工程の条件を編集する（`CuttingSimulationConditions` を置き換える）。ジョブは工程の ID と改訂の番号を持ち、取り込みは工程の最も新しい改訂の結果にする | 今の操作（投入・実行・取り込み）が、工程のエンティティを通して同じようにできる |
| 2 | 加工手順の中に複数の工程を持ち、工程の追加・複写・削除・並べ替え、前の工程の素材の受け継ぎ、再計算待ちの表示を行う（#988 の画面と合わせる） | 荒・仕上げの 2 工程の手順を計算し、仕上げの切削シミュレーションが荒の後の素材から始まる |
| 3 | ワークサイクル（工程の並びのひな形）の登録と読み込み、加工プラン | — |
