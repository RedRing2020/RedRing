# CAM の工程のエンティティ 設計書

**作成日**: 2026年11月3日
**ステータス**: 段階 1 を実装した（6.2 の 1.〜3.。#1049・#1050・#1051）
**関連Issue**: #933（本書）, #887, #988, #914, #883, #913

---

## 1. 目的

加工の対象・工具・加工の条件をまとめた「工程」を Model のエンティティとして持ち、ジョブ（CAM の計算・切削シミュレーション）と結び付ける。工程から投入したジョブと取り込める成果物を引けるようにし、工程を変えたときのジョブ・成果物の扱いを決める。v0.2.0（加工の管理。`RELEASE_VERSION_PLAN.md` 2.2）の土台とする。

## 2. 背景

本節は、本書を作成したときの状態を書く（段階 1 の実装で置き換えたものを含む）。

- 工程のエンティティはない。ViewModel（`CuttingSimulationSession`）が「次に投入する条件」（`CuttingSimulationConditions`。工具・走査線の条件・素材の余裕・精度）を 1 組持ち、加工条件のウィンドウはそれを編集する（`CUTTING_SIMULATION_DESIGN.md`「条件の持ち方」）
- 投入（`CamSimulationWorkflow::submit_product_shapes`）は、表示中の製品形状の面と条件から、CAM の計算のジョブ（`CamProcess`）と、その子の切削シミュレーションのジョブ（`CuttingSimulation`）を登録する。ジョブはどの工程のものかを持たず、取り込みは最も新しい結果だけ
- 工程テンプレート（`ProcessTemplate`）とオペレーションの定義（`OperationDefinition`）は、精度プロファイルと加工の種類の既定値を決めるだけで、工程の並びは持たない
- `cam_entity::CAMEntity` は、ツールパスと加工の属性を持つ表示用の型として作ったが、使われていない
- ジョブの関係の決まり: 切削シミュレーションは CAM の計算のジョブの子として、1 つの CAM の工程に 1 件だけ置ける（`BATCH_COMPUTE_PLATFORM_DESIGN.md` 14.8）。親のジョブを再実行すると、子孫のジョブは再計算待ちになる（14.7）

## 3. 参考にするデータ構造

1 本の CL を最小単位に、加工の順序と方法で CL を順序付きで集める。

| 単位 | 内容 |
|---|---|
| 加工プラン | 複数の加工手順を束ねる |
| 加工手順 | 加工の順序を意図した複数の加工工程の組。加工対象形状（形状データへの参照）を持つ。例: 領域の加工は荒・中・仕上げの順、稜線の加工は工具径の大きい順 |
| 加工工程 | 1 つの加工領域を、1 本の工具で、1 つの加工機能で加工する単位。加工機能を動かすパラメタを持つ |
| 経路・基本経路 | 加工工程の結果の工具経路 |

使う人に依存するデータ（加工方法・加工条件・工作機械・コントローラ）は、加工技術ファイルとしてプログラムから分ける。加工技術ファイルは、ワークサイクル（加工工程の集合。加工手順のひな形）、加工方案（ワークサイクルの集合）、工具・ホルダ・アタッチメント・工具セット、工作機械・コントローラの仕様、加工条件（素材の材質と工具から算出する主軸回転数・切削速度）を持つ。加工手順をデータベースに入れて、似た部品の加工に使う。

本節は、大野、1995 を参考にした。

## 4. 方針

### 4.1 単位

- **加工工程を、工程のエンティティの最小の単位**とする。1 つの加工領域を、1 つの工具（ツールセット）で、1 つの加工の種類（`operation_type`）で加工する
  - 理由: CAM の計算のジョブ 1 つと、その成果物の CL 1 つに対応する。工具・加工の種類・領域のどれかが変われば、別の CL になる
- **加工手順を、加工の対象と、加工工程の順の並び**とする。加工の対象（製品形状の面の参照の集合）と素材は加工手順が持ち、手順の中の工程で共有する
  - 理由: 荒・中・仕上げのように、同じ対象を順に削る工程は、前の工程の削った後の素材を次の工程が受け継ぐ。対象と素材を手順で持つと、工程ごとに食い違わない
- 加工プラン（複数の加工手順を束ねる）は、v0.2.0 では持たない。1 つの製品に複数の段取り（向きを変えて置き直す）や、複数の部品を扱うときに加える

### 4.2 加工工程の中身

| 項目 | 内容 | 今の値の出どころ |
|---|---|---|
| 工程の ID | 全体で一意で安定 | なし |
| 名前 | 利用者が付ける | なし |
| 加工の段階 | 荒・中・仕上げ（`machining_stage`） | `OperationDefinition::machining_stage` |
| 加工の種類と、その条件 | スキャン加工と走査線の条件（ピックフィード・送り方・工具の移動範囲）。種類ごとに条件の型を持つ | `OperationSpec::Scanline(ScanlineParams)` |
| 工具 | ツールセットの ID で参照する（#887）。ツールライブラリができるまでは、工具の値を持つ | 本書の作成時は ViewModel の条件の工具。#1051 で加工工程の中身（今は計算の条件の `MachiningOperationConditions::tool`）にした |
| 加工領域 | 加工範囲（`MachiningBoundary`。指定しなければ対象の XY の範囲） | `OperationDefinition::boundary` |
| 素材を使う | CAM の計算で、前の工程の切削シミュレーションの最後の素材を使い、加工範囲の中で素材が残っている所だけを削るか（入・切。4.4） | なし |
| 切削シミュレーションをする | 手順の切削シミュレーションで、この工程の区間を計算するか（入・切。4.4）。穴あけや、残し量を十分に取った荒加工では切にして計算を省ける | なし |
| 精度プロファイル | ツールパス生成のトレランス（`tolerance_profile`） | 工程テンプレートの既定値 |
| 加工の条件 | 送り（後に主軸回転数）。ツールライブラリの工具ごとの推奨値を初期値にする（#933 のコメント） | `ScanlineParams::feed_rate` |
| 改訂の番号 | 計算の条件を変えるたびに増える（4.5） | なし |
| 改訂の鍵 | 改訂の番号を増やすたびに作り直す UUID（4.5） | なし |

工程の中身は、型の上で 2 つの組に分ける（#1247）。

| 組 | 型 | 中身 | 変えたとき |
|---|---|---|---|
| 工程の属性 | `MachiningOperationAttributes` | 名前・加工の段階 | 改訂を進めない（今の結果のまま） |
| 工程の計算の条件 | `MachiningOperationConditions` | 加工の種類と条件・工具・加工領域・精度プロファイル | 改訂を進める（計算し直し） |

- 計算の入力（ツールパス生成のソルバーの入力）は、計算の条件の組だけから作る。改訂を進めるかは、計算の条件の組が変わったかで決める。計算に使う項目と改訂を進める項目が、型の上で必ず一致する
- 計算に使わない項目（工程のメモなど）を足すときは、属性の組に足す。加工の段階を計算に使うとき（段階ごとの残し代など）は、その時点で計算の条件の組に移す
- 工具の識別子（`Tool::id`）は、工具の種類と径から作る値で、利用者が別に付ける名前ではないため、計算の条件の組の工具のままにする。ツールライブラリ（#887）で工具の名前・番号を持つときに、属性に分けるかを決める
- 加工手順の側の条件（素材の余裕・精度・加工の対象の面）は、今は変えるとすべての工程の改訂を進める（4.5）。素材を受け渡す計算（4.4）を入れるときに、次の形で整理する
- 素材を受け渡す計算が入ると、工程の順番と前の工程の計算の条件も計算に影響する。そのときは、3 つ目の種類として「前の工程から受け取るもの」を加える（#1081）

| 種類 | 中身 | 変えたとき |
|---|---|---|
| 工程の属性 | 名前・加工の段階 | どの工程も計算し直さない |
| 工程の計算の条件 | 加工の種類と条件・工具・加工領域・精度プロファイル | その工程を計算し直す（素材を受け渡すときは、後の工程も） |
| 前の工程から受け取るもの | 順番と、前の工程の計算の条件 | 素材を受け取って計算する工程だけ計算し直す |

- 工程が今の結果のままでよいかを見分ける鍵は、その工程の計算の条件と、素材を受け取るときは前の工程の鍵を合わせたものにする（前の工程の名前・段階を変えても、後の工程は計算し直さない。並べ替えでは、前の工程が変わった工程だけを計算し直す）
- 加工手順の側の条件（素材の余裕・精度・加工の対象の面）は、最初の工程の「前の工程から受け取るもの」として扱える

### 4.3 加工手順の中身

| 項目 | 内容 |
|---|---|
| 手順の ID・名前 | 全体で一意で安定な ID と、利用者が付ける名前 |
| 加工の対象 | 製品形状の面の ID の集合（`PRODUCT_SHAPE_ENTITY_DESIGN.md` 3.4）。選ばなかった面は対象外 |
| 素材 | 製品形状を囲む箱からの余裕と、切削シミュレーションの精度。最初の工程の素材になる |
| 加工工程の並び | 加工の順の加工工程（手順が工程を持つ） |

- 加工工程は 1 つの加工手順に属する。工程を別の手順でも使いたい場合は複写する（参照を共有すると、片方の変更がもう片方の結果を変える）

### 4.4 ジョブとの結び付き

- **加工工程ごとに、CAM の計算のジョブ（`CamProcess`）を 1 つ投入する**。入力は、手順の加工の対象と、工程の工具・加工の種類と条件・加工領域・精度プロファイル
- **切削シミュレーションは、加工手順に 1 つとし、工程ごとの区間を持つ**。時間軸は手順の全体で、手順の素材から始め、工程の CL を加工の順に削る。区間の終わりの素材を次の区間の始まりにする（`CUTTING_SIMULATION_STOCK_MODEL_DESIGN.md` 5.2）。手順の最後の時点が、手順の全体の加工の結果になる
  - 理由: 素材が工程の間で食い違わず、手順の全体の結果がそのまま得られる。削り込みは、生じた区間から原因の工程が分かる
  - 実行は、区間ごとのジョブに分ける（`JOB_MANAGER_STORAGE_DESIGN.md` 5.4・5.5）。区間のジョブは、その工程の CAM の計算と前の区間のジョブに依存する。変わった工程の区間から後だけを計算し直せる
  - 切削シミュレーションをしない工程（「切削シミュレーションをする」が切）は、区間のジョブを作らず、前の素材をそのまま次の区間へ渡す。後の区間の削り込みの判定は正しいが、削り残しの判定には、省いた工程が削るはずだった所も出る。手順の全体の結果と工程の画面で、省いた工程を含むことを知らせる。省いた工程も、後から「切削シミュレーションをする」を入にして計算できる
  - `BATCH_COMPUTE_PLATFORM_DESIGN.md` 14.8 の決まり（切削シミュレーションは CAM の計算の子として 1 件）は、区間のジョブが CAM の計算と前の区間の 2 つに依存する形に替える（実装の段階で直す）
  - 前の工程の素材は、切削シミュレーションの入力の参照（`stock_ref`。`BATCH_COMPUTE_PLATFORM_DESIGN.md` 22.1。残り加工で使う予定の項目）で渡す。素材の受け渡しの形式（トリデクセルの最後の状態）は、実装の段階で決める
- **素材を使う工程は、CAM の計算も前の工程の切削シミュレーションに依存する**。素材を使わない工程の CAM の計算は、前の工程に依存しない
  - 加工範囲（加工領域）は常にある（指定しなければ加工の対象の XY の範囲）。素材を使う工程は、加工範囲の中で素材が残っている所だけを削る。加工範囲だけ・素材だけ（加工範囲は全体）・両方の組み合わせを、加工領域と「素材を使う」の入・切で表す
  - 素材を使う計算は、素材を使う加工の種類（残り加工等）や、空を切る動きを省く機能を足すときに対応する。今のスキャン加工は素材を使わない
- **加工の順と計算の順は分ける**。加工の順（手順の中の工程の並び。NC の出力の順と素材の受け渡しの順）は、計算の順を変えても変わらない。計算の順は、ジョブの依存関係を守る範囲で、ジョブマネージャーが決める（`JOB_MANAGER_STORAGE_DESIGN.md` 5.5）
- **ジョブは、工程の ID と改訂の番号を持つ**。工程から、投入したジョブと、取り込める（正常に終わった）成果物を引く。取り込みは「最も新しい結果」ではなく「選んだ工程の、最も新しい改訂の結果」にする
- 手順の全体の計算（すべての工程を順に投入する）と、工程だけの計算を選べる（大野、1995 の、加工手順の全工程の計算と、指示した工程だけの計算を参考にした）

### 4.5 工程の内容を変えたとき

- 計算の条件を変えると、工程の改訂の番号が増える（属性（名前・加工の段階）だけを変えても増えない。4.2）。前の改訂で投入したジョブと成果物は消さずに残し、「前の条件の結果」として取り込める（見比べるため）
- 工程の画面では、最も新しい改訂の結果がない工程を「再計算待ち」と表す
- 手順の素材・加工の対象を変えると、手順のすべての工程が再計算待ちになる。工程の並びを変えると、変わった位置より後の工程の切削シミュレーションが再計算待ちになる（素材の受け継ぎが変わるため）
- 工程を変えると、その工程の区間から後の区間は再計算待ちになる（素材と、切削負荷（#934）が変わるため）。後の工程のうち素材を使う工程は、CAM の計算から再計算待ちになる。素材を使わない工程の CAM の計算は、そのまま使う
- 工程の並べ替え（段階 2）の再計算の範囲は、区間の前提の鍵で決めた（6.3「今の結果か」。並べ替えた位置から後の区間を再計算待ちにする）。決めるときの検討の材料:
  - 素材は手順の素材から掃引体を差し引いたもので、差し引きは順番によらないため、並べ替えた範囲より後の区間の始まりの素材は変わらない。並べ替えた範囲だけを計算し直す方法と、変えた位置から後をすべて計算し直す方法がある
  - 区間の結果に、前に差し引いた工程の組（各工程の ID・改訂の番号・CL を作ったジョブ・CL の編集の番号）を記録すれば、順番だけの変更と条件の変更を見分けられる。並べ替えでは改訂の番号を増やさない決まりが要る
  - 工程の外の入力（製品形状の面の形・ツールライブラリの工具・計算のプログラムの版）は改訂の番号に表れないため、版を記録する必要がある（#1068・#887。空間モデルは、保存したプログラムの版を持つ。`SPACE_MODEL_FILE_DESIGN.md` 3 章）
  - 加工プランに足す設定（例: 板厚の設定と、それによる取り残しの既定値）が、素材や比べ方に効く場合があるため、加工プランの設計とあわせて決める
- 空間モデルに取り込んだ CL を編集すると（CL の編集を足したとき）、工程の中身は変わらないため工程の改訂の番号は進めず、CL の編集の番号を進める。その工程と後の工程の切削シミュレーションは再計算待ちになる（`JOB_MANAGER_STORAGE_DESIGN.md` 6 章）
- 製品形状の面の参照が切れた場合（面を削除した等）は、手順を誤りとして表し、投入できないようにする（`PRODUCT_SHAPE_ENTITY_DESIGN.md` 7 の「引き継げなかった参照の扱い」）

### 4.6 置き場所

- 加工手順・加工工程のエンティティは `cam_entity` に置き、使われていない `CAMEntity` を置き換える
- 工程が持つ加工の条件の値（加工の種類と条件・加工ステージ・加工範囲）と素材の余裕は、`cam_core` に置く。`cam_entity` は `cam_algorithms` に依存できないため。条件の検証と経路の計算は `cam_algorithms` に残す（#1049）
- 保管先は Application の工程の保管先とし、製品形状の保管先（`ProductShapeStore`）と同じく呼び出し元が持つ。ViewModel は、選んだ工程の条件を編集する
- 永続化（ファイル）は、空間モデル（モデルファイル）に、加工手順・加工工程を ID と改訂の番号ごと保存する（`SPACE_MODEL_FILE_DESIGN.md`。#1068）

## 6. 段階 1 の詳細

### 6.1 決めたこと

- 工程の ID: 加工手順・加工工程の ID は、製品形状の面の ID（`geo_entity::FaceId`）と同じく、ランダムに作る UUID の型とする（番号は使わない）
- 工具: ツールライブラリ（#887）ができるまでは、加工工程が工具の値（`Tool`）を持つ。ツールライブラリができたら ID の参照に替え、そのときに工程の工具の値をライブラリへ登録する
- 改訂の番号: ジョブの記録に、工程の ID と改訂の番号の項目を足す。ジョブの入力の参照（`InputRef`）には入れない。入力の参照は計算の入力の中身を指すもので、工程の管理とは分ける
- 加工条件のウィンドウは、加工手順 1 つの加工工程 1 つを編集する。素材の余裕・精度は加工手順の項目、工具・走査線の条件は加工工程の項目として持つ
- 改訂の番号は、工程の計算の条件を変えたときと、手順の加工の対象・素材を変えたときに増える。工程の属性（名前・加工の段階）は計算に使わないため、属性だけを替えたときは増やさない（名前は段階 2 で名前を替えられるようにしたときに決め、加工の段階は #1247 で属性と計算の条件を型で分けたときに加えた。属性を替えても、計算の結果を今の改訂の結果のまま使う）。手順の変更でも工程の改訂の番号を増やすことで、1 つのアプリの中では、ジョブは工程の ID と改訂の番号だけで、今の条件の結果かどうかを見分けられる（#1049）
- 改訂の番号は、複製したモデルファイル・保存せずに捨てた変更で、別々の中身に同じ番号が付くことがある。そのため、改訂の番号を増やすたびに改訂の鍵（ランダムな UUID）を作り直し、ジョブの投入元に持たせて、工程の ID と改訂の鍵で引く（`SPACE_MODEL_FILE_DESIGN.md` 5.1。#1165）
- 手順は工程を加工の順に直接持つ（工程の ID の列と工程の保管先を分けない）。工程は 1 つの手順に属するため（4.3）
- ジョブの記録の項目は、業務に依らない「投入元」（投入元の ID の文字列と改訂の番号・改訂の鍵。`job_runtime::JobSource`）とする。ジョブの実行の層（`job_runtime`・`job_domain`）は CAM に依存しないため、工程の型は持たせない。Application が工程の ID を文字列にして入れ、工程から引くときは、その文字列と改訂の鍵で比べる（#1050・#1165）
- 加工手順・加工工程は Application の保管先（`MachiningSequenceStore`）の中だけで持ち、作成と編集は保管先の関数で行う。投入・確認・取り込みは、保管先と手順・工程の ID で指定する（`VIEWMODEL_MODEL_ROUTE_REDEFINITION_DESIGN.md` §3.4.1。#1050）

### 6.2 実装の単位

1. cam_entity・application: 加工手順・加工工程のエンティティと、Application の保管先。使われていない `CAMEntity` を置き換える
2. application: 工程から投入し、ジョブに工程の ID と改訂の番号を持たせる。取り込みは、選んだ工程の最も新しい改訂の結果にする
3. viewmodel・view: 加工条件のウィンドウで工程の条件を編集する（`CuttingSimulationConditions` を置き換える）

### 6.3 区間の切削シミュレーションと素材の受け渡し（#1081 で決めた）

段階 2（複数の工程）の上で、手順の切削シミュレーションを工程ごとの区間のジョブで計算し、区間の終わりの素材を受け渡す（4.4）。ここでは、実装の前に決めることを決める。実装は段階 2（#1195）の後とする。

#### 格子は手順で 1 つ

- トリデクセルの格子（3 方向の線の配置と間隔）は、手順で 1 つとし、すべての区間で同じ格子を使う
  - 間隔は、手順の素材の精度と、切削シミュレーションをする工程の工具のうち最も小さい半径から決める（`CUTTING_SIMULATION_STOCK_MODEL_DESIGN.md` 4.1 の √(8 × 半径 × 精度)）。範囲は手順の素材の包含箱とする
  - 線の本数の上限（`MAX_DEXEL_LINES`）は、手順の格子で確かめる（Preflight）
- 理由: 区間の終わりの素材を、作り直しも補間もせずに、そのまま次の区間の始まりにできる（区間ごとに格子が違うと、格子の間を補間して精度を落とすか、前の区間までのすべての掃引体を差し引き直すことになり、区間に分けた意味がなくなる）
- 切削シミュレーションをする工程の工具・手順の素材・精度を変えると、格子が変わることがある。格子が変わったら、手順のすべての区間を計算し直す（下の「今の結果か」で、格子を区間の前提に含める）

#### 素材のファイル

- 区間のジョブは、切削シミュレーションの成果物に加えて、区間の終わりの素材を、別のファイル（素材のファイル。共通のヘッダの種類 `RRST`）に書く（`JOB_MANAGER_STORAGE_DESIGN.md` 5.4）
  - 中身は、格子（3 方向の線の配置）と、各線の材料の区間（端の法線を含む）。切削シミュレーションの成果物の「格子」の節と同じ形とし、最後の時点の状態を持つ
  - 成果物の最後のキーフレーム（`CUTTING_SIMULATION_STOCK_MODEL_DESIGN.md` 5.2）から作り直すこともできるが、成果物は数百 MB〜数 GB で、次の区間・CAM の計算はその一部しか要らないため、別のファイルにする
- 次の区間のジョブは、前の区間の素材のファイルを、始まりの素材として読む。成果物の「格子」の節の初期の区間には、始まりの素材を書く（再生の入口は、今と同じく初期の状態から作り直せる）
- 最初の区間は、今と同じく手順の素材（直方体）から始める
- 素材を使う工程の CAM の計算（4.4）は、前の区間の素材のファイルを入力にする。今の加工の種類（スキャン加工）は素材を使わないため、素材を使う加工の種類を足すときに読む

#### ジョブと依存関係

- 区間のジョブは、切削シミュレーションのジョブ（種類 `sim`）とし、2 つのジョブに依存する: その工程の CAM の計算（CL を入力にする）と、前の区間のジョブ（素材を入力にする）。最初の区間は、CAM の計算だけに依存する
  - ジョブマネージャーは、依存するジョブの種類で入力を決める（CAM の計算の成果物を CL に、切削シミュレーションのジョブの素材のファイルを始まりの素材にする）。CL のファイルを持つ切削シミュレーション（`toolpath_file`。#1080）も、前の区間に依存してよい
  - `BATCH_COMPUTE_PLATFORM_DESIGN.md` 14.8 の決まり（切削シミュレーションは CAM の計算の子として 1 件。ジョブマネージャーの「CAM の計算 1 つに切削シミュレーション 1 つ」）は、区間のジョブが CAM の計算と前の区間の 2 つに依存する形に替える。CAM の計算 1 つに、同じ前の区間の切削シミュレーションは 1 つとする
  - 要求に素材の依存を足すため、保存先の記録・要求の形式の版を上げる（前の版のジョブマネージャーが、2 つに依存する切削シミュレーションを黙って取り込まないように）
- 切削シミュレーションをしない工程は、区間のジョブを作らない。次の区間は、その前の、切削シミュレーションをする工程の区間に依存する
- 手順の全体の計算は、工程の CAM の計算と区間のジョブを、1 つの投入にまとめて置く（同じ投入の中の依存は `DependencyRef::Submitted`）。工程だけの計算は、その工程の CAM の計算と区間のジョブを、前の区間の今の結果のジョブ（`DependencyRef::Existing`）に依存させて置く。前の区間に今の結果がなければ、前の区間から投入する

#### 今の結果か（並べ替えを含む）

- 区間の結果は、その区間の前提が今の手順と同じときだけ、今の結果とする。前提は、次をまとめたもの（区間の前提の鍵）
  - その工程の ID と改訂の鍵
  - 手順の中で前にある、切削シミュレーションをする工程の ID と改訂の鍵の列（加工の順）
  - 格子（手順の素材・精度と、格子を決める工具の半径）
- 区間のジョブの投入元に、区間の前提の鍵を足す（`JobSource`。改訂の鍵と同じく文字列。前の版の記録・要求は持たない）。工程から今の区間の結果を引くときは、工程の ID・改訂の鍵に加えて、区間の前提の鍵で比べる
- これで、4.5 の再計算待ちの範囲は、次のとおりに決まる
  - 工程を変えると、その工程の改訂の鍵が変わり、その区間と後のすべての区間の前提が変わる（後の区間は再計算待ち）。CAM の計算は、その工程だけが再計算待ちになる（素材を使わない工程の CAM の計算は、前の工程に依存しない）
  - 工程を並べ替えると（改訂の鍵は変えない）、並べ替えた位置から後の区間の前提が変わり、再計算待ちになる。CAM の計算は再計算待ちにしない
  - 切削シミュレーションをする・しないを替えると、その後の区間の前提が変わる
  - 手順の素材・加工の対象を変えると、すべての工程の改訂の鍵が変わる（6.1）
- 並べ替えた範囲より後の区間は、差し引きが順番によらないため素材は変わらないが、ここでは再計算待ちにする（前提の鍵が単純になり、取り違えがない）。範囲だけを計算し直すのは、計算の時間が問題になったときに、前提の鍵を「前の工程の組（順を問わない）」に替えて検討する
- 素材を使う工程の CAM の計算は、区間と同じく、前の工程の前提の鍵（その前までの区間の前提）を投入元に持ち、前提が変わったら再計算待ちにする
- 工程の外の入力（製品形状の面の形・ツールライブラリの工具・計算のプログラムの版）は、前提の鍵に含めない（4.5 の検討の材料のとおり、別に版を記録する。#1068・#887）

#### 再生と表示

- 手順の全体の切削アニメーションは、区間の成果物を加工の順につないで再生する。区間 k の再生は、区間 k の成果物の初期の区間（前の区間の終わりの素材）から作り直す
- 手順の全体の結果（削り込み・削り残し。#1073）は、最後の区間の終わりの素材から求める
- 切削シミュレーションをしない工程を含む手順は、全体の結果と工程の画面で、省いた工程を含むことを知らせる（4.4）

#### 実装の単位（段階 2（#1195）の後）

1. cam_sim: 手順の格子の決め方、素材のファイル（`RRST`）の読み書き、始まりの素材からの切削シミュレーション、終わりの素材の書き出し
2. job_runtime・job_manager・job_runner: 2 つに依存する切削シミュレーションの取り込みと入力の決め方、素材のファイルの受け渡し、要求の形式の版
3. application: 手順の全体の計算・工程だけの計算の投入、区間の前提の鍵、工程の今の区間の結果の引き方
4. viewmodel・view: 手順の全体の切削アニメーション、再計算待ちの表示（段階 2 の画面に足す）
5. 素材を使う工程の CAM の計算の入力（素材を使う加工の種類を足すとき）
