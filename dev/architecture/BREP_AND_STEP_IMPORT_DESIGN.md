# 位相の基盤と STEP の読み込みの設計書

**作成日**: 2026年11月16日
**ステータス**: 設計確定（実装前）
**関連Issue**: #1324（本書）, #205, #380, #668, #666, #256, #232, #1385, #1484（押し出しの面・回転の面。7.2）

---

## 1. 目的

STEP（ISO 10303-21。AP203・AP214・AP242 の形状）の読み込みと、その前提になる位相の基盤（面・ループ・シェル・立体）を決める。読み込みを、構文・中間データ・位相・製品構造の 4 つの段に分け、段ごとに置く場所と受け渡すデータを決める。実装は、12 章の段ごとに別の Issue にする。

## 2. 背景

- 形状の読み込みは、STL と RedRing のバイナリ形式（`geo_io`）だけで、STEP は読めない
- 位相（`geo_topology`）は、頂点・稜線・ワイヤまで
  - 番号（`TopoId`）は、プロセスの中の連番で、ファイルに残せない
  - 頂点は `Arc` で共有するが、稜線はワイヤが値で持つ。そのため、2 つの面で 1 本の稜線を共有できない
  - 許容誤差は、形状の全体で 1 つ（`TopologyToleranceSettings`）
  - 面・ループ・シェル・立体・パラメータ曲線はない
- 製品形状は、面単体のエンティティ（トリムしていない NURBS 曲面か、三角形メッシュ）だけを持つ（`PRODUCT_SHAPE_ENTITY_DESIGN.md` の段階 1）。CAM は、加工面を面の ID（`geo_entity::FaceId`）で選ぶ
- 円・楕円・円柱・円錐・球・トーラスは、解析的な型（`geo_primitives`）で持つ。NURBS（`geo_nurbs`）は、両端を固定したノットベクトルだけを扱う
- モデルファイル（`.rrm`）は、面の形状（メッシュか NURBS 曲面）だけを保存する。位相・曲線・解析的な面・元のファイルは保存しない
- `PRODUCT_SHAPE_ENTITY_DESIGN.md` は、STEP の読み込みを、トリムした面を扱う段階 2 の後としている。本書は、段階 2 の位相の持ち方と STEP の読み込みを合わせて決める

## 4. 層の分け方

### 4.1 段と置き場

| 段 | 置き場 | 入力 | 出力 |
|---|---|---|---|
| 1. 構文 | `geo_step` の `syntax` | バイト列 | エンティティの表（番号から、名前と引数の並び） |
| 2. 中間データ | `geo_step` の `record` | エンティティの表 | 形状と位相と製品構造の記録（計算のないデータ。単位だけ直す） |
| 3. 位相 | `geo_step` の `topology` | 中間データの 1 つの立体 | `geo_topology` の B-rep と、読めなかった面の理由 |
| 4. 製品構造 | `application` | 中間データの製品構造と、段 3 の結果 | 製品形状のエンティティ（名前・配置・元の要素との対応つき） |

- 段 1・2 は、幾何の計算をしない（単位の掛け算だけ）。平方根・三角関数・内積・外積・正規化を使わず、`geo_primitives`・`geo_nurbs`・`geo_topology` の型も使わない。モジュールの決まりとし、見直しと試験で守る
  - 理由: ファイルの値をそのまま試験で比べられる。座標系を作る計算を段 3 の 1 か所にまとめる
- 段 3 は、立体ごとに独立に動く（同じ入力から同じ結果を返し、ほかの立体に依らない）。並列にするかは段 4 で決める（10.4）
- 段 4 は、読み込みの口（アプリの操作）・進み具合・取り消しを扱う
- `geo_step` は、ファイルのパスを受けず、バイト列を受ける。ファイルを開いて読むのは `application` とする
  - 理由: 試験（壊れたファイルなど）を、ファイルなしでバイト列から行える。ファイルの扱い（大きさの上限で読むこと・OS ごとの違い）を 1 か所にまとめる

### 4.2 クレートと依存

- `geo_step` を Model の層に足す。STEP のデータ交換（読み込み。書き出しを作るときも、ここに置く）だけを持つ
  - 依存は `analysis`・`geo_contracts`・`geo_core`・`geo_primitives`・`geo_nurbs`・`geo_topology`・`geo_algorithms` とする
  - `geo_io` は、STL と RedRing のバイナリ形式（位相を持たない形状のバイト列）のままとする（`geo_io` は `geo_topology` に依存できない。STEP を `geo_io` に置くと、STL などの読み込みまで位相に依存する形になる）。`geo_io` を、RedRing のバイナリ形式と STL のクレートに分けるかは、#1342 で決める
  - ほかの形式（IGES など）を足すときは、同じ形で別のクレート（`geo_iges` など）にする
- `application` の依存に `geo_step` を足す
- 依存の決まり（`scripts/_arch_rules_data.ps1`）と `ARCHITECTURE.md` は、`geo_step` を作る Issue で更新する
- 形状の層のクレート `geo_shapes` を、`geo_primitives`・`geo_nurbs` の上に足す（#1484。7.2.1）。曲線の参照（`CurveRef`）・曲面の参照（`SurfaceRef`）と、押し出しの面・回転の面の型を置く
  - 依存は `analysis`・`geo_contracts`・`geo_core`・`geo_primitives`・`geo_nurbs` とする。`geo_topology`・`geo_step`・`application` の依存に `geo_shapes` を足す
  - 依存の決まりと `ARCHITECTURE.md` は、`geo_shapes` を作る Issue（#1493）で更新する

### 4.3 入力を信用しない

- すべての段で、パニックしない。エラーは型で返す（`unwrap`・`expect` を使わない）
- ファイルから読んだ数で、先に領域を取らない（読みながら増やす）
- 上限を超えたら、型つきのエラーで止める。上限は次のとおりとし、各段の定数として置く（許容誤差ではないため `analysis` には置かない）

| 対象 | 上限 | 段 |
|---|---|---|
| ファイルの大きさ | 512 MiB（呼び出し元が広げられる） | 1 |
| エンティティの数・引数の数 | それぞれ 2,000 万 | 1 |
| 引数の入れ子の深さ | 64 | 1 |
| 複合のエンティティの部分の数 | 64 | 1 |
| 幾何の参照の入れ子の深さ | なし（中間データの段は、参照を再帰でたどらずに順に読むため、入れ子の深さで止まらない） | 2 |
| B-spline の制御点の数 | 100 万 | 2 |
| B-spline の次数 | 32 | 2 |
| 座標の大きさ | mm に直した後の値で 1e9 mm（mm に直す前の値では、単位によって大きさが変わるため） | 3 |
| 1 つの立体の面の数 | 50 万 | 3 |
| 1 つの立体で、写した後の曲線・曲面の制御点の合計 | 1,000 万（ファイルで共有している曲面を要素ごとに写すため。5.1） | 3 |
| 1 つのループの稜線の数 | 10 万 | 3 |
| アセンブリの深さ | 32（循環は止める） | 4 |
| 出現をたどる回数 | 10 万（共有した部分アセンブリでの増えすぎを止める） | 4 |
| 1 つのファイルの面の数 | 500 万（出現ごとに数える） | 4 |
| 1 つのファイルで、写した後の曲線・曲面の制御点の合計 | 5,000 万（作った `Brep` ごとに数える。同じ部品の出現は `Brep` を共有するため、出現ごとには数えない。10.4） | 4 |

- 数値は、有限でない値（NaN・無限大）を読めないものとする
- 取り消しと進み具合は、段 1・2（中間データから曲線・曲面を作る処理を含む）でエンティティ 4,096 個ごと、段 3 で立体ごとに確かめる。段の関数は std の型だけで書いた閉包で受け取り、Model の framework 層のクレートに依存しない（`COMMAND_AND_BACKGROUND_TASK_DESIGN.md` 7.1）
  - 閉包（`geo_step::Progress`）は、済んだ数と全体の数を受け取り、続けるか止めるかを `std::ops::ControlFlow` で返す。止めると返したら、段は途中で止まり、型つきの誤りで返る（構文は `SyntaxErrorKind::Cancelled`、中間データと曲線・曲面は `geo_step::Cancelled`、位相は `BuildError::Cancelled`）
  - 渡す数は、段ごとに決める。構文は、読んだバイトの数とファイルのバイトの数（エンティティの数は、読み終えるまで分からないため）。中間データは、見たエンティティの数と、その上限（表を 3 回たどり、形状から指される要素を読むので、エンティティの数の 4 倍）。曲線・曲面は、見た幾何の記録の数と全体の数。位相は、作り終えた表現の要素の数と全体の数（表現の要素を作り始めるたびに知らせる）
  - 出現の配置の点・方向のように、少ない要素を読むところは、数えない

## 5. 位相の基盤（`geo_topology`）

### 5.1 B-rep の表

1 つの B-rep（`Brep`）が、要素の種類ごとの配列を持つ。要素は、型つきの番号（配列の位置）で引く。

| 要素 | 持つもの |
|---|---|
| 頂点 | 点、許容誤差 |
| 稜線 | 曲線、曲線のパラメータの区間（小さいほうから大きいほうへ）、始点と終点の頂点、許容誤差、使用の一覧（面・ループ・位置） |
| 稜線の使用 | 稜線、向き（稜線の向きに沿うか）、パラメータ曲線 |
| ループ | 稜線の使用の並び |
| 面 | 曲面、ループ（0 個以上。5.3）、曲面の向きに対する面の向き |
| シェル | 面（外向きにそろえた面。面の向きは面が持つ）。閉じているかは、シェルの面が稜線をちょうど 2 回ずつ使うかで求める |
| 立体 | シェル（初めが外側、残りが空洞） |

- 離れた面を 1 つのまとまりとして扱うものは「複合面」と呼び、つながった面の集まりであるシェルと分ける（本書では扱わない）
- 番号は、`Brep` の中だけで意味を持つ。ほかの `Brep`・ファイルの中では、番号で要素を指さない（面を外から指すのは、エンティティの面の ID。10.1）
- 2 つの面は、1 本の稜線を共有する（稜線の使用が 2 つ）。ファイルにある継ぎ目の稜線は、1 つの面で 2 回使う形のまま持つ
- 稜線の使用の一覧は、使った順で持つ。多様体でない稜線（使用が 3 つ以上）は、読み込みでは作らない（8.4）。表の確かめで、多様体でない稜線として報告する
- 要素の並びは、決まった順にそろえる（面はシェルをたどる順、稜線・頂点は面をたどる順）。同じ入力から、同じ並びになる
- 曲線・曲面は、要素が値で持つ（共有しない）。ファイルで共有している曲面は、読み込みで要素ごとに写す

### 5.2 曲面と曲線の種類

- 曲面: 平面・円柱・円錐・球・トーラス・NURBS 曲面（`geo_primitives`・`geo_nurbs` の型）と、押し出しの面・回転の面（`geo_shapes` の型。7.2）
- 3 次元の曲線: 線分の母線（無限の直線）・円・楕円・NURBS 曲線。稜線は、曲線と区間の組で持つ（`TOPOLOGY_ENTITY_LAYER_DESIGN.md` の「母曲線と範囲」）
- 曲線の参照（`CurveRef`）と曲面の参照（`SurfaceRef`）は、形状の層 `geo_shapes` に置き、B-rep の表（`geo_topology`）が使う（7.2.1。移すのは #1493）
- パラメータ曲線（2 次元）: 直線・円・楕円・NURBS 曲線。稜線の母曲線と同じパラメータで (u, v) を返す形で持つ（円は、楕円の 2 つの半軸が同じ長さで直交するものとして持つ）

### 5.3 向きの規則

- ループは、面の外向きの法線の側から見て、面がループの進む向きの左にあるように持つ。継ぎ目のない周期的な面（円柱の帯を囲む 2 つの円など）も、同じ規則で決まる
  - 外側のループのある面では、外側のループが反時計回り、内側のループが時計回りになる
- 面の向き（曲面の向きに対して表か裏か）は、面が持つ。面の向きが裏なら、面の外向きの法線は曲面の法線の逆になる
- シェルは、外向きにそろえた面を持つ。立体の外側のシェルは外向き、空洞のシェルは空洞の側を向く
- ループのない面は、閉じた曲面（球・トーラス・両方向に閉じた NURBS 曲面）の全体とする

### 5.4 今の型との関係

- 今の `Vertex`・`Edge`・`Wire`（`Arc` と値での保持）と `TopoId` は、`Brep` の表に置き換える
  - `Wire` は、`Brep` の中の稜線の使用の並びにする
  - 今の使い手（`application` の稜線の組み立て）は、置き換える Issue で移す
- `TopologyValidator` の稜線とワイヤの確かめ（端点の一致・つながり）は、`Brep` の稜線とループの確かめとして残す
- `TOPOLOGY_ENTITY_LAYER_DESIGN.md` の未決の「ループを独立した要素にするか」は、ループを要素とする（稜線の使用の並び）で決める
- `PHASE4_TOPOLOGY_ENTITY_DESIGN.md` のパラメータ曲線（稜線が、隣の面ごとに持つ）は、稜線の使用が持つ形にする（ファイルの継ぎ目の稜線は、同じ面の上に 2 つのパラメータ曲線を持つため）

### 5.5 パラメータ曲線

- 解析的な曲面の上では、パラメータ曲線を正確な形で作る
  - 平面: 直線・円・楕円・NURBS 曲線を、平面の座標に写した形
  - 円柱・円錐: 母線は v 方向の直線、軸に垂直な円は u 方向の直線
  - 球・トーラス: 経線と緯線にあたる円は、u・v 方向の直線
- 周期的な曲面の上のパラメータ曲線は、周期で折り返さず、つながった値で持つ（円柱の帯の円は、u が 0 から 2π まで進む直線）
- 正確な形にならない組（円柱の上の楕円など）と NURBS 曲面の上では、許容誤差の中で NURBS 曲線を当てはめる。当てはめのずれは、稜線の許容誤差に含める
- ファイルのパラメータ曲線（`PCURVE`）は使わない
  - 理由: 書き出した CAD ごとに曲面のパラメータの取り方が違い、そのままでは RedRing の曲面のパラメータに合わない

#### 5.5.1 当てはめ（#1351）

面を足す処理（`Brep::add_face`）が、稜線の使用ごとにパラメータ曲線を作る。正確な形（上の組）を作り、区間を 8 つに分けた 9 点で、曲面の上で評価した点と稜線の点のずれが稜線の許容誤差に収まらなければ、当てはめる。表を中身から戻すとき（10.3）も、同じ処理で作り直す。そのため、当てはめは `geo_topology`（`ParameterCurve`）に置く（`geo_topology` は `geo_algorithms` に依存できない）。

| 項目 | 決め |
|---|---|
| 形 | 有理でない 3 次の NURBS 曲線。稜線の区間を小区間に分け、小区間ごとに 3 次の Bezier にして、つなぎ目で C0 につなぐ（小区間の境はノットの重複が 3）。パラメータは、稜線の母曲線と同じ `t` |
| 小区間の Bezier | 小区間の両端と 1/3・2/3 の 4 点を曲面に写した (u, v) を通す（4 点を通す 3 次の補間） |
| 初めの小区間 | 区間を 8 つに分けた点と、母曲線が NURBS 曲線なら区間の中のノット（ノットで折れる曲線の折れ目を、小区間の中に入れないため） |
| ずれの測り方 | 曲面の上で評価した点と、稜線の点の距離。写した点と、小区間の中の 3 点（4 点を通す補間の誤差の主な項 τ(τ − 1/3)(τ − 2/3)(τ − 1) が最も大きくなる 1/2 ± √5/6 と、極になる 1/2）で測る。測った点の間では、わずかに超えることがある |
| 細かくする | 中の 3 点のずれが目安の許容誤差を超える小区間を 2 つに分ける。稜線が曲面から離れていて、写した点のずれが目安を超えるときは、中の 3 点のずれが「写した点のずれ＋目安」を超える小区間だけ分ける（分けても、曲面からの離れより小さくならないため）。分ける深さは 10 まで（初めの小区間 1 つが最大で 1,024 個） |
| 目安の許容誤差 | 稜線の許容誤差。深さの上限まで分けても収まらなければ、そのまま使い、ずれを返す（読み込みが稜線の許容誤差を広げる。6.1） |
| 解析的な曲面への写し方 | 点の (u, v) を閉じた式で求め（曲面の上の近い点）、周期の分だけ動かして前の点につなぐ。極の点の u は前の点の u（初めの点が極なら、すぐ隣の点の u） |
| NURBS 曲面への写し方 | 前の点の (u, v) から、ガウス・ニュートン法（1 階の偏導関数だけを使う）で詰める（`NurbsSurface3D::parameter_for_point_from`）。初めの点は、曲面の上の格子（1 方向に、制御点の数の 2 倍に分け、32 まで）の最も近い点から詰める。曲面の上を動く長さが目安以下になるか、20 回で止める。偏導関数が平行な点（極・1 点に縮退した辺）では、0 でない偏導関数の向きだけを動かす。前の点から詰めるので、曲面の離れた部分には飛ばない |

- NURBS 曲面の上では、ループの隣り合うパラメータ曲線が (u, v) でつながるかを確かめる（平面の上のパラメータ曲線は 3 次元の点を平面の座標に写したものなので、確かめない）。つなぎ目の (u, v) の差の中ほどの点を曲面の上で評価し、つなぎ目の頂点から、頂点と前の稜線の許容誤差の和より離れていれば、面を足さない（`BrepError::ParameterCurveGap`）。1 点に縮退した辺では、中ほどの点も頂点に重なるので、つながるとみなす
- NIST の試験用のファイル（11 章の大きなファイル。11 個）では、当てはめの前に外していた面（NURBS 曲面の面・正確な形にならない組の面）を、すべて読めた（残る外した要素は、幾何の段で型にできなかったもの）
  - 読んだ NURBS 曲面の上の面（64 面）は、表示の許容弦誤差ですべて三角形にできる（#1417。`TRIMMED_FACE_TESSELLATION_DESIGN.md` 8.2）。当てはめの目安が稜線の許容誤差なので、許容誤差の広がった稜線（0.09〜0.12 mm）では、当てはめたパラメータ曲線のずれが 0.001 mm ほどになり、工程の精度 0.001 では 8 面が三角形にできない。目安を工程の精度より細かくすることは、別の Issue で扱う
- 閉じた NURBS 曲面（両端の制御点が重なる、円柱のような B-spline 曲面）は、周期のない曲面として扱う。継ぎ目の稜線（(u, v) の片側の端にしか写らない）を使うループと、継ぎ目をまたぐ稜線（写した点が定義域の端に止まり、ずれが大きくなる）のある面は、上の確かめか、ずれが上限を超えることで外す。閉じた NURBS 曲面に周期を持たせて読むことは、#1418 で扱う

### 5.6 切れ目を入れた範囲

- 継ぎ目のない周期的な面は、(u, v) の範囲が、1 つの閉じた輪で囲まれた形にならない（円柱の帯は、u の方向に 1 周する 2 本の線に挟まれた範囲。球の全体は、ループがない）
- 三角形にする処理・点が面の内側かの判定など、(u, v) で面を扱う処理のために、曲面と (u, v) のループ（点の並び）から「切れ目を入れた範囲」を作るヘルパーを `geo_algorithms` に置く
  - ヘルパーは `geo_topology` の型を受けない（`geo_algorithms` と、それに依存する `geo_io` を、位相に依存させないため。4.2）。面から曲面と (u, v) のループを取り出すのは、呼び出し元とする
  - 切れ目の位置は、ループの頂点のない、空いた角度の範囲から選ぶ。極（円錐の頂点・球の極）は、範囲の端の点として扱う
  - 結果は、(u, v) の閉じた輪の並びと、切れ目の位置（範囲の左右の端が同じ線であること）とする。面の位相は変えない
- 周期の扱いは、このヘルパーの中にまとめる。ほかの処理は、周期を直接扱わない
- ヘルパーの入出力と、トリムした面の三角形への分割の全体は、`TRIMMED_FACE_TESSELLATION_DESIGN.md`（#668）で決めた

## 6. 許容誤差

### 6.1 要素ごとの許容誤差

- 頂点と稜線は、それぞれ許容誤差を持つ。`Brep` は、全体の許容誤差（要素の許容誤差の下限）を持つ
- **全体の許容誤差は、モデルファイル（.rrm）ごとに 1 つに固定する**
  - モデルを作るときに、アプリの設定の既定値（今の線・円などの作成で使う標準の距離の許容誤差）から決め、利用者は作るときに変えられる。決めた値は .rrm に保存し、あとから変えない（変えると、作った表の確かめが成り立たなくなるため）。前の版の .rrm（値を持たない）は、開くときに既定値とする
  - 読み込んだ `Brep` も、モデルで作る `Brep` も、モデルの全体の許容誤差を表の全体の許容誤差にする
  - 読み込み（STEP のファイル）ごとに全体の値を決めないのは、許容誤差を変えて書き出したファイルを取り込み直すと、1 つのモデルに複数の全体の値が混ざるため
  - 小さな部品を精度よく扱うときは、部品を別のモデルとして作り、アセンブリとして配置する（部品ごとに全体の値を持てる）。アセンブリの部品の定義を別のファイルに持つかは、`SPACE_MODEL_FILE_DESIGN.md` の 13.2 で、この方針に合わせて決める。値の違う部品をまたぐ処理（干渉の確かめなど）は、関係する部品の値の最大を使う
- 要素の初めの値は、ファイルの許容誤差（`UNCERTAINTY_MEASURE_WITH_UNIT` を mm に直した値）とし、全体の許容誤差と上限の間に収める。ファイルにないときは、全体の許容誤差とする
- 要素の許容誤差の上限は、読み込む立体の大きさ（外形の箱の対角の長さ）に比例させる（腕時計の部品と建物で、同じ絶対の値を使わないため）
- 頂点が曲線から外れているときは、その頂点の許容誤差を、ずれの 1.5 倍まで広げる
- 稜線が面の曲面から外れているときは、稜線の区間を分けた点でずれを測り（区間を 8 つに分け、両端を含む 9 点で測る。パラメータ曲線の確かめと同じ点）、その稜線の許容誤差を、ずれの 1.5 倍まで広げる。NURBS 曲面では、当てはめたパラメータ曲線と 3 次元の曲線のずれで測る（曲面への最も近い点の探索は、離れた部分に落ちて、ないずれを返すことがあるため）
  - 解析的な曲面では、曲面の近い点までのずれで広げた後、広げた許容誤差でパラメータ曲線を作り、そのずれ（正確な形にならない組では、当てはめのずれ。5.5.1）が許容誤差を超えれば、そのずれの 1.5 倍まで広げる（`ParameterCurve::deviation`）。NURBS 曲面では、稜線の許容誤差を目安に当てはめたずれだけで測る
  - 面を足すときは、広げた許容誤差を目安に同じ処理をもう一度行い、パラメータ曲線を作る（目安を超える小区間は分けるので、ずれは広げた許容誤差に収まる。深さの上限まで分けた小区間は、読み込みで測ったときと同じ点で測る）
- 広げた値が上限を超えたら、その面を外し、理由（どの要素が、どれだけずれたか）を残す
- 頂点の合併（6.2）・稜線の一致の確かめは、両方の要素の許容誤差の和で比べる
- 頂点の許容誤差は、その頂点を使う稜線の許容誤差以上に保つ
- 処理の順は次のとおりとする
  1. 頂点を、その頂点を使う曲線に合わせて広げる
  2. 頂点をまとめる（6.2。まとめた頂点の許容誤差は、まとめる前の頂点をすべて含む値）
  3. 稜線を、面の曲面に合わせて広げる
  4. 頂点の許容誤差を、その頂点を使う稜線の許容誤差以上にそろえる

| 値 | 既定 |
|---|---|
| 全体の許容誤差（モデルごと） | アプリの設定の既定値（標準の距離の許容誤差）。モデルを作るときに変えられる |
| 要素の許容誤差の上限 | 読み込む立体の大きさ × 1e-3 |
| ずれに掛ける倍率 | 1.5 |

- 上限の比と倍率は、読み込みの設定とする。呼び出し元（`application`）が読み込みのときに渡し、利用者が画面から変えられるようにする（変えた値は、アプリの設定に持つ）。既定の比と倍率の数値は、`analysis` に名前をつけて置く（`GEOMETRIC_TOLERANCE_USAGE_RULES.md` の「呼び出し元が許容誤差を渡す」）
- 全体の許容誤差が、座標の大きさに対して f64 の刻みで表せない小ささ（座標の大きさの最大 × 1e-12 より小さい）なら、読み込みの結果に書く（値は変えない）
- 読み込みの設定の型（比と倍率の組）は `geo_step` の `topology` に置き（`ImportToleranceSettings`）、許容誤差を広げる処理もそこで行う（表に面を足す前に、稜線の形を求めて許容誤差を決め、頂点と稜線をまとめる）。`geo_topology` は、頂点・稜線ごとの許容誤差を持つ表と、その確かめ（頂点の許容誤差は、使う稜線の許容誤差以上）だけを持つ
- モデルの全体の許容誤差を .rrm に保存することと、モデルを作るときに決めることは、#1357 で作る
- 今の `TopologyToleranceSettings`（全体で 1 つ）は、`Brep` の全体の許容誤差として残す。稜線は母曲線と区間で持ち、端点を区間の端で評価した点の 1 つにしたため、`TOPOLOGY_ENTITY_LAYER_DESIGN.md` の稜線の許容誤差の内訳（δ_ideal・δ_eval・δ_bind）は分けない

### 6.2 頂点と稜線をまとめる

- 1 つの角に、ファイルの頂点（`VERTEX_POINT`）が複数あることがある。点が両方の許容誤差の中で重なる頂点は、1 つにまとめる。1 本の稜線の両端の頂点は、まとめない（短い稜線をつぶさないため）
- 同じ頂点の間で、同じ曲線と同じ区間を持ち、それぞれ 1 つの面だけが使う稜線の組は、1 本の稜線にまとめる
  - 同じ曲線と同じ区間かは、両方の区間を 8 つに分けた 9 点が、両方の許容誤差の和の中で重なるかで確かめる（同じ割合のパラメータの点どうしを比べるので、ファイルで別の曲線の記録でも、パラメータの付け方が同じならまとめる。円弧と同じ形の NURBS 曲線など、付け方の違う組はまとめない）。同じ面のループの中の 2 本は、ループの形が変わるのでまとめない。まとめた稜線の許容誤差は、離れを含む値とする
  - 頂点・稜線は、まとめた後の許容誤差が上限を超えるときはまとめない

### 6.3 立体の評価

- 要素ごとの許容誤差は、ずれに合わせて広がる。各要素が自分の許容誤差の中に収まっていても、全体としてずれの大きい形状がありうる
- 読み込んだ立体の精度を評価する機能（稜線と面の離れを、稜線に沿って確かめる・全体の許容誤差に比べて精度の悪い要素を数えるなど）は、STEP に限らず立体に使えるため、本書の範囲の外とし、別に設計する（12 章の後の Issue）

## 7. 2 次の曲線・曲面

- 円・楕円・円柱・円錐・球・トーラスは、`geo_primitives` の解析的な型のまま持つ（読み込みで形を変えない）
- 放物線・双曲線は、RedRing に解析的な型がないため、読み込むときに有理でない NURBS 曲線で近似する。近似のずれは、稜線の許容誤差に含める
- NURBS が要る処理（NURBS 曲面だけを受ける計算など）は、使うときに有理でない近似を作り、ずれを許容誤差として扱う。有理 2 次の正確な円は作らない（有理 2 次の円は意匠 CAD だけで使う決まり）
- ファイルの有理の B-spline 曲線・曲面は、読んだとおり有理のまま持つ（ファイルの形を変えない。上の決まりは、RedRing が作る円の表し方の決まり）
- 両端を固定していない B-spline（周期的なものを含む）は、ノットの挿入で、両端を固定したノットベクトルの同じ形に直す（形は変わらない）
- 回転の面・押し出しの面・オフセットの面
  - 押し出しの面: 曲線が直線なら平面、押し出しの向きが軸と平行な円なら円柱にする。それ以外は、7.2.2・7.2.4 で外すものを除き、押し出しの面の型にする（7.2）
  - 回転の面: 回す曲線が、軸に平行な直線なら円柱、軸と交わる直線なら円錐、軸の上に中心のある円なら球、軸を含む平面の上の円ならトーラスにする。それ以外は、7.2.2・7.2.4 で外すもの（軸と直角に交わる直線を回した平らな面は、今のまま外す）を除き、回転の面の型にする（7.2）
  - 平面・円柱・円錐・球・トーラスになるものを、押し出し・回転の面の型にそろえないのは、これらの型では、パラメータ曲線の正確な形（5.5）・三角形分割の近道（`TRIMMED_FACE_TESSELLATION_DESIGN.md` 6.3）・オフセットが今のまま使えるため
  - オフセットの面: 解析的な曲面のオフセットは、同じ種類の曲面（半径を変えたものなど）にする。それ以外（NURBS 曲面・押し出しの面・回転の面のオフセット）は、初めは理由をつけて外す（型で持つかは #1495 で決める）

### 7.1 管が軸と交わるトーラス

管の半径（小半径 r）が中心の円の半径（大半径 R）以上のトーラスは、自分と交わる。断面の円のうち、軸から見て同じ側の大きな弧を回した外側の部分（りんご形）と、軸の向こう側に中心がある小さな弧を回した内側の部分（レモン形・樽の側面）に分かれ、2 つは軸の上の 2 点で交わる。

- ISO 10303-42 の `toroidal_surface` は、大半径・小半径を正の長さとし、式 σ(u, v) = C + (R + r cos v)(cos u X + sin u Y) + r sin v Z の全体を曲面とする。どちらか一方の部分は、下位の型の `degenerate_toroidal_surface`（R < r。`select_outer` が真なら外側、偽なら内側）で表す
- 実際のファイルでは、SolidWorks が内側の部分を、大半径を負にした `TOROIDAL_SURFACE` で書く（規格には合わない）。Parasolid・ACIS は「大半径が負なら内側（レモン形）」と決めていて、これをそのまま書き出している。式に負の大半径を入れると、R + r cos v > 0 の側がレモン形になり、∂u × ∂v は管の中心（軸の向こう側）から離れる向きで、ファイルの面の向きとも合う（SolidWorks のサンプルデータ 2 つの、内側の面 207 面すべてで、境界の頂点と稜線の点の位置から確かめた）。OpenCASCADE は大半径を正に直し、面の向きを逆にして読む
- 2026-11 の時点で、形状 93 個のアセンブリのサンプルデータで、樽の側面の 6 面（大半径 −53.1・−85.3・−12.1 mm）を `InvalidShape` で外し、その面を持つシェル 3 つが開いていた

読み方の案（#1479。2026-11-27 に、利用者が案 1 を選んだ）:

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| 1（選んだ） | `TorusSurface3D` で負の大半径（−r < R < 0）を受け付け、面を R + r cos v ≥ 0 の部分とする。管が軸と交わるトーラスは、球と同じく v に周期を持たせず、R + r cos v = 0 の 2 つの v を極にする | ファイルの値を変えずに持つ。点・法線の式は今のまま。.rrm の形式も変えない。`degenerate_toroidal_surface` も、外側は正の大半径、内側は負の大半径に直して同じ型で持てる | 負の大半径の .rrm は、前の版のアプリでは開けない（形の誤りとして開くのをやめる） |
| 2 | 読むときに大半径を正に直し、外側か内側かの印を曲面の型に足す | 規格どおりの値で持つ | 曲面の型を使うすべての処理（.rrm の形式・三角形への分割・オフセット）に印の扱いが要る。.rrm の版を上げる |
| 3 | 内側の部分を NURBS 曲面にする | 曲面の種類が増えない | 近似のずれが出て、解析的な形がなくなる。1 周する面では、閉じた NURBS 曲面の扱い（#1418）にかかる |
| 4 | 今のまま外し、理由の出し方だけ直す | 直す量が少ない | 面が欠け、シェルが開いたまま |

案 1 の決め:

- 面は、σ(u, v) のうち R + r cos v ≥ 0 の部分（断面の円の、軸から見て角度 u の側にある部分）とする。R > r ならトーラスの全体、0 < R ≤ r なら外側、−r < R < 0 なら内側。R = 0（球）と R ≤ −r（面がないか 1 点）は作らない
- 管が軸と交わるトーラスの v は、`[−v₀, v₀]`（cos v₀ = −R / r）で、両端の v が極（軸の上の点。u によらず 1 点）になる。周期は u だけとし、点の (u, v) は v を周期で折り返さない（`(−π, π]` の中）。極では面がとがっているので（円錐の頂点と同じ）、法線を決めない
- 極・帯・ループのない面の扱いは、球と同じ（8.3 の読める形、`TRIMMED_FACE_TESSELLATION_DESIGN.md` の極の扱い）。0 < R < r の外側の部分も、この扱いに変わる（前は v にも周期を持たせていた。軸に届かない面は、どちらでも同じに読める）
- 点までの距離は、点と軸を含む断面の、点の側の半平面の上で、断面の円のうち軸からの距離が 0 以上の弧までの距離とする（弧の上の最も近い点が軸の向こう側に出るときは、極までの距離）
- 回転の面で、回す円の管が軸と交わるものは、面がどちらの部分にあるかを曲面だけからは決められないので、今のまま範囲の外とする
- `degenerate_toroidal_surface`（#1466）は、この型で持つ。外側（`select_outer` が真）は、そのままの正の大半径。内側（偽）は、大半径を負にし、u を π、v を π − v に付け替えた同じ点の式にする（v の向きが逆になるので、∂u × ∂v も逆になる）。ファイルの面の向きと ISO の法線の決まり（内側の法線は ∂u × ∂v と逆）が合うかは、#1466 で、立体の囲む体積の符号で確かめて決める

### 7.2 押し出しの面・回転の面（#1484）

STEP の押し出しの面（`SURFACE_OF_LINEAR_EXTRUSION`）と回転の面（`SURFACE_OF_REVOLUTION`）は、NURBS 曲面に置き換えず、STEP と同じ形（元の曲線と、押し出しのベクトル・回転の軸）の解析的な型で持つ（2026-11-28 に利用者が決めた）。平面・円柱・円錐・球・トーラスになるものは、7 章の初めのとおり、その型にする。

- 2026-11 の時点で、大きなアセンブリのサンプルデータでは、外れた面 3,631 枚のうち 3,573 枚が、押し出しの面（3,341 枚。押し出す曲線はすべて B-spline）と回転の面（232 枚。回す曲線は B-spline 217、複合の曲線 15）の上にあった
- NURBS 曲面に置き換えるより、次の点で良い
  - データが小さい。回転の面を有理でない近似で NURBS にすると、制御点が回す曲線の 10〜30 倍になる（押し出しの面は約 2 倍）
  - 形が正確で、近似のずれが稜線の許容誤差に加わらない
  - パラメータが STEP の定義（押し出しの長さ・回す角度）と同じになる
  - 1 周する回転の面を、円柱と同じく周の向きに閉じた曲面として持てる（NURBS 曲面は、周期を持たない四辺の面にする決まり）
  - 2 次の曲面を解析的な型のまま持ち、NURBS が要る処理では使うときに近似を作る、という 7 章の初めの決まりと同じ考え方になる

#### 7.2.1 置き場（形状の層 `geo_shapes`）

- 元の曲線は、直線・円・楕円・NURBS 曲線のどれもありうる。今それを 1 つの型で持つ曲線の参照（`CurveRef`）は `geo_topology` にあり、`geo_primitives` と `geo_nurbs` は互いに依存しない（4.2）ので、型をどちらにも置けない
- `geo_primitives`・`geo_nurbs` の上に、両方の型を参照する形状の層のクレート `geo_shapes` を足す（2026-11-28 に利用者が決めた）
  - 置くもの: 曲線の参照（`CurveRef`）、曲面の参照（`SurfaceRef`。点・法線・周期・極などの形の操作を含む）、押し出しの面の型（`ExtrusionSurface3D`）・回転の面の型（`RevolutionSurface3D`）
  - `geo_topology` は、B-rep の表・パラメータ曲線・表の確かめを持ち、`geo_shapes` の曲線・曲面の参照を使う。`geo_topology` に別名の再エクスポートは置かず、使う側の import を直す
  - `geo_io` は `geo_shapes` に依存しない。モデルファイルの押し出し・回転の面のバイト列は、`application` のモデルファイルの読み書きが、`geo_io` の曲線のバイト列を組み合わせて書く（7.2.6）
- ほかの案と、選ばなかった理由
  - `geo_topology` に置く: 依存は変わらないが、位相のクレートに曲面の形の評価が増え、形と位相が分かれない
  - `geo_primitives` に置き、元の曲線を型引数で受ける: 曲線の点と微分の trait を `geo_contracts` に足すことになり、今それを実装するのは曲線の参照だけ
- 曲線・曲面の参照を移すことは、振る舞いを変えない段 0（#1493）として先に行う

#### 7.2.2 型と持つもの

| 型 | 持つもの | パラメータ | 点の式 |
|---|---|---|---|
| 押し出しの面（`ExtrusionSurface3D`） | 元の曲線（曲線の参照）、押し出しのベクトル V（向きと長さ。STEP の `VECTOR` の大きさを掛けたもの） | u: 元の曲線のパラメータ。v: 押し出しのベクトルの長さを 1 とする量 | σ(u, v) = C(u) + v V |
| 回転の面（`RevolutionSurface3D`） | 元の曲線、軸（点 A と単位の向き k）、元の曲線の両端の極の種類 | u: 軸のまわりの角度（k のまわりに右ねじの向き。u = 0 は元の曲線）。v: 元の曲線のパラメータ | σ(u, v) = A + R(u)(C(v) − A)（R(u) は k のまわりの角度 u の回転） |

- パラメータと法線の向き（∂u × ∂v）は、STEP の定義（ISO 10303-42）と同じにする。そのため、型の曲面の法線と STEP の曲面の法線は、いつも同じ向き（`Sense::Same`）になる
  - 今の読み込みは、押し出しのベクトルの大きさを捨て、向きだけを使っている。押し出しの面の型には、大きさを含めて渡す
- 元の曲線は、直線・円・楕円・NURBS 曲線とする。次の面は、初めは理由をつけて外す（後の Issue）
  - 放物線・双曲線を元にする面（今は稜線の区間ごとに NURBS 曲線にする。曲面の元の曲線には区間がない）
  - 複合の曲線を元にする面（中間データで、複合の曲線を読まない）
  - 直線を回した面で、直線が軸と平行でも交わりもしないもの（回転の双曲面。元の曲線の定義域に限りがなく、初めの点の格子（7.2.3）を作れない。サンプルデータになかった）
- 周期
  - 押し出しの面: 元の曲線が円・楕円なら u に 2π。v には周期がない
  - 回転の面: u に 2π。元の曲線が円・楕円なら v にも 2π
  - 元の曲線が閉じた NURBS 曲線でも、周期を持たせない（閉じた NURBS 曲面と同じ扱い。5.5.1・#1418。継ぎ目をまたぐ面は外れる）
- ループのない面にできる閉じた曲面は、回転の面で元の曲線が円・楕円のものだけとする
- 押し出しの面の v には限りがない。面の範囲は、ループが決める
- 回転の面の極の種類は、元の曲線の始まりの端と終わりの端ごとに「極でない」「接線が軸に垂直な極」「とがった極」のどれかとし、読み込みで決めて型に持つ（7.2.4）。型は、許容誤差を受けず、形の判定をしない

#### 7.2.3 型が持つ操作

使う処理があるものだけを持つ。

| 操作 | 使う処理 |
|---|---|
| 作る（値が有限で、ベクトル・軸の向きが 0 でないことだけを確かめる） | 読み込み・モデルファイル |
| 持つものを返す | モデルファイル |
| 点 | 曲面の参照の点 |
| 1 階の偏導関数 ∂u・∂v | 法線・点の (u, v) を詰めること |
| 法線（∂u × ∂v の単位ベクトル。縮退した点では決めない。回転の面の極では、接線が軸に垂直な極なら、極の近くの ∂u × ∂v の向きの極限（軸に沿う向きで、正か負かは、元の曲線の接線の向きと、極が始まりの端か終わりの端かで決まる）、とがった極なら決めない） | 三角形分割の法線 |
| 周期・極の v | 曲面の参照の周期・極（ループの確かめ・三角形分割） |
| 点の (u, v) を、近い (u, v) から詰める（ガウス・ニュートン法。NURBS 曲面の `parameter_for_point_from` と同じ形と止め方。5.5.1） | パラメータ曲線の当てはめ |
| 点の初めの (u, v)（元の曲線の定義域に格子で点を取り、押し出しの面では各 u で v を (P − C(u))·V / (V·V) から、回転の面では各 v で u を軸のまわりの角度の差から決め、最も近いもの） | 当てはめの初めの点 |

- 曲線の参照に、1 階の微分（直線・円・楕円は閉じた式、NURBS 曲線は今の `derivative_at`）と、周期と定義域（円・楕円は周期 2π、NURBS 曲線はノットの範囲）を足す。偏導関数・型の周期・初めの点の格子に使う
- 許容誤差は、どの操作も呼び出し元が渡す（`GEOMETRIC_TOLERANCE_USAGE_RULES.md`）。新しい決まった数は置かず、繰り返しの上限などは NURBS 曲面の点の (u, v) を詰める処理と同じものを使う
- NURBS の近似を作る操作は、今は足さない
  - 今の曲面の参照の使い手（パラメータ曲線・表の確かめ・三角形分割・モデルファイル・読み込みの上限の数え方。7.2.5）は、どれも点・偏導関数・法線・周期・極だけで受けられ、NURBS 曲面だけを受ける処理はない。CAM の入力も、三角形分割の結果を使う
  - NURBS 曲面だけを受ける処理（一般のオフセットの面（#1495）、解析的な面を三角形メッシュを通さずに CAM の計算に使うこと（#1414）、STEP でない形式の書き出しなど）ができたときに、型の操作として足す。押し出しの面は正確な NURBS 曲面（u は元の曲線と同じ次数・ノット・重み、v は 1 次。v の範囲は使う処理が渡す）、回転の面は有理でない近似（有理 2 次の円は作らない。7 章の初め）で、ずれを返す。近似の許容誤差は使う処理が渡し（#1465）、回す向きの分け方（数と次数）は、そのときに決める
- ファイルのパラメータ曲線（`PCURVE`）は、5.5 のとおり使わない。型のパラメータが STEP と同じなので、後で使うと決めたときは、写し直さずに使える

#### 7.2.4 縮退

読み込み（`geo_step` の曲線・曲面の段）で、型を作る前に確かめ、縮退するものは理由をつけて外す。角度は、今の読み込みと同じく、呼び出し元の `ToleranceSettings` を使う。極と軸に触れることを決める距離は、ファイルの許容誤差（6.1 の要素の初めの値）とする（今の曲線・曲面の段は標準の距離の許容誤差 1e-6 mm を受けるが、極の端はファイルの精度でしか軸に載らないため）。確かめる点は、元の曲線の定義域を、円・楕円は 1 周を、NURBS 曲線はノットの区間ごとに、8 つに分けた点（両端を含む）とする。点の値だけでは、点の間の縮退や軸との接触を見落とす（点の値が単調に並んでいても、点の間で触れることがある）。そのため、軸との接触と、接線の平行は、区間ごとの下界で確かめる。

- 軸との接触（回転の面）: 区間の曲線を囲む範囲から、軸からの距離の下界を求める。NURBS 曲線は、区間を Bezier に分け（ノットの挿入）、制御点の凸包（重みが正なら、曲線は制御点の凸包の中にある）を、軸に垂直な平面に写した多角形と、軸の点との距離を下界とする。円・楕円は、1 周を小区間に分け、小区間の弧を、弦と弧の高さで囲む範囲から下界を求める
  - 下界が距離の許容誤差より大きければ、その区間は軸に触れない
  - そうでなければ、区間を 2 つに分けて（Bezier は de Casteljau の分割）同じことを繰り返す
  - 止める条件: 区間の曲線を囲む範囲の大きさ（写した制御点どうしの距離の最大、円・楕円では弦の長さ）が距離の許容誤差以下になったら、そこで分けるのをやめ、その区間の点の軸からの距離が許容誤差以下なら触れるとする。分けるごとに範囲は小さくなるので、必ず止まる
- 接線の平行（押し出しの面のベクトル・回転の面の回す向き）: ∂u × ∂v そのものを区間で囲む。押し出しの面は V × C′(t)、回転の面は (k × (C(t) − A)) × C′(t) で、回す向き k × (C − A) は t とともに変わるので、1 つの平面に写すだけでは囲めない。そこで、この外積を、分母を払った多項式の曲線（有理でない NURBS 曲線は C′ の Bezier の制御点から、有理の曲線は C = p / w として w³ を掛けた (k × (p − A w)) × (p′w − p w′) から。どちらも、Bezier の積の制御点として正確に求まる）にし、その制御点の凸包と 0 の点との距離を下界にする。有理の曲線では、これは w³ を掛けた外積の下界なので、区間の中の w³ の上界（重みが正なので、区間の Bezier の重みの最大の 3 乗）で割って、外積の大きさの下界にする。角（の正弦）の下界は、この下界を、2 つの向き（V か k × (C − A) と、C′）の大きさの上界の積で割って求め、角度の許容誤差と比べる。分け方は軸との接触と同じとし、区間の外積の制御点どうしの距離の最大が、角度の許容誤差 × 2 つの向きの大きさの上界の積 × w³ の上界以下になったら止める。止めたときに角の下界がまだ角度の許容誤差以下なら、区間の中の点を選んで決めることはせず（選んだ点が縮退する所から外れると見落とすため）、決まらなかった区間として安全な側に倒し、縮退するとして外す。円・楕円は、押し出しの面は閉じた式（下の項）、回転の面は小区間の弧を囲む範囲から同じく求める
- 極の近く（下の回転の面の項）は、この確かめから除く

面の範囲は曲面を作るときには分からないので、面の範囲の外で縮退するものも外す。

- 押し出しの面: 押し出しのベクトルが元の曲線の接線と平行になる点では、∂u × ∂v = 0 になり、法線が決まらない
  - 円・楕円は、ベクトルが曲線の平面の上にあれば縮退する（閉じた式で確かめる）
  - NURBS 曲線は、接線とベクトルが平行（同じ向きか逆の向き）から角度の許容誤差以内になるか、接線が 0 になれば外す（ふつうの押し出しは、曲線の平面に垂直か斜めのベクトルで、縮退しない）
- 回転の面
  - 元の曲線の端が軸の上（距離の許容誤差以内）にあれば、その端を極にする。曲線の接線と軸の角が直角から角度の許容誤差以内なら「接線が軸に垂直な極」、ほかは「とがった極」とする。点の式は元の曲線のままとし、端を軸の上に寄せない（ファイルの形を変えない）
    - 端が軸からわずかに離れていると、極の v の線は 1 点でなく、半径が距離の許容誤差以下の小さな円になる。ループの確かめと三角形分割は、この線を 1 点として扱う。つぶす先の点（極の点）は、端から軸に下ろした足（軸の上の点）とし、円の上の点（u = 0 の点など）にしない。円の上の点は極の点から半径（距離の許容誤差以下）しか離れず、そのずれは、極にある頂点・稜線の許容誤差（ファイルの許容誤差以上。6.1）に収まる（円の上の 1 点につぶすと、反対の側の点まで半径の 2 倍離れ、収まらないことがある）
  - 端でない所で軸に触れる・軸をまたぐ曲線は外す。極のほかの所で、曲面が自分と交わるため
    - 極の近く: 極の端から曲線の内側へたどり、軸からの距離が初めて距離の許容誤差を超えるまでの範囲とする（曲線は極の端から続いているので、そのすぐ隣の点も軸に近い。この範囲は、軸に触れているとしない）
    - 極の近くの外で、上の区間ごとの確かめで軸に触れるとした区間がある（止めたときの区間の点の軸からの距離が距離の許容誤差以下。下界だけでは決めない）か、隣り合う点の、軸から離れる向きの角が直角を超えれば外す。極のない端では、端そのものから確かめる
  - 極の端を除き、曲線の接線と回す向き（軸のまわりの円の向き）が平行（同じ向きか逆の向き）から角度の許容誤差以内になるか、接線が 0 になれば外す（∂u × ∂v = 0 になるため）。押し出しの面の確かめと同じ形。極の端では回す向きが決まらないので、上の極の種類の決め方で確かめる
  - 元の曲線を回した形が自分と重なるか（軸からの距離と高さの同じ点が、曲線の 2 か所にあるか）は確かめない。面はループで囲んだ部分だけで、点・法線の式はそのまま成り立つ
- 極の扱いは、球の極・円錐の頂点・管が軸と交わるトーラスの極と同じとする（極の v の線は u によらず 1 点。8.3 の「極までの面」と、極を通る稜線を極で分けること、`TRIMMED_FACE_TESSELLATION_DESIGN.md` 5.3 の極の扱い）。縮退した辺のまま持ち、極の近くを別に扱わない

#### 7.2.5 曲面の参照に足す種類と、種類ごとの処理

曲面の参照（`SurfaceRef`）に、押し出しの面（`Extrusion`）と回転の面（`Revolution`）を足す。種類で分ける処理は、種類を漏らせない（Rust の `match`）ので、使い手ごとに受け方を決める。NURBS の近似で受ける所はない（7.2.3）。

| 使い手 | 受け方 |
|---|---|
| 曲面の参照の点・法線・周期・極・点が極にあるか | 型の操作 |
| 閉じた曲面か | 回転の面で、元の曲線が円・楕円のもの |
| 点の (u, v) を閉じた式で求めること | なし（NURBS 曲面と同じ） |
| パラメータ曲線（5.5・5.5.1） | 正確な形は作らず（#1494 で足す）、当てはめる。写し方は NURBS 曲面と同じく、前の点の (u, v) から詰める（初めの点は型の操作）。周期のある向きは、前の点から詰めるので、つながった値になる。(u, v) を定義域に収める処理は、元の曲線が NURBS 曲線のときの、その定義域の向き（押し出しの面の u・回転の面の v）だけにかける（円・楕円の周期のある向きと、押し出しの面の v には限りがないので、収めない） |
| ループのつなぎ目の (u, v) の確かめ（5.5.1） | 押し出しの面・回転の面にもかける（当てはめたパラメータ曲線どうしのつなぎ目のため）。周期のある向きは、周期の分を除いて比べる |
| ループの巻き数の確かめ（8.3） | 押し出しの面で u に周期のあるものは、円柱と同じ規則。回転の面は、v に周期がなければ、両端が極なら球、片方の端が極なら円錐、極がなければ円柱と同じ規則。v にも周期があれば、トーラスと同じ規則 |
| 面の三角形分割（`application` の `shell_mesh`） | NURBS 曲面と同じく、面の (u, v) の範囲に格子で点を取って測った長さと曲がりで、刻みと三角形分割の座標を決める（`TRIMMED_FACE_TESSELLATION_DESIGN.md` 6.3。点の評価だけを使うので、曲面の種類によらない）。極は、曲面の参照の極。ループのない面（回転の面の全体）の範囲は、u・v の周期 |
| 読み込みの上限（4.3 の制御点の合計） | 元の曲線の制御点の数を数える |
| オフセットの面（7 章の初め） | 理由をつけて外す（#1495 で決める） |
| モデルファイル | 7.2.6 |

- 三角形分割の近道（押し出しの面は、円柱と同じく押し出しの向きに内側の点を足さないなど）は、段 3（#1494）で、効きを測ってから足す

#### 7.2.6 モデルファイル

- B-rep の表の曲面の種類に、7: 押し出しの面、8: 回転の面を足す（`SPACE_MODEL_FILE_DESIGN.md` の区画 `SHEL`）
  - 押し出しの面: 元の曲線（稜線の曲線と同じく、曲線の種類 `u8` と `geo_io::binary_geometry` の曲線）・押し出しのベクトル `f64`×3
  - 回転の面: 元の曲線・軸の点 `f64`×3・軸の向き `f64`×3・始まりの端と終わりの端の極の種類 `u8`×2（0: 極でない、1: 接線が軸に垂直な極、2: とがった極）
  - 読むときは、信用できない入力として、極の印のある端の軸からの距離が、表の頂点・稜線の許容誤差の最大以下か（面が極まで届かず、極に頂点がないこともあるため、端の頂点では確かめない。要素の許容誤差は、極を決めたファイルの許容誤差以上。6.1）を確かめ、あわせて、印のある端の極の種類（1: 接線が軸に垂直な極、2: とがった極）を、上の決め方で求め直し、書かれた種類と合うかを確かめる。合わなければ壊れたファイルとして開かない（型は形の判定をしないため、表を戻す処理で確かめる。10.3）
    - 印のない端は確かめない。読み込みは、ファイルの許容誤差で極でないと決めたが、表にはその値が残らず、表の全体の許容誤差・要素の許容誤差は、ファイルの許容誤差と同じとは限らない（違う値で比べると、自分で書いたファイルを開けなくなる）。印のない端が軸に近くても、極の v の線が小さな円のまま、ふつうの辺として扱われるだけで、形は壊れない（面を足す処理の確かめは、そのまま行う）
    - 求め直しに使う角度の許容誤差は、読み込みで極の種類を決めたときと同じ値とする。今は、どちらも標準の値（`ToleranceSettings::standard()` の角度の許容誤差）を使う。モデルの許容誤差をアプリケーションの側に持つとき（#1465）は、読み込みと表を戻す処理に同じ値を渡す
  - 曲面としてまとめたバイト列は、`geo_io` に足さない（`geo_io` は `geo_shapes` に依存しないため。7.2.1）
- 区画 `SHEL` の版の上げ方は、`SPACE_MODEL_FILE_DESIGN.md` 4.2 に書く

## 8. STEP から位相を作る規則（`geo_step` の `topology`）

### 8.1 向き

ファイルの向きの旗をそのまま信用せず、形で確かめて直す。直したときは、何を直したかを残す。

- 稜線（`EDGE_CURVE`）: 稜線の区間は、いつも小さいほうから大きいほうへ持つ。ファイルの稜線が区間の向きに沿うかは、閉じた曲線では `same_sense` から、開いた曲線では両端の頂点の曲線のパラメータの順から決める。開いた曲線で `same_sense` と頂点の順が食い違うときは、頂点の順を使う
- ループ（`FACE_BOUND`）: `orientation` が `.F.` なら、ループを逆にする
- 面（`ADVANCED_FACE`）: 面の向きは、`same_sense` と、曲面を RedRing の型にしたときに法線が逆になったかの組で決める。`same_sense` は曲面の法線と面の法線の関係だけを表し、ループの向きは面の法線を基準に書かれている（ISO 10303-42。5.3 と同じ）。そのため、面の向きが裏でも、ループは逆にしない
- `ORIENTED_FACE`: 向きの旗を重ねて反映する（入れ子は 4 段まで）
- 回転でできた球（軸の上に中心のある円を回した球）: 円の半分ずつが球の全体を作り、面がどちらの半分から作られたかで STEP の法線が逆になる。面の継ぎ目の稜線（同じループで行きと帰りに使う稜線）は、回転の角度 0 の位置で回した円の上にあるので、継ぎ目の点での STEP の法線（回る向き × 回した円の接線）から決める。継ぎ目がなければ、ループの回りで確かめ、表と裏のどちらも規則に合う面は、向きを決められなかった面として結果に書く（ファイルのパラメータ曲線から決めることは、後の Issue）
- ループが 5.3 の規則（面がループの左）に合わなければ、面を裏返す。外側のループのない面では、ループの巻き数（8.3）の符号で確かめる
- 内側のループが、外側のループと同じ回りなら、逆にする
- 空洞: `ORIENTED_CLOSED_SHELL` の旗は使わない（すでに空洞の側を向いたシェルに `.F.` を書く CAD があるため）。外側のシェルか空洞のシェルかは、立体の記録（`MANIFOLD_SOLID_BREP`・`BREP_WITH_VOIDS` の外側と空洞）から決め、シェルの囲む体積の符号が期待する符号（外側は正、空洞は負）と違えば、シェルの面をすべて裏返す（体積の符号で外側か空洞かを決めると、面の向きの決め方と循環するため。体積の求め方は `TRIMMED_FACE_TESSELLATION_DESIGN.md` 9 章）。今の実装は `ORIENTED_CLOSED_SHELL` の旗を使っており、#1380 でこの決め方に変える

### 8.2 稜線の区間

- 円・楕円の稜線の区間は、両端の頂点の角度から決める。両端が同じ頂点なら 1 周とする。両端の頂点が許容誤差より近くても、別の頂点なら 1 周にしない（短い円弧のまま）
- 直線の稜線で、頂点が直線から大きく外れるときは、頂点の間の線分にする
- 開いた曲線（直線・放物線・双曲線）の上の閉じた稜線は、読めないものとする

### 8.3 周期的な面

周期的な曲面（円柱・円錐・球・トーラス・閉じた NURBS 曲面）の面は、継ぎ目の稜線を足さずに持つ。読み込みでは、面が 5.6 のヘルパーで扱える形かを確かめる。

- ループを曲面のパラメータ（u, v）に写し、u・v の周期を何回まわるか（巻き数）を数える
- 読める形
  - 周期をまわらないループだけの面
  - 1 つのループが 1 回まわる面（極までの面。円錐の頂点まで・球の極まで）
  - 2 つのループが逆向きに 1 回ずつまわる面（円柱の帯など）。トーラスでは、管のまわりにまわる面も同じ
  - ループのない面（閉じた曲面の全体）。切れ目（稜線に沿って行って戻るループ）だけで囲まれた面も、閉じた曲面の全体とし、切れ目は捨てる（切れ目は、続けて使う同じ稜線の行きと帰りを打ち消していき、ループの初めと終わりをつないでも何も残らないループとする。頂点だけのループは、切れ目と一緒にあってよい）
- 極を通る稜線は、極で分ける（パラメータ曲線が極で折れるため）
- 読めない形（理由をつけて外す）: 1 つのループが 2 回以上まわる、v の方向にもまわる、軸のまわりにまわるループが 3 つ以上ある、u・v の両方で閉じた NURBS 曲面にループがある
  - 今は、閉じた NURBS 曲面も周期のない曲面として扱い、継ぎ目にかかるループの面を外す（5.5.1）
- ファイルにある継ぎ目の稜線は、取り除かずに残す（同じ面で 2 回使う稜線）
- 1 周より多く巻く面（ねじ山の側面など）は、初めは理由をつけて外す。読むときは、曲面を 1 周より先まで伸ばした NURBS 曲面にし、パラメータ曲線は、稜線の角度を連続して追った形で作る（後の Issue）

### 8.4 読めない面の扱い

- 段 3 のエラーは、どの面（ファイルのエンティティの番号）で起きたかを持つ
- ループの隣り合う稜線が同じ頂点でつながらない面は、読めない面として外す（保存した表を開くときに、ループのつながりを確かめるため。`SPACE_MODEL_FILE_DESIGN.md` の区画 `SHEL`）
- 面が読めないときは、その面を外し、残りの面でシェルを作り直す（開いたシェルになる）。作り直しでまたエラーになったら、そのエラーが持つ面を外して作り直す。作り直しは 8 回までとする
  - 作り直しは、表現の要素の表を初めから作る（読めなかった面のために足した稜線・頂点を、表に残さないため）。表に稜線・頂点を足す前に外れた面（NURBS 曲面の面・曲面からのずれが上限を超える面など）は、表に何も残さないので、作り直さずに外す。要素の許容誤差の上限（6.1）は、外した面も含めた大きさで決める
- それでも作れないときは、1 つずつ読める面を、面単体として読む（面ごとに 1 つの表を作り、その面だけの開いたシェルにする。立体は作らない）
- 上限（4.3）を超えたときは、表現の要素ごと止める
- 外した面と理由は、読み込みの結果として返す（10.4）。外した面を三角形メッシュとして残すことはしない

## 9. 構文と中間データ（`geo_step` の `syntax`・`record`）

### 9.1 構文

- エンティティの表は、番号の順に並べる（どの環境でも同じ順に回せる）
- エンティティは、名前と引数の組の並びとする（複合のエンティティは、組が複数）
- 引数の種類: 整数・実数・文字列・列挙・参照・リスト・型つきの値・バイナリ・なし（`$`）・派生（`*`）
- 同じ番号が 2 回出たら、初めのものを使い、重なりとして記録する
- 短い名前（`ADVFC` など）は、正式な名前に直す。構文の段では書かれた名前のまま持ち、中間データの段で、規格の表から直す
  - 短い名前の表は、ISO が規格の保守のページ（ISO Standards Maintenance Portal の ISO 10303 の短い名前の表）で、すべてのスキーマ（AP）をまたいで 1 つの表として決めている。短い名前・正式な名前はそれぞれ重ならないため、スキーマで読み分けない（実装の Issue で表を確かめて決めた）
  - 実装には、中間データの段が読むエンティティの組だけを写し、出どころ（表の場所・最終更新の日・SHA-256）を書き残す。表にない短い名前は、書かれたとおりに残し、読めない要素として扱う
- 文字列のエスケープ（`\X\`・`\X2\`・`\X4\`・`\S\`）を直す。エスケープの外の UTF-8 として読めないバイトは ISO 8859-1 として読み、`\X2\`・`\X4\` の中の直せない文字は置き換え文字にする。文字列・バイナリの中の改行は中身に含めない
- 先頭の BOM は飛ばす。ヘッダの `FILE_SCHEMA` から、AP の種類と版を読む

### 9.2 中間データ

- 長さは mm に直す（`dev/foundation/UNITS.md`）
- 角度は `analysis` の `Angle` で持つ。ファイルの角度の単位が度なら度から（`from_degrees`）、ラジアンならラジアンから（`from_radians`）作る。それ以外の換算の単位は、度への倍率を掛けて度から作る
- 単位は、表現の文脈（`REPRESENTATION_CONTEXT`）ごとに持つ（1 つのファイルの中で単位の違う文脈を読める）
  - SI の接頭語は倍率にする。換算の単位（インチ・度など）は、ファイルに書いた換算の値を使う。換算の連なりは 4 段までとし、循環は単位なしとする
  - 単位がない・壊れているときは、mm と度とし、そのことを記録する
- 配置（`AXIS2_PLACEMENT_3D`）は、ファイルの値のまま持つ（正規直交にしない。軸と基準の方向はないことがある）。正規直交の座標系にするのは段 3 とする
  - 理由: 段 2 で計算をしないため（4.1）
- 読む表現の決まり（AP の種類ではなく、文脈の次元と表現の種類で決める。AP203・AP214・AP242 のどれでも同じ規則で扱う）
  - 2D と 3D の形状は、表現の文脈（`GEOMETRIC_REPRESENTATION_CONTEXT`）の座標の次元で分かれる。次元 3 の文脈の表現に載る、立体とシェル（`MANIFOLD_SOLID_BREP`・`BREP_WITH_VOIDS`・`SHELL_BASED_SURFACE_MODEL` など）だけを読む
  - 次元 2 の文脈の形状と、線・点だけの表現の要素（ワイヤーフレーム）は読まずに、飛ばしたことを記録する（何を、いくつ飛ばしたか）。1 つの形状の定義が、立体の表現と線の表現の両方を持つときは、線の表現を飛ばすため、立体の表現を使うことになる
  - 曲線・曲面・頂点・稜線・面・シェルなどのエンティティは、AP によらず同じ規格の部（ISO 10303-42）なので読み分けない。スキーマでは読み分けない（短い名前の表も、すべてのスキーマで 1 つ。9.1）。製品の文脈の書き方の違い（AP203 の第 1 版の `DESIGN_CONTEXT`・AP214 の `PRODUCT_DEFINITION_CONTEXT` など）は、どちらも受け付ける（#1360）。AP242 にだけあるもの（PMI・三角形で表した形状など）は範囲の外とし、飛ばしたことを記録する
- 幾何（点・曲線・曲面）と位相（頂点・稜線・ループ・面・シェル・立体）を、ファイルの番号を持った記録にする。ファイルで共有している要素は、1 回だけ読む
- 製品構造（製品・形状の表現・アセンブリの出現・配置・名前・色・非表示）を記録する
  - 製品は `PRODUCT_DEFINITION` ごとに、製品の識別子・名前と、`SHAPE_DEFINITION_REPRESENTATION` で結ばれた形状の表現を持つ。形状の表現の間の変換のない関係（`SHAPE_REPRESENTATION_RELATIONSHIP`）は、そのまま並べて持つ
  - アセンブリの出現（`NEXT_ASSEMBLY_USAGE_OCCURRENCE`）は、親と子の製品と、`CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` の配置を持つ。配置の変換（`ITEM_DEFINED_TRANSFORMATION` の 2 つの配置・`CARTESIAN_TRANSFORMATION_OPERATOR_3D` の方向と原点）は、関係の 1 つ目・2 つ目の表現の文脈の単位で、幾何の記録として読む（演算子は 2 つ目の文脈）。どちらの配置からどちらへ写すかは、段 4 で決める
  - 色は、`STYLED_ITEM` からスタイルをたどって探す（`COLOUR_RGB` と、規格で名前の決まった色。同じ要素は 1 回だけたどる）。面の塗りつぶし（`SURFACE_STYLE_FILL_AREA`）の下の色を、面の境界・輪郭の線の色より優先する。同じ要素に複数の割り当てがあれば、上書きの割り当て（`OVER_RIDING_STYLED_ITEM`）、面の塗りつぶしの色の順に優先する
  - 非表示は、`INVISIBILITY` の要素とする（スタイルの割り当ては、その対象。レイヤー（`PRESENTATION_LAYER_ASSIGNMENT`）は、そこに割り当てた要素）
  - 出現の配置として読まなかった変換つきの関係は、飛ばしたと記録する
  - `MAPPED_ITEM` による配置は、初めは読まない（後の Issue）

## 10. 製品構造とエンティティ（`application`）

### 10.1 製品形状のエンティティ

- 段 3 の立体・シェルは、シェルのエンティティにする（`PRODUCT_SHAPE_ENTITY_DESIGN.md` の段階 2 のシェルのエンティティ）。開いたシェルもシェルのエンティティにする
- 読み込んだ面ごとに、新しい面の ID（`FaceId`）を作る。同じファイルを 2 回読み込んでも、面の ID は重ならない
- シェルのエンティティが、`Brep` の面の番号から面の ID への表を持つ。同じ部品の出現は `Brep` を共有し、表だけを出現ごとに別に持つ（面の ID は、出現と面の組ごとに 1 つ）
- 面への参照（CAM の加工面など）は、これまでどおり面の ID で指す
- 実装（`application::product_shape`）: シェルのエンティティは、B-rep の表（`Arc` で出現の間で共有する）・配置（相似変換）・B-rep の面の順の面の ID・元の要素（ファイルの名前・出現の並び・面ごとの元の面のエンティティの番号）を持つ。製品形状の保管先が、面単体とシェルを保持し、面の ID とエンティティの ID が両方をまたいで重ならないことを確かめる。表示と CAM の入力（トリムした面の離散化）は、段階 2 の Issue で扱うまで、シェルの面を表示中の面に含めない

### 10.2 名前

- シェルのエンティティの名前は、立体の名前とする。立体の名前が空のときは、製品の名前、それもなければアセンブリの出現の名前とする
- 立体の名前・製品の名前・アセンブリの出現の名前（出現の並び）は、エンティティの属性として残す

### 10.3 元のファイルとの対応

- STEP のテキストは、モデルファイルに残さない。変換した形状だけを残し、元のファイルなしで開き直せるようにする
- 面ごとに、元の要素との対応を残す
  - ファイルの名前、アセンブリの出現の並び、元の面のエンティティの番号
- 読み直し（同じファイルの新しい版で置き換える）は、後の Issue で作る。そのときは、元の面の番号と形が合う面に、古い面の ID を引き継ぐ。番号が変わっていれば、古い面の中の点が載る新しい面を探す
- モデルファイルには、シェルのエンティティの B-rep と、面ごとの元の要素との対応を保存する節を足す（`SPACE_MODEL_FILE_DESIGN.md`）。曲線・解析的な曲面のバイト列は `geo_io` の `binary_geometry` に足し、B-rep の表のバイト列は `application` のモデルファイルの読み書きで扱う
  - `Brep` は、表の中身（頂点・稜線・面とそのループ・シェル・立体。番号は表の中の位置）を取り出す口と、中身から表を戻す口を持つ。パラメータ曲線は持たず、戻すときに面を足す処理で作り直す。戻す口は、信用できない入力として、要素を足す処理で作り直して確かめ、取り出した表と同じ番号・向き・パラメータ曲線になる

### 10.4 アセンブリと読み込みの口

- 配置（`ITEM_DEFINED_TRANSFORMATION`・`CARTESIAN_TRANSFORMATION_OPERATOR_3D`）は、それぞれの表現の単位で読む
- 初めは、アセンブリを展開し、出現ごとに形状を配置してシェルのエンティティにする。同じ部品の形状は 1 回だけ作り、出現ごとに配置だけを変える
  - アセンブリをアセンブリのまま持つ（部品の定義と出現）のは、モデルファイルの出現の節（`SPACE_MODEL_FILE_DESIGN.md` の 13.2）と合わせて、後の Issue で決める
- 回転と移動でない配置（拡大・鏡映）は、初めは理由をつけて外す（後の Issue）
- 配置の読めない出現は、理由を残して、配置なしで読む
- 段 3 は立体ごとに独立のため、立体ごとに並列に動かせる。初めは順に動かし、結果はファイルの順にそろえる。並列にするか、ジョブマネージャーで動かすかは、大きなファイルの時間を測ってから決める
  - #1385 で測った段ごとの時間（大きなアセンブリのサンプルデータ。ファイル 18 MB・エンティティ 約 32 万・表現の要素 143。リリースのビルド）: 構文 0.26 秒・中間データ 0.39 秒・曲線と曲面 0.04 秒・位相 5.2 秒・製品構造ほか 0.2 秒。読む時間の大半は位相の段なので、並列にするなら位相の段になる。並列にするかは、まだ決めていない
- 読み込みの結果として、読めた立体の数・外した面と理由・直した向き・広げた許容誤差を返す。画面には件数を出し、要素ごとの理由はログに出す
  - 画面に出す件数は、外した要素（面・シェル・立体）・配置を読めずに配置なしで読んだ出現・拡大や鏡映の配置のため外した出現を、種類ごとに数え、0 でない種類だけを出す（合計を 1 つの言い方で出すと、起きていない種類まで起きたように読めるため）
- 実装（#1353。`application::product_shape` の `step_import`）
  - 製品の定義のうち、どの出現の子でもないものを根とし、出現を深さ優先でたどる。製品の形状の表現は、形状の表現の間のつながり（`SHAPE_REPRESENTATION_RELATIONSHIP`）を向きを問わずにたどって集め、その要素から作った B-rep をシェルにする。製品構造でたどれなかった B-rep は、配置なしで読む
  - 出現の配置は、子の形状の座標から親の形状の座標への変換にする。変換は `geo_step::geometry::rigid_transformation` が作る（配置の座標系の作り方と、座標系を作れないとみなす角度を、曲線・曲面の配置と 1 か所にまとめる）。`ITEM_DEFINED_TRANSFORMATION` は、1 つ目の配置の座標系を 2 つ目の配置の座標系に重ねる変換、`CARTESIAN_TRANSFORMATION_OPERATOR_3D` は ISO 10303-42 の軸の決め方（`base_axis`）の変換とする。関係の 2 つ目の表現が子の形状なら、逆の変換にする。倍率が 1 でない・鏡映の配置の出現は外し、配置・点・方向を読めない出現は配置なしで読む
  - 名前は、立体の名前、なければ製品の名前、なければ出現の名前。立体・製品・出現の名前の並び（根から ` / ` でつなぐ）は、メタデータの `step.solid_name`・`step.product_name`・`step.occurrence_names` に残す
  - B-rep の表の全体の許容誤差は、標準の値（1e-6 mm）とする（モデルファイルごとの値は #1357）
  - 構文の段の上限をクレートの外から変える口（`Limits::with_max_bytes`）は、呼び出し元が既定の上限を使うので、変える必要ができたときに足す
- 読み込みの口は、読む処理と、加える処理に分ける（#1385。`COMMAND_AND_BACKGROUND_TASK_DESIGN.md` 4.1・7.2・8 章）
  - 読む処理（`application::product_shape::read_step_file`）は、ファイルを読み、製品形状の保管先に加える前の形状（`StepShapes`。出現ごとのシェルと、同じ部品の出現で共有する三角形の置き場）を返す。保管先を触らないので、別のスレッドで行える。取り消しを確かめて進み具合を知らせる口（`TaskContext`）を受け取り、段の閉包をこの口に当てはめる
  - 加える処理（`ProductShapeStore::add_step_shapes`）は、読んだ形状を、出現ごとにシェルのエンティティとして加える。読む処理が失敗・取り消しで終われば、加える処理を呼ばないので、何も加わらない
  - 進み具合（`StepImportProgress`）は、今の段（構文・中間データ・曲線と曲面・位相・表示用の三角形）と、全体を 1,000 としたときの済んだ量とする。段の量は、段にかかる時間のおおよその割合で決める（構文 50・中間データ 50・曲線と曲面 20・位相 530・表示用の三角形 350）。段の初めにも知らせる（区切りに届かない小さなファイルでも、段の間で止められる）
  - 表示用の三角形は、保管先に加える前に作る（`TRIMMED_FACE_TESSELLATION_DESIGN.md` 7 章）。加えた後の表示で、画面のスレッドが三角形に分けるのを待たないようにする
  - `viewmodel` は、読む処理と、表示用の三角形を作るところまでを 1 つの処理にまとめ、別のスレッドで行う（`step_reading` の `StepReading`。文書の `start_step_reading` で始める）。スレッドを作れないときは、今のスレッドで同じ処理を行う。読めた形状は、文書の `add_step_shapes` で加え、加わった面を編集の対象の加工手順の加工の対象に加える
  - 画面（`view/app`）は、読み込みを、終わるまで実行中のまま残るコマンドとして始める（`COMMAND_AND_BACKGROUND_TASK_DESIGN.md` 10 章）。毎フレーム、ステータスバーに進み具合（全体のうち済んだ割合）と取り消しのボタンを出し、終わっていれば結果を反映する。取り消した・読めなかったときは、何も加えず、そのことをステータスバーに出す。取り消しを頼んだ後に読み終えていたときも、取り消したものとして、加えない
  - アプリで測った値（大きなアセンブリのサンプルデータ。リリースのビルド、論理プロセッサー 20 個）: 読み込みは 6.7 秒で、その間も毎秒 約 60 コマで描き続ける（フレームの間隔は最大 48 ms。前は、読んでから表示できるまでの 13 秒ほど、画面が止まっていた）。読めた形状を加えて表示するフレームは 46 ms。取り消しは、表示用の三角形の段では 17 ms で止まり、位相の段では、作りかけの表現の要素を作り終えるまで 2 秒ほどかかる

## 11. 試験

試験は、読み込みの全体（段 1〜4）と三角形への分割を通して、`application` の製品形状の読み込み（`product_shape/step_import/tests` の `conformance`・`broken_files`・`large_files`）に置く。各段だけの試験は、それぞれの段の試験に置く。

- 適合: 形を式で決めた部品の STEP を、自分で作ってリポジトリ（`tests/fixtures/step`）に置く。三角形にした結果の体積・面積・外形の箱と、B-rep の面の数を、式の値と比べる
  - 部品: 直方体・円柱・円錐（頂点まで）・球・トーラス・大半径が負のトーラスの樽と先まで（7.1）・穴の多い板・空洞のある直方体（`BREP_WITH_VOIDS`）・インチと度の単位の円錐・原点から遠い円柱
  - 正しく書いたファイルなので、外す要素も直す向きもないことも確かめる
  - 体積・面積は、許容弦誤差 0.01 mm で三角形にし、式の値との相対の差 0.2% 以内とする（曲面を内側の三角形にした差を含む）。外形の箱は、許容弦誤差以内とする
- 向き: 三角形の向き（面の外向き）から求めた、シェルの囲む符号つきの体積を、式の値（正）と比べる。空洞のシェルは負の体積として足される。面の向きの旗（`same_sense`）を逆に書いたファイルでも、ループの回りから向きを直し、体積が旗の正しいファイルと合うことを確かめる
  - 半球やトーラスの半分のように、ループのどちらの側も面になる面は、ループの回りでは向きを決められないので、この確かめから外す
- 周期的な面: 継ぎ目のある書き方と継ぎ目のない書き方の同じ部品（円柱・球・トーラス）で、体積と三角形にした結果の面積が合うことを確かめる
- 書き出しと読み直しの比較は、書き出しを作るときに足す（本書の範囲の外）
- 大きなファイル: 環境の変数 `REDRING_STEP_LARGE_FILES` で取得したフォルダを渡したときだけ読む試験とし、ファイルはリポジトリに入れない。公開されている試験用のファイル（NIST の MBE PMI の試験用の CAD モデル）の、取得の手順（`tests/fixtures/step/README.md`）と、一覧（SHA-256 とパス。`tests/fixtures/step/large_files.txt`）だけを置く。ハッシュが一覧と違えば、試験を落とす
- 壊れたファイル: 適合の試験のファイルを壊した入力で、エラーを返すか、読める要素だけを読み、パニックしないことを確かめる（読めたシェルは三角形にも分ける）
  - 途中で切る（終わりの印の前で切ったファイルは、構文の誤り）
  - バイトを替える（種を決めた疑似乱数で、位置と、数・区切り・参照・文字列の印・ASCII でないバイトから選ぶ）
  - 大きな数・有限でない値になる数（座標の上限を超える値・f64 の最大に近い値・大きな・小さな・負の・0 の半径・長さ 0 の向き・円錐の半頂角の 0 と直角・単位の倍率の 0 と負）。読めない要素は、エラーにするか、外して結果に書く。書けない大きさの数と NaN の文字は、構文の誤り
  - 壊れた参照・循環する参照（参照ごとに、ない番号・自分自身・次のエンティティに替える）
  - 深い入れ子（`ORIENTED_FACE`・`ORIENTED_EDGE` を 1 万段重ねる。引数の入れ子が構文の上限を超える）
- ファジングの道具（cargo-fuzz など）は入れない。nightly の Rust と libFuzzer が要り、Windows では動かしにくく、CI にも別の仕事が要るため。読み込みの段の入力は、上の壊れたファイルの試験で確かめる。読み込む口（モデルファイル・ジョブマネージャーとの口など）のファジングは #1249 で扱う
- 実際のファイルで見つかった問題は、問題の部分だけを残した小さな STEP にして、退行の試験にする
