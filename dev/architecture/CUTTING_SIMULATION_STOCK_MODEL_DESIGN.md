# 切削シミュレーションの素材の表現 設計書

**作成日**: 2026年10月20日
**ステータス**: 設計確定（段階 1 の実装前）
**関連Issue**: #886（本書）, #881, #882, #883, #884, #887, #888〜#892

---

## 1. 目的

大きな素材でも高い精度で切削シミュレーションを実行できる素材の表現を決める。ユーザーには、ボクセルの大きさ・Octree の深さ・ノード数を見せない。

## 2. 背景

- 現在の `cam_sim` は、素材を `VoxelOctree`（ノードに「中身あり・空・混在」の状態だけを持つ）で表す。削った面をすべて最も深い階層まで分割するため、ノード数は「削った面の面積 ÷ 精度²」で増える。100 mm の素材の全面を 0.01 mm で表すと 10⁸ 個規模になる
- #881 では暫定で深さの上限（`STOCK_OCTREE_MAX_DEPTH`）を置き、上限で達成できない精度を Preflight で `NotReady` としていた（#890 で削除）
- `CUTTING_SIMULATION_DESIGN.md` の「SAT-Cut 内部表現」で、素材の正本を工具の掃引プリミティブの差分集合とし、Voxel / Octree を表示用のキャッシュとする方針が決まっている。試作（`PrimitiveSetExactWork`）は空間索引がなく、本番の実行には使われていない

## 3. 構成

| 層 | 内容 | 精度・大きさ |
|---|---|---|
| 正本 | 初期素材 `W₀` と、工具の掃引プリミティブの時系列 `p₁, p₂, …, pₙ`。現在の素材は `W = W₀ \ (p₁ ∪ … ∪ pₙ)`。空間索引（BVH 等）を持つ | 浮動小数点の精度。メモリは工具の移動の数に比例し、精度に依存しない |
| 派生表現 | トリデクセル（X・Y・Z の 3 方向の格子の各線上の、材料のある区間の列）。正本から作る | 解像度は用途ごとに選ぶ（4 節） |
| スナップショット | 時点（プリミティブの番号）と、派生表現の変化の履歴（5 節） | 大きさは変化の量に比例する |

### 3.1 正本の問い合わせ

| 問い合わせ | 方法 |
|---|---|
| 点が材料の内部か | 空間索引で候補のプリミティブを絞り、どれにも含まれず `W₀` に含まれるか |
| 点から削った面までの距離 | 候補のプリミティブまでの距離の最小（製品との比較・削り残し / 削り込みの判定に使う。#883 の段階 3） |
| 残りの体積 | 派生表現（トリデクセルの区間の長さの和）から求める |

### 3.2 掃引プリミティブ

| 工具 | 直線移動の掃引体 | 線・点との交差・距離 |
|---|---|---|
| フラットエンドミル | 両端の円柱と、底面の円板の掃引（角柱状の部分）の和 | 解析的に求まる |
| ボールエンドミル | 先端の球の掃引（カプセル）と、シャンクの円柱の掃引の和 | 解析的に求まる |
| ラジアスエンドミル（段階 2） | コーナー R の中心が描く円を移動に沿って掃引した面を、コーナー R だけ太らせた立体と、底面・シャンクの掃引の和 | 移動のパラメータ t についての 1 変数の最小化（ニュートン法等）。3 軸の直線移動では、工具面上の接触の曲線（法線が移動方向と直交する点）は閉じた式で求まる |

円弧移動は、`CUTTING_SIMULATION_DESIGN.md` の弧の分割の規則で直線移動の列にする（円弧の掃引の厳密化は後続）。

## 4. 派生表現（トリデクセル）

- 各格子線とプリミティブの交差の区間を解析的に求め、材料の区間から差し引く。更新はプリミティブの包含箱にかかる格子線だけで行う
- 面の向きによらず、格子の間隔程度の均一な精度で形状を表す（1 方向のデクセルの急な壁の精度の問題を、3 方向で解消する）
- メモリは解像度の 2 乗に比例する
- 解像度は用途ごとに選び、正本からいつでも作り直せる

| 用途 | 解像度 |
|---|---|
| 表示（アニメーション） | 画面の画素数と同程度（それより細かくしても見た目は良くならない） |
| 確認（削り残し・削り込みの判定、指定の範囲の拡大） | 入力の精度で、指定の範囲だけを作る（関心領域。段階 2） |

- ユーザーが指定する精度（`CuttingSimulationInput::precision`）は、判定の許容誤差として使う。正本は厳密なので、精度は素材の表現の分解能を決めない
- 表示用の面（`cam_sim::DexelSurface`。#896）: 3 方向の格子線は同じ格子点を通るため、格子点の間の辺はいずれかの方向のデクセル上にある。格子点の内外を Z のデクセルで判定し、内外が変わる辺の交点をその辺上のデクセルの端点（正本から求めた厳密な点）とするマーチングキューブで面を作る。頂点はすべて正本の境界上にあり、誤差は頂点の間を平面でつなぐ分（鋭い角はセルの中で面取りされる）
  - セルの各面では「内側の頂点どうしは面の対角線をまたいでつながない」と決めて線分を作り、線分の輪を外向きにそろえて三角形にする。隣り合うセルは共有する面で同じ線分を作るため、面に穴は開かない（従来の 256 通りの表のあいまいな場合の食い違いを避ける）
  - 格子を素材の外側へ 1 層広げて空とし、素材の外周の面も作る
  - 面は 32³ セルのブロックごとに作り、スナップショットの変化（変化したデクセルの線に接するセル）から作り直すブロックを求める（部分的な再描画）
  - 論文の方式（「3 方向デクセルモデルとポリゴンモデルの相互変換技術」: 方向ごとの面を角度で選んで重ねる）は、面が重なり閉じないため採らない。鋭い角を保つには交点の法線を使う方式（デュアルコンツアリング）が要るが、成果物に法線を持たないため後続とする
- 格子線と掃引体の交差は、掃引体を凸な形（垂直の円柱・球の掃引）に分け、移動のパラメータ t についての「1 次式 ± √(2 次式)」の最小・最大として閉じた式で求める（区間の端と、微分が 0 となる点の 2 次方程式の根）。許容誤差と反復を使わない

## 5. スナップショット（#882 の成果物）

- 時点は、プリミティブの番号（ツールパスの区間とパラメータ）で表す
- 表示用のトリデクセルは、格子線ごとに変化の履歴（プリミティブの番号と、変化した区間）を記録する。任意の時点の状態を、履歴をたどって復元し、前後にスクラブする（「3 軸数値制御工作機械による曲面加工の高速なシミュレーション」の履歴保存）
- 成果物は、スナップショットの時点の列・統計と、表示用のトリデクセルの格子の配置・初期の区間と、スナップショットごとの変化（前の時点から変化したデクセルと変化後の区間）とする（#882）。掃引体ごとの履歴をそのまま入れると移動が 10⁵ 回規模で数百 MB になりうるため、表示する単位であるスナップショットの時点にまとめる。任意の時点の状態は、初期の状態に変化を順に当てて復元する
- 置き場所: 成果物の種別の識別子（`ArtifactKind::CuttingSimulation`、マジック `RRCS`）と共通のヘッダ・版の検査は cam_core、中身の型と書き出し・読み込み（`CuttingSimulationArtifact`・`write_cutting_simulation_artifact_v1`・`read_cutting_simulation_artifact_v1`）は cam_sim に置く。cam_core は中身を解釈しないバイト列として扱い、素材の表現に依存しない
- ViewModel は成果物を描画用に変換するだけで、材料除去を再計算しない（#857 の経路の方針）。ViewModel の置き換えは表示用の面（#896）ができてから #884 で行う
- 表示は、変化した範囲だけを描き直す（「部分的な再描画による NC 加工プロセスの高速なアニメーション」。#884）

## 7. 既存のコードへの影響

- `cam_sim::PrimitiveSetExactWork`・`ExactWorkModel` は、段階 1 の正本（`cam_sim::StockModel`。#888）で置き換えた
- `run_hybrid_gate_case`・`run_hybrid_gate_case_with_config`（Voxel と ExactWork の比較）は、方式を決めるための検証で、本書で方式を決めたため #888 で削除した。試作と Voxel はどちらもフラットエンドミルを「移動の経路を軸とする円柱」として扱っていた（水平の移動で横向きの円柱を除去する）ため、比較では一致していた。正本は工具軸 +Z の工具を刃長まで掃引する
- `cam_sim::CuttingSimulator` は、正本と表示用のトリデクセル（最大の辺を `TRI_DEXEL_DISPLAY_LINES` = 512 本）の上に作り直し、スナップショットの残りの体積をトリデクセルから求める（#890）。`cam_sim` は `VoxelOctree` に依存しない
- `geo_algorithms` の `VoxelOctree` は、Octree の表示の確認（`octree_converter`・fixtures）と、#882 までの ViewModel のデモの除去の再生で使うため残す
- `viewmodel` の `cam_sim_visualization_converter` が行っている材料除去の再生（`apply_cutting_progress`）は、#882 で成果物の変換に置き換える
