# リリースの版の計画

**最終更新**: 2026年11月3日

`RELEASE_VERSION_PLAN_2026Q1.md`（2026年2月）の v0.1.0 の範囲（技術プレビューの基盤）を、この文書で置き換える。版数の決まり（SemVer・0.x の間は互換性を壊してよい）は `VERSIONING_POLICY.md` のとおりとする。

## 1. 方針

- 管理の機能まで揃うのを待たずに、細かく出す。版ごとに、STL の取り込みから CAM の計算・切削シミュレーションでの確かめまでを、一通り通して使える形にする
- 理由:
  - 工程・ジョブ・工具の管理の設計は、使ってみた意見で決まる部分が大きい。揃えてから出すと作り直しが大きくなる
  - タグ・CHANGELOG・リリース前の確認・既知の制約の書き方を、小さい版で一度通しておく
  - 0.x の間は互換性を壊してよいため、細かく出しても後で変えられる
- プレビューの版は、実際の加工に使えないこと（NC を出力しない間）と既知の制約を、リリースノートとマニュアルに書く

## 2. 版の目標

| 版 | 目標 | 主な Issue |
|---|---|---|
| v0.1.0（プレビュー） | STL → スキャン加工 → 切削シミュレーションのデモを、一通り通して使える | #1013（最後の時点の素材の面を削り込み・削り残しで色分け）、#1036（マニュアル・既知の制約・CHANGELOG・リリースノート・タグ） |
| v0.2.0 | 加工を管理する（工程・ジョブ・工具） | #933、#988、#887、#914 |
| v0.3.0 | 加工に使える経路にする（つなぎの移動・NC の出力） | パスの間のエアカット・つなぎの移動（Issue 未作成）、#680〜#683、#301、#947 |
| 以降 | 大きな形状、工程の種類を増やす（等高線加工など） | #1025 など |

### 2.1 v0.1.0（プレビュー）

含めるもの:

- STL の取り込みと表示
- スキャン加工の CAM の計算（ボール・フラットエンドミル、ツールパス生成のトレランスの保証。`CAM_ALGORITHMS_DESIGN.md` 12）
- 切削シミュレーション（トリデクセル）と切削アニメーション
- 最後の時点の素材の面の、削り込み・トレランスの中・削り残しの色分け（#1013。経路がトレランスに収まることと、既知の制約の削り残しを画面で確かめる）
- 加工条件のウィンドウ（日本語・英語）

既知の制約として書くもの（例）:

- NC を出力しない。パスの間のエアカット・つなぎの移動がない
- 工具の半径より狭い隙間は、1 本のパスでつなぐ（削り込みはしない。`CAM_ALGORITHMS_DESIGN.md` 12.9）
- NURBS の入力では、三角形に分ける誤差とパスの誤差の合計が、最大でトレランスの 2 倍になる（12.8）
- ジョブは同じプロセスの中で実行し、工程を持たない（投入のたびに条件を登録する）

受け入れ条件:

- `RELEASE_VERSION_PLAN_2026Q1.md` 3. のリリース前の確認（build・test・clippy・fmt・依存関係・mdbook）が `main` で通る
- マニュアルの手順で、STL の取り込みから切削アニメーションまでを通せる
- `CHANGELOG.md` の 0.1.0 とリリースノート（`dev/RELEASE_NOTE_TEMPLATE.md`）に、含めるものと既知の制約を書く
- `main` に `v0.1.0` のタグを付ける

### 2.2 v0.2.0（加工の管理）

- 工程のエンティティと、工程ごとのジョブの結び付き（#933）
- ジョブの投入・実行・状態の確認・取り込みの UI（#988）。利用者向けの操作ヘルプ・案内を画面に出す
- ツールセットの登録と ID での参照（#887）
- ジョブのキュー・入力・成果物の保存先（#914）

### 2.3 v0.3.0（加工に使える経路）

- パスの間のエアカット・つなぎの移動（CL の編集と工程をそろえた後に計算する）
- NC のポスト処理（#680〜#683、#301）
- 工具長を超える接触の干渉のエラーと工具長分割（#947）

## 3. Issue の振り分け

- `release:in` は次に出す版（今は v0.1.0）に含める Issue とする。ほかは `release:out` とし、どの版に入れるかはこの文書の 2. に書く
- 版を出したら、次の版の Issue を `release:in` に移す
