# UI フレームワーク選定メモ

最終更新: 2026年3月31日

## 選定結論: egui 一択

RedRing（winit + wgpu 構成）に対してメニューボタン等の GUI を追加する場合、  
フレームワークは **egui**（`egui-wgpu` クレート経由）を採用する。

## 理由

| 候補 | 評価 |
|---|---|
| **egui** | `egui-wgpu` で wgpu バックエンドに直接統合可能。winit との組み合わせ実績多数。**採用** |
| imgui-rs | デバッグ用途寄り。C ライブラリバインディングでメンテコストが高い |
| iced | 独自イベントループで winit との統合が複雑 |

## 統合時の想定工数

| 作業 | 工数 |
|---|---|
| egui-wgpu 統合・描画パイプライン接続 | 1〜2日 |
| winit イベントループへの egui 入力転送 | 半日 |
| 基本メニューバー実装 | 半日〜1日 |
| **合計** | **2〜4日** |

## 統合ポイント

- wgpu のレンダーパスに egui を**後段**で合成する構造変更が必要
- 影響範囲: `app_renderer.rs` 周辺
- winit の `WindowEvent` を `egui_winit::State` に転送し、egui 側のスクリーン座標系と wgpu の座標系を合わせる

## 実施タイミング

`h` キーのログ表示で代替できている現状（Series A デモ改善フェーズ）では不要。  
Series B 以降の「本格的な操作 GUI が必要な機能」追加時に実施する。
