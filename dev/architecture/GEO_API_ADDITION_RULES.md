# Geo API Addition Rules

最終更新: 2026-10-12

## 目的

`geo_*` クレート（`geo_core` / `geo_primitives` / `geo_nurbs` / `geo_algorithms` / `geo_topology` / `geo_commons`）の公開 API を、基本の形状定義と最低限のメソッドに保つ。呼び出し元のない「将来使うかもしれない」メソッド・別名・結果が誤った簡易実装が増えると、検証されない API の名前が挙動を約束し、不具合を隠す（3 点からの円の生成が 2 点の中点を中心とする、XZ 平面への投影が XY 平面への投影を返す等）。

## 原則

**基本の形状定義と最低限のメソッドから始め、呼び出し元が必要になった時点で追加する。**

## 追加してよいもの

- `geo_contracts` の trait定義の実装
- 形状の基本の生成（`new` 等）と、定義パラメータ・構成要素の取得
- `GEOMETRY_SHAPE_SEMANTICS_DESIGN.md` の capability（評価・パラメータの逆算・最近点・距離・包含・分類・方向の反転等）のうち、呼び出し元があるもの
- 同じ変更で呼び出し元（`geo_algorithms`・業務クレート・アプリケーション等）を追加するメソッド

## 追加しないもの

| 種類 | 例 | 代わりにすること |
| --- | --- | --- |
| 呼び出し元のない公開メソッド | 品質スコア・類似度・慣性モーメント・質量特性・別アルゴリズムの体積・一括判定・並列版の検索 | 必要になった時点で、呼び出し元と一緒に追加する。案は Issue に記録する |
| 既存メソッドの別名 | `magnitude`（`length` の別名）、`xy_arc`（`from_center_radius` の別名）、`reverse_direction`（`reverse` の別名） | 正本の名前を使う |
| 別の生成方法・便利メソッド | 軸ごとの生成（`new_x_axis` 等）、`from_diameter`、`with_origin` | 基本の生成メソッドに引数を渡す |
| 結果が誤った簡易実装 | 引数を無視して自身を返す、常に `None` を返す、別の処理の結果を返す | 正しく実装するか、追加しない |
| 方針外の変換 | 非一様スケール・ミラーリング | 変換の設計（相似変換のみ）に従う |

- テストからのみ呼ばれるメソッドは、呼び出し元のないメソッドとして扱う
- 閉じた式で求まらない量（楕円の周長・曲面の面積等）の近似式・数値積分は、正しい実装として扱う。doc コメントに方法と精度を記載し、「簡易実装」とは書かない

## 判断に迷う場合

1. trait定義の実装か → 追加してよい
2. 形状の定義パラメータ・構成要素の取得か → 追加してよい
3. この変更の中に呼び出し元があるか → なければ追加しない
4. 既存メソッドと同じ処理か → 追加しない（正本を使う）

## 検出

`scripts/check_unused_public_api.ps1` が、`geo_*` クレートのテスト以外から呼ばれない公開メソッド・`geo_contracts` の trait定義のメソッドと、簡易実装・TODO の記載を一覧にする。事前チェック（`scripts/check_all_before_push.ps1`）で警告として表示し、失敗にはしない。

- 名前だけで判定するため、別の型の同名メソッドの呼び出しがあれば検出しない
- trait定義のメソッドは、実装を呼び出しに数えない
- テストのファイルと、本体ファイル内の `#[cfg(test)] mod` の中の呼び出しは数えない
- 意図して残す公開メソッド・trait定義のメソッドは `scripts/unused_public_api_allowlist.txt` に理由とともに記載する
- 簡易実装の記載の誤検出は、行末に `api-check: allow` を付けて除外する
