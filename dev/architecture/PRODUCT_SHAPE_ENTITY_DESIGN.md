# 製品形状のエンティティ 設計書

**作成日**: 2026年10月24日
**ステータス**: 設計確定（段階 1 の実装前）
**関連Issue**: #883（本書）, #917, #918, #905, #912, #380, #668, #256, #205

---

## 1. 目的

加工の対象となる製品形状（NURBS 曲面・三角形メッシュ）を Model のエンティティとして持ち、表示と CAM の入力に使う。実装を段階に分け、位相構造（面・ループ・シェル）を後の段階で入れても、ViewModel から先と CAM の入力の作りを変えない境界を決める。

## 2. 背景

- 製品形状は、ツールパス生成の入力（`CamSolverInput::geometry`。NURBS 曲面の集合か三角形メッシュ）としてだけ存在し、Model のエンティティとしては持っていない
- `GeometricEntity` の中身は線分・円・円弧だけで、Application が保持し、ViewModel が `geo_contracts` のエンティティの trait定義から描画用に変換している
- `geo_topology` は頂点・エッジ・ワイヤまで。面・ループ・シェルはない（#380）。トリムされた NURBS 面の位相・幾何・エンティティの整合は未設計（#668）
- STL は `geo_io::load_stl` で `TriangleMesh3D` になるが、アプリでは描画用の頂点に変換して表示するだけで、Model に残らない
- NURBS 曲面の三角形メッシュへの離散化（`tessellate_surfaces`）は `cam_algorithms` にあり、ツールパス生成だけが使う

## 3. 方針

### 3.1 製品形状の単位

- **ニットした面の単位はシェル**とする。シェルは面の集合と、面どうしのつながりを持つ
  - 理由: 境界で頂点のそろう離散化（工具が隙間に落ちない）、加工範囲・輪郭の抽出、製品と素材の比較（内外）、隣の面の扱いが、面どうしのつながりに頼る
- 製品形状のエンティティは、**シェル**と**面単体**（トリム面 1 枚、または三角形メッシュ 1 つ）を別の種類とする。単体のトリム面・ニット（稜線を許容誤差で縫い合わせる処理）に失敗した面は面単体のエンティティとする。どちらも同じ「面を返す」trait定義で、表示と CAM の入力に使う
  - 理由: データ交換の形式（IGES・STEP）や面を中心に作る CAD（金型設計など）では、面単体とシェルを別の種類として扱う。金型・CAM で扱う面の集まりの取り込みに合う
- STL は 1 ファイルを面単体のエンティティ（三角形メッシュの面 1 つ）とする

### 3.2 面の ID と参照

- **すべての面が、全体で一意で安定した面の ID を持つ**（面単体のエンティティの面を含む）。ニットで面単体がシェルにまとまっても、シェルを分解しても、面の ID を引き継ぐ
- **面への参照は面の ID だけで指す**。面がどのエンティティに属するかは保管先から引く。ニット・分解でエンティティが替わっても、CAM の対象・グループの参照が切れない
- フィーチャに対応する場合は、面の ID をフィーチャの出力から決まる形で作り（`EntityId::from_feature_output` と同じ考え方）、再計算しても同じ面に同じ ID が付くようにする。具体的な規則はフィーチャの設計で決める

### 3.3 レイヤー・グループ

- レイヤーはエンティティ（シェル・面単体）単位で所属する。シェルの中の面ごとには分けない
- グループは、将来シェルの中の面も所属できるようにする（所属の対象を、エンティティか面の ID とする）。段階 1 では実装しない

### 3.4 CAM の対象

- **CAM の対象は面への参照（面の ID）の集合**とする。シェルを選んだ場合は、その中のすべての面を選んだものとする
- 対象の決め方は、ピック（選んだ面・シェル・面単体）、表示中のすべて、加工範囲に含まれる形状（加工範囲に届く面）とする
- **選ばなかった面は対象外**とし、工具が当たってはいけない面（チェック面）としても扱わない
  - 理由: CAD のモデリングで、製品形状のほかにキャビ・コアの形状を同じ空間に持つ場合など、上部の形状を切削の対象から外す工程管理を行うため
- 計算の対象外にする判定は、面の向きに頼らない。位相のある面群でも外向きがそろっているとは限らないため、対象とした面すべてから、工具の高さの上限で結果を変えずに外す（#912。3 軸を前提とする）

## 4. 段階

| 段階 | 範囲 | 完了条件 |
|---|---|---|
| 1: 保持と表示（位相なし） | Application が製品形状のエンティティ（面単体）を保持する。面はトリムなしの NURBS 曲面か三角形メッシュで、面の ID を持つ。STL を Application 経由で取り込む。表示は製品形状のエンティティの trait定義から変換し、切削アニメーションに重ねる | STL を取り込むと製品形状のエンティティとして保持・表示され、表示中のすべての製品形状を面への参照の集合として CAM の入力に渡せる |
| 2: 位相 | `geo_topology` に面・ループ・シェルを加え（#380）、トリムされた NURBS 面を扱う（#668）。シェルのエンティティと、ニット（面単体からシェル）・分解を加える。トリムを反映し、境界で頂点のそろう離散化にする。稜線を表示する。三角形メッシュの位相を扱う（#256） | シェルのエンティティを、ViewModel から先と CAM の入力の作りを変えずに表示・CAM の入力に使える。ニット・分解で面の ID が引き継がれる |
| 3: 選択と比較 | ピック（面・シェル・面単体）、面をグループに所属させること、加工範囲による対象の決定、製品と素材の比較による削り残し・削り込みの判定と色分け | — |

- STEP・IGES の読み込みは段階と別に扱う（トリムされた面を扱う段階 2 の後が前提になる）
- 段階 1 の後に、製品形状から切削シミュレーションを投入し、取り込んで再生する（#905）

## 5. 段階をまたいで変えない境界

| 境界 | 内容 |
|---|---|
| 面の ID | 全体で一意で安定。段階 1 から持ち、段階 2 で位相構造の面になっても、ニット・分解をしても引き継ぐ |
| 面への参照 | 面の ID だけで指す。ViewModel と CAM の入力は、面が属するエンティティの種類に頼らない |
| 表示の trait定義 | `geo_contracts` に置く（線分・円・円弧と同じ方式）。エンティティの識別子・表示属性と、面ごとの面の ID・表示用の三角形（位置・法線・頂点番号）を返す。シェル・面単体で同じ trait定義とし、段階 2 でトリム・境界の頂点の共有が入っても変えない |
| CAM の入力 | 面への参照の集合を Application が解決し、ツールパス生成の入力の形状にする |

## 6. 段階 1 の詳細

### 6.1 エンティティ

- 種類: 面単体のエンティティだけを扱う（シェルは段階 2）。STL は 1 ファイルを面単体のエンティティ（メッシュ全体を面 1 つ）とする
- 中身: 面 1 つ。面はトリムなしの NURBS 曲面か三角形メッシュで、取り込みのときに面の ID を作って保持する（番号は使わない）
- 保管先: Application の `ProductShapeStore`（`product_shape`）。呼び出し元が持ち、エンティティを加えた順に保持する。面の ID は `geo_entity::FaceId`
- 表示属性: 既存の `DisplayAttributes` を使う。色は透明度を含む（`[f32; 4]`）ため、半透明の表示もこれで表す。表示・非表示も同じ。面ごとの強調表示は段階 3（ピック）で扱う

### 6.2 離散化

- 表示用の三角形は Model 側で作る。NURBS 曲面の離散化を `cam_algorithms` から `geo_algorithms` に移し、ツールパス生成と表示で同じ離散化を使う
  - 理由: CAM の計算と表示で同じ三角形になり、段階 2 で境界の頂点をそろえる処理を 1 か所で扱える
- 表示用の許容弦誤差は、表示の設定から与える

### 6.3 入力の経路

- STL: Application の取り込みの口から `geo_io::load_stl` で読み、製品形状のエンティティにする。ViewModel が geo_io を直接読んで描画用の頂点にする今の経路は、製品形状の表示には使わない
- NURBS: 段階 1 ではファイルからの入力はない（テストで曲面を作って確かめる）
- CAM の入力の形状: 面の ID の集合を、三角形メッシュの面は 1 つのメッシュに、NURBS 曲面の面は曲面の集合にする。両方が混ざる場合は、段階 1 ではエラーとする（NURBS 曲面をメッシュにする許容弦誤差を入力として決める必要があるため）

### 6.4 段階 1 の実装の単位

1. 製品形状のエンティティと、Application による保持・STL の取り込み・面への参照の解決（CAM の入力の形状）（#917）
2. 表示の trait定義、NURBS 曲面の離散化の `geo_algorithms` への移動、ViewModel・View での表示（切削アニメーションとの重ね合わせを含む）（#918）

## 7. 段階 2 以降で決めること

- ニット・分解のときのエンティティの `EntityId` の扱い（新しく作るか、どれかを残すか）
- 面の分割・統合のときの面の ID の引き継ぎ（位相の命名）と、引き継げなかった参照の扱い（無効にする、ジョブを再計算待ちにする等）
- 選択の単位（エンティティ・面・稜線）と、その切り替え
- 表示属性・属性を面ごとに上書きするかと、その優先の規則
- 取り込み元の要素の番号を残すか
- フィーチャの出力からの面の ID の作り方
