# コマンドの層と、時間のかかる処理を裏で動かす設計書

**作成日**: 2026年11月23日
**ステータス**: 設計
**関連Issue**: #1260（本書）, #1258（Epic）, #1259, #1261, #1262, #1263, #1264, #1265, #1266, #1267, #1385, #1243

---

## 1. 目的

時間のかかる処理（モデルファイルの保存・開く、形状ファイル（STL・STEP）の読み込み、CL 取込など）の間も、画面を止めずに操作できるようにする。そのため、次の 2 つを決める。

- 利用者の操作を「コマンド」として 1 か所に通し、処理の最中に来た操作を、すぐ実行するか・待たせるか・受け付けないかを、コマンドの宣言から決める層
- 処理を別のスレッドで行い、画面のスレッドで進み具合と結果を受け取り、取り消せる仕組み

## 2. 背景

### 2.1 画面を止めている処理

次の処理は、どれも画面のスレッドで同期して行い、その間ウィンドウが止まる（Windows では「応答なし」になりうる）。

| 処理 | 今の場所 |
|---|---|
| モデルファイルを開く | `view/app` の `app_state/model_file.rs`（`SpaceModelDocument::open`） |
| モデルファイルの保存 | 同上（`SpaceModelDocument::save_as`） |
| 形状ファイル（STL・STEP）の読み込み | `view/app` の `app_state/product_shapes.rs`（`SpaceModelDocument::import_stl`・`import_step`） |
| CL 取込・切削シミュレーションの取り込み | `view/app` の `app_state/cutting_simulation.rs`（`CuttingSimulationSession::import_toolpath`・`import_latest`） |

### 2.2 今ある仕組み

- モデルファイルの操作は、要求として列に積み（`FileAction`）、イベントの処理が終わった後（`about_to_wait`）に順に行う。ファイルを選ぶ画面は別のスレッドで開き（rfd の `AsyncFileDialog`）、閉じるまで残りの操作を待たせる。本書のコマンドの待ち行列と非同期のコマンドは、この形を一般にしたものになる
- アプリは、イベントの処理が終わるたびに描き直しを頼む（最小化の間を除く）。そのため、別のスレッドの結果は、毎フレームの問い合わせで受け取れ、スレッドから画面を起こす仕組みは要らない
- 別のスレッドで動かしている処理（ツールパスの大きさの見積もり・シェルの三角形・切削アニメーションの素材の面・ジョブの状態の問い合わせ）は、それぞれ `Arc<Mutex<…>>` などで受け渡しを書いている。共通の仕組みはない
- 保存していない変更の確かめの画面は、閉じるまで待つ形で開く

## 4. 層と置き場

### 4.1 置き場ごとの役割

| 置き場 | 持つもの | 持たないもの |
|---|---|---|
| Model の framework 層の新しいクレート | 別のスレッドで処理を 1 つ行い、進み具合・結果・取り消しを受け渡す仕組み（5 章）。コマンドの宣言・実行のスタック・待ち行列・割り込みの決め方（6 章） | RedRing の型（空間モデル・製品形状など）、画面の部品、OS ごとの違い（`platform_foundation` に置く） |
| 中間ファイルのクレート（`geo_step` など） | 中間ファイルのバイト列を読み書きする段。段の中で、区切りごとに閉包を呼ぶ（7.1） | スレッド、framework 層の型、ファイルを開くこと（`BREP_AND_STEP_IMPORT_DESIGN.md` 4.1） |
| `application` | 読む処理（ファイルを開いて読み、空間モデルに加える前の結果を返す）と、加える処理。段を順に呼び、全体の進み具合にまとめる。保存に渡す空間モデルの写し（#1263）。framework 層の型のうち、上の層が使うものの再エクスポート | 本書の処理のスレッドを作ること（`ARCHITECTURE.md` の「Application Layer の役割」。今あるスレッドは 9 章） |
| `viewmodel` | 空間モデルの文書に対するコマンド（開く・保存・形状の読み込み・計算など）の宣言と実行。非同期のコマンドの処理を framework 層の仕組み（application の再エクスポート）で別のスレッドに出し、終わったら文書に反映する | 画面の部品 |
| `view`（`app`） | 入力（ボタン・キー・メニュー・マウス・ファイルを落とす）からコマンドを作って実行の係に渡すこと。表示だけのコマンド（回転・パン・拡大縮小・表示の切り替え）の宣言と実行。毎フレーム実行の係を進めること。進み具合と取り消しのボタンを出すこと | 処理そのもの |

### 4.2 依存の決まりの変更

承認を受けて、次のように変える。クレートを作る #1261 で、`scripts/_arch_rules_data.ps1`・`ARCHITECTURE.md` の層の図とクレートの責務を更新する。

- Model の層の中に framework 層を設ける（ディレクトリは `model/framework/` の下。依存の決まりのデータでは、Model とは別の層の組として持ち、Foundation と Model の間に置く）。framework 層は、RedRing の型を知らない、使い回せる仕組み（コマンド・別のスレッドの処理）を持つ
- framework 層に新しいクレート `command_framework` を足す（コマンドの層の仕組みを持つクレートとして名前を付けた。別のスレッドの処理は `background_task`、コマンドは `command` のモジュールに置く）。依存してよいのは foundation の層のクレート（要るときに足す）だけとし、幾何・CAM・ジョブ・`application` には依存しない
- framework 層のクレートに依存してよいのは `application` だけとする
  - ViewModel が依存する Model のクレートは `application` だけ（`ARCHITECTURE.md` の「ViewModel → Model の経路」）のため、`viewmodel` は `application` が再エクスポートした型を使う。`view` は `viewmodel` が再エクスポートした型を使う（ビューはモデルのクレートに直接依存しない）
  - 中間ファイルのクレート（`geo_step` など）・幾何・CAM・ジョブのクレートは依存しない（禁止の一覧に足す）。取り消しと進み具合は std の閉包で受ける（7.1）
  - foundation の層のクレートは依存しない（下の層から上の層へ依存しない）
  - `application` はスレッドを作らない。スレッドを作るのは framework 層の仕組みの中だけとする
- 外のクレートでは、async のランタイム（tokio など）を入れない。std のスレッド・`Mutex`・原子変数で作る（5.4）

## 5. 別のスレッドの処理

### 5.1 始める

- 処理 1 つを、名前を付けたスレッド 1 本で行う。処理は、取り消しを確かめて進み具合を知らせる口を受け取る
- 結果の型と進み具合の型は、処理ごとに決める（仕組みは型を知らない）
- スレッドを作れないときは、誤りとして返す。呼ぶ側は、画面のスレッドで同期して行う（今の動き）

### 5.2 画面のスレッドからの問い合わせ

- 画面のスレッドは、毎フレーム、止まらずに次を問い合わせる
  - 進み具合（最も新しい値だけ。途中の値は捨てる）
  - 終わったか。終わっていれば、結果（成功・誤り・取り消した・panic した）
- 結果は 1 回だけ受け取る

### 5.3 取り消しと panic

- 取り消しは、画面のスレッドから頼む（印を立てるだけで、待たない）。処理は、区切りごとに印を確かめ、立っていれば止めて「取り消した」を返す
- 頼んでから止まるまでの間は、処理中のままにし、「取り消し中」と出す
- 処理の中の panic は、処理のスレッドで捕まえ、誤りとして返す（画面のスレッドに panic を持ち込まない）

### 5.4 作り方の決まり

- std のスレッドと、`Mutex`・原子変数で受け渡す。進み具合は、値を上書きして持つ（列に積まない）
- 画面を起こす仕組み（waker・イベントループへの合図）は使わない（2.2）
- 毎フレームの問い合わせは、鍵を短く取るだけにし、待たない

### 5.5 型（`command_framework::background_task`）

| 型 | 役割 |
|---|---|
| `BackgroundTask<T, E, P>` | 別のスレッドで行っている処理 1 つ。`spawn`（名前を付けたスレッドで始める）、`progress`（最も新しい進み具合）、`request_cancel`・`is_cancel_requested`（取り消しを頼む・頼んであるか）、`take_outcome`（終わっていれば結果を 1 回だけ受け取る）。`T` は結果、`E` は誤り、`P` は進み具合の型 |
| `TaskContext<P>` | 処理が受け取る口。`is_cancel_requested`（区切りで確かめる）、`report_progress`（進み具合を知らせる） |
| `TaskFailure<E>` | 処理が結果を出さずに終わった理由（取り消した・誤り）。処理は `Result<T, TaskFailure<E>>` を返す |
| `TaskOutcome<T, E>` | 始めた側が受け取る結果（成功・誤り・取り消した・panic した） |
| `SpawnError<W>` | スレッドを作れなかった誤り。始めなかった処理を持ち、`BackgroundTask::run_on_current_thread` で今のスレッドで行える（結果の受け取り方は、別のスレッドで行うときと同じ） |

- 結果を受け取らずに `BackgroundTask` を手放すと、取り消しを頼む（結果を受け取る者がいないため）
- 処理が取り消しを確かめる前に終われば、結果は取り消しにならない（成功・誤りのまま）
- 進み具合の型は、すぐ写せる小さな値にする（問い合わせは、鍵を持ったまま値を写す）。置き換えた前の値は、鍵を放してから手放す

## 6. コマンド

### 6.1 コマンドとは

- 利用者の操作 1 つを値にしたもの。入力の処理（ボタン・キー・メニュー・マウス・ファイルを落とす）から処理を直接呼ばず、コマンドを作って実行の係に渡す
- すべての操作をコマンドとして動かす（表示の操作・パネルの操作を含む）。載せ替えの順は 10 章

### 6.2 コマンドが宣言すること

| 宣言 | 値 | 説明 |
|---|---|---|
| 実行の形 | 同期・非同期 | 同期は、その場で終わる。非同期は、別のスレッドの処理や、ファイルを選ぶ画面を待つ段を持ち、終わったら画面のスレッドで反映する |
| 触るもの | 種類と対象 | 種類は、表示だけ・読むだけ・変える・入れ替える（6.4）。対象は、アプリが決める区分（例: 製品形状・加工手順）。仕組みは対象の中身を知らない |
| 許す割り込み | 種類と対象の組の集まり | 非同期のコマンドが、自分の最中に実行してよいコマンドの触るもの |
| 割り込めないとき | 待つ・受け付けない・取り消してから実行 | 来たコマンドが、走っているコマンドに許されないときの扱い。取り消してから実行は、許さないコマンドが取り消せるならすべて取り消し、止まってから実行する（取り消せないものがあれば、それが終わるのを待つ） |
| 取り消せるか | 取り消せる・取り消せない | 非同期のコマンドが、途中で止められるか（終了のときに使う。6.5） |

### 6.3 実行のスタック

- 実行中のコマンドをスタックに積む。下が先に始めたもの
- 来たコマンドは、スタックのすべてのコマンドが許すときだけ実行する（積む）。1 つでも許さなければ、来たコマンドの宣言に従い、待ち行列に入れるか、受け付けない
- 許すかは、互いに確かめる。スタックのコマンドが、来たコマンドの触るものをすべて許し、来たコマンドが非同期なら、来たコマンドも、スタックのコマンドの触るものをすべて許すこと（非同期のコマンドは、積んだ後、下のコマンドが終わって反映する間も実行中のため）。同期のコマンドはその場で終わるため、スタックのコマンドが許せば実行する
- 同期のコマンドは、実行し終えたら同じフレームの中で下ろす。非同期のコマンドは、終わって反映するまで残る
- 非同期のコマンドは、積んだ順と違う順に終わってよい。終わったものをスタックから除く（積んだときに、互いに許していることを確かめているため）
- コマンドの中から、別のコマンドを子として積める。たとえば、開くの「保存していない変更を確かめる」で保存を選んだら、開くの上に保存を積み、保存が終わってから開くの続き（ファイルを選ぶ・読む）を行う。子が失敗・取り消しで終わったら、親も続けずに終わる
- 子は、親とその下のコマンドとは照らさず、親より上のコマンドとだけ照らす（親は、自分の子をいつも許す）。親より下のコマンドは、親を許したときに、親が子として行うことも含めて許したものとする
- 親より上のコマンドが子を許さないときは、子を待たせずに、受け付けない（親が途中で止まったままスタックに残らないように。子の「割り込めないとき」の宣言は使わない）。親は、子が失敗したときと同じく、続けずに終わる
- 待ち行列のコマンドは、スタックが変わるたびに、先頭から順に実行できるかを確かめる。実行できるものを 1 つ積むたびに、残りを確かめ直す（積んだコマンドが、残りを待たせることがあるため）。実行できるものは、前に待っているものがあっても実行する（待っているもの同士の順は保つ）。そのため、保存の最中に開くが待ち、その後に条件を適用すると、適用は今のモデルに先に行われ、開くは保存の後にその変更を保存するかを確かめる
- 画面は、今受け付けないコマンドのボタン・メニューを無効にして出す。実行の係に「この宣言のコマンドを今受け付けるか」を問い合わせる
- スタックは、操作の入れ子（保存して開くなど）を、操作の記録に残すときにも使う（6.7）

### 6.4 触るものの種類と、非同期のコマンドの宣言

触るものの種類は次のとおり。

| 種類 | 例 |
|---|---|
| 表示だけ | 回転・パン・拡大縮小、表示の切り替え |
| 読むだけ | 工程を選ぶ、条件の画面を開いて見る |
| 変える | 条件の適用、工程の追加・削除、形状の読み込み、CL 取込 |
| 入れ替える | 開く・新規・終了 |

保存は、読むだけ（空間モデル）に加えて、対象「モデルファイル」を変えるコマンドとする。保存はモデルファイルを変えるものを許さないため、続けての保存は待つ。

v0.3.0 で作る非同期のコマンドは、次のように宣言する。

| 非同期のコマンド | 許す割り込み（これ以外は許さない） | 取り消せるか |
|---|---|---|
| 保存（保存を始めた時点の写しを書く） | 表示だけ・読むだけ・変える（モデルファイルのほか） | 取り消せない（初めは作らない） |
| 開く（モデルファイルを読み、終わったら入れ替える） | 表示だけ・読むだけ | 取り消せる（前のモデルのまま） |
| 形状の読み込み（STL・STEP。終わったら製品形状に加える） | 表示だけ・読むだけ・変える（製品形状のほか） | 取り消せる（何も加えない） |

来たコマンドは、許されないときの扱いを次のように宣言する。

| 来たコマンド | 割り込めないとき |
|---|---|
| 終了 | 取り消してから実行（6.5） |
| 開く・新規・保存・形状の読み込み | 待つ |
| そのほかの変える（条件の適用・工程の追加など） | 受け付けない（ボタン・メニューを無効にする） |

- たとえば、開くの最中に落とした形状ファイルは待ち、開き終えた後のモデルに加える。開くの最中の条件の適用は受け付けない（読み終えたら入れ替えるため、黙って消えないように）
- 形状の読み込みの最中に計算を投入すると、読み込む前の形状で計算する。読み込みを反映すると、加工の対象が変わるため、前の条件の計算として取り消す（今の、取り込んだ後の扱いと同じ）

### 6.5 処理の最中の終了

- 終了は入れ替えるコマンドで、割り込めないときは「取り消してから実行」と宣言する（6.2）。取り消せる非同期のコマンド（開く・形状の読み込み）は取り消し、止まってから、保存していない変更を確かめて終える。読んだものはまだ保存していないため
- 取り消せない非同期のコマンド（保存）があれば、終わるのを待ってから終える。待つ間も画面は止めない
- 「取り消してから実行」のコマンドが待っている間は、後から始まったコマンドも、それを許さず取り消せるなら取り消す

### 6.6 型（`command_framework::command`）

| 型 | 役割 |
|---|---|
| `CommandDeclaration<K>` | コマンドの宣言（6.2）。実行の形（`Execution`）、触るもの（`Access`：種類 `AccessKind` と対象）、許す割り込み（`AllowedInterrupt`：種類と、対象の集まり `TargetSet`（すべて・挙げた対象のほか））、割り込めないとき（`WhenBlocked`）、取り消せるか。`K` は、アプリが決める対象の区分の型 |
| `CommandScheduler<K, C>` | 実行の係のうち、スタックと待ち行列を持ち、受け付け方を決める部分。`C` は、アプリが決めるコマンドの値の型。コマンドの実行と、取り消しを処理に伝えることは、使う側が行う |
| `Admission` | 今出したときの扱い（すぐ実行・待たせる・取り消してから実行・受け付けない） |
| `Submission<C>` | 出した結果（実行を始めた（`Started`：識別子 `CommandId` とコマンド）・待ち行列に入れた・受け付けなかった） |

`CommandScheduler` の使い方は次のとおり。

- `admission`: 「この宣言のコマンドを今受け付けるか」を問い合わせる（何も変えない。画面は、受け付けないときにボタン・メニューを無効にする）
- `submit`: コマンドを出す。実行を始めたら、使う側が実行し、終わったら `finish` で下ろす（同期のコマンドは、実行してすぐ下ろす）
- `submit_child`: 実行中のコマンドの中から、子を出す
- `take_ready`: スタックが変わったら呼び、待ち行列のコマンドのうち実行できるものを、1 つずつ受け取る（受け取ったものは積まれている）
- `take_cancel_requests`: 「取り消してから実行」のコマンドが待っているときに、取り消すコマンドを受け取る（同じコマンドは 1 回だけ）。使う側が、その処理に取り消しを頼む

### 6.7 Undo/Redo・操作の記録・サーバーで動かす形との関係

- Undo/Redo は本書の範囲の外（別の Epic・Issue）。変えるコマンドが終わったところで、元に戻す情報を履歴に積む形を後で足せるよう、変えるコマンドの終わりを実行の係の 1 か所にする
- 操作の記録: コマンドを値で持つため、名前と引数をログに出せる。スタックで、入れ子（どのコマンドの中の操作か）も出せる
- サーバーで動かす形（#1243）: 別の PC から来た要求も、コマンドとして同じ実行の係に入れる形にできる。口と認証は #1243 で決め、本書では決めない

## 7. 進み具合と取り消しの伝え方

### 7.1 中間ファイルのクレート

- 段（構文・中間データ・幾何の変換・位相など）の関数は、std の型だけで書いた閉包を受け取る。済んだ数と全体の数を渡し、続けるか止めるかを `std::ops::ControlFlow` で受け取る（例: `FnMut(done, total) -> ControlFlow<()>`）
- 止めると言われたら、その段は、型つきの「取り消した」の誤りで返る
- 呼ぶ区切りは、構文・中間データの段でエンティティ 4,096 個ごと、位相の段で立体ごととする（`BREP_AND_STEP_IMPORT_DESIGN.md` 4.3）。中間データから曲線・曲面を作る段（`geo_step::geometry`）も、エンティティ 4,096 個ごとに呼ぶ
- framework 層のクレートにも、ほかの新しいクレートにも依存しない。IGES・CAD ネイティブの形式のクレートも、同じ形で受け取る

### 7.2 application

- 読む処理は、framework 層の仕組みの「取り消しを確かめて進み具合を知らせる口」を受け取る。中間ファイルの段を順に呼び、段の閉包をこの口に当てはめ、段ごとの重みで全体の進み具合（段と、済んだ数・全体の数）にまとめて知らせる
- 取り消しを頼まれていたら、読む処理は「取り消した」で返る（空間モデルは変えない）
- スレッドを作らない（読む処理は、呼ばれたスレッドで動く）

### 7.3 viewmodel と view

- `viewmodel` は、application が再エクスポートした framework 層の仕組みで、application の読む処理を別のスレッドに出す
- `view` は、ステータスバーに、処理の名前と進み具合（全体の数が分からなければ、動いている印）、取り消しのボタンを出す。取り消しを頼んだら「取り消し中」と出す。文言は一般的にし、具体的な手順はマニュアルに書く

## 8. 終わったときの反映

- 結果は、画面のスレッドで、そのコマンドの続きとして一度に反映する（文書を変える・表示を作り直す・知らせを出す）。GPU の資源を作ることは画面のスレッドで行う
- 開く: 読み終えたら、文書を入れ替える。取り消した・失敗したら、前のモデルのまま（失敗の理由を出す）
- 形状の読み込み: 読んだ形状を製品形状に加え、反映するときの編集の対象の加工手順の加工の対象に加える（今の `import_shapes` の後半を、反映のときに行う）。取り消した・失敗したら、何も加えない
- 保存: 保存を始めた時点の空間モデルの写し（#1263。大きなデータは共有し、写しを安く作る）を書く。文書は変更の番号を持ち、写しを作ったときの番号を覚える。書き終えたら、保存先を開いたファイルにし、今の番号が覚えた番号と同じときだけ、保存していない変更を消す（保存の後に変えたものは、保存していない変更として残る）
- 反映の後に、待ち行列のコマンドを確かめる（6.3）
