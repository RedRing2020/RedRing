# テストの配置ルール

最終更新: 2026-10-12
適用範囲: ワークスペースの全クレート

## 1. 目的

テストの置き場所を、モジュールの構成とテストの長さで一通りに決める。テストを探す場所が一つに決まり、本体のファイルがテストで読みにくくならないようにする。

## 2. 規則

| モジュール | テストの置き場所 |
| --- | --- |
| 単一ファイルのモジュールで、テストが短い（目安 150 行以下） | 同じファイルの末尾の `#[cfg(test)] mod tests { ... }` |
| テストが長い（目安 150 行を超える）モジュール | `x.rs` + `x/tests.rs`（テストだけの子モジュール） |
| 子のファイルに分かれたモジュール（`x.rs` + `x/bounds.rs` 等） | `x/tests.rs` にまとめる。子のファイルにテストを置かない |
| 複数のモジュール・形状にまたがり、公開 API だけを使うテスト | 結合テスト（`tests/`） |

- 単一ファイルのモジュールのテストを同じファイルに置くのは Rust の慣習に従うためで、コードのすぐ下でテストを見つけられる
- 子のファイルに分かれたモジュールは、テストを `tests.rs` にまとめ、形状・型ごとにテストを探す場所を一つにする
- `x/tests.rs` は `use super::*;` で親の要素を使い、`mod tests { ... }` で包まない
- テストの子モジュールは、親の先頭の doc コメントの直後で `#[cfg(test)] mod tests;` と宣言する

## 3. 使わない書き方

- `#[path = "x_tests.rs"]` で兄弟のファイルを読み込む書き方
- 親モジュールから `#[cfg(test)] pub mod x_tests;` のように、テストを兄弟のモジュールとして宣言する書き方

どちらもテストが本体と別のモジュールになり、エディターでの表示にネストの設定が必要になる。
