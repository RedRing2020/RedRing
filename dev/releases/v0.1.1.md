## Summary

v0.1.0 の修正版です。セキュリティの修正を含むため、v0.1.0 をお使いの場合は v0.1.1 をお使いください。細工した成果物・STL のファイルを開くとアプリが落ちる（巨大なメモリの確保をさせられる）問題を直し、依存クレートの既知の脆弱性を直しました。加工の条件は、内部で加工手順・加工工程として持つようになり、取り込みは、今の条件と表示中の製品形状で計算した結果だけになりました。

## Highlights

### Added

- 加工の条件を、加工手順・加工工程（工程の ID と改訂の番号）として持つ。ジョブは投入元の工程と改訂の番号を持つ
- 依存クレートの検査（`cargo deny`。脆弱性・ライセンス・取得元）を CI と週に 1 回の実行で行い、Dependabot で依存と GitHub Actions の更新を知らせる（`dev/DEPENDENCY_AUDIT_OPERATION.md`）

### Changed

- 取り込み（「取り込み」・`Shift+L`）は、今の条件と表示中の製品形状で計算した結果だけを取り込む。条件や表示中の製品形状を変えた後は、投入し直すまで取り込めない
- GitHub Pages のマニュアルは、利用者向けの「はじめに」と「切削シミュレーション 操作」だけにした（開発者向けのページは、今のコードに合わせて作り直すまで目次から外した。#1063）

### Fixed

- 【セキュリティ】成果物（ツールパス・干渉・切削シミュレーション）とバイナリの STL の読み込みで、ファイルに書かれた個数・長さのとおりに先にメモリを確保していたため、細工したファイルで巨大な確保をさせてアプリを落とせた。個数・長さを確かめてから確保する（#1083）
- 【セキュリティ】依存クレートの既知の脆弱性を直した: crossbeam-epoch（RUSTSEC-2026-0204）、quick-xml（RUSTSEC-2026-0194・0195）、webbrowser（RUSTSEC-2026-0257）。健全性の注意のある anyhow・memmap2・rand・tokio と、取り下げられた版の clipboard-win を上げた（#1084）
- 【セキュリティ】GitHub Actions をコミットで固定し、書き込みの権限を公開のジョブだけにした（#1085）
- 加工条件のウィンドウで、ピックフィードが工具径を超える誤りに出す工具径を、投入した工具の径にした
