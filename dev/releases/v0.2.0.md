# RedRing v0.2.0（プレビュー）

## Release Information

- Version: `v0.2.0`
- Release Date: 2026-11-23
- Target Branch: `main`
- Related Milestone: なし（`dev/architecture/RELEASE_VERSION_PLAN.md` 2.2）
- Related Issues: #933（工程とジョブの結び付き）、#988（ジョブの投入・状態・取り込みの UI）、#887（ツールライブラリ）、#914（ジョブのキュー・保存先）、#1068（モデルファイル）、#1076〜#1081（ジョブマネージャーと区間の切削シミュレーション）、#1324・#1379・#1351・#1354（STEP の読み込みと加工）

## Summary

加工を管理できるようにした版です。ツールパス生成と切削シミュレーションは、アプリとは別のジョブマネージャーが計算し、計算の間もアプリの画面は止まりません。加工手順に複数の加工工程を持て、工具はツールライブラリに登録して工程から選びます。切削シミュレーションは、前の工程の後の素材から削ります。STEP の形状を読み込んで加工の対象にでき、製品形状と加工手順はモデルファイル（`.rrm`）に保存できます。

実際の加工にはまだ使えません（NC を出力しません）。加工の管理と切削シミュレーションを試すためのプレビューです。

## Highlights

### Added

- ジョブマネージャー（`redring-job-manager.exe`）とランナー（`redring-batch-runner.exe`）。ツールパス生成と切削シミュレーションをアプリの外で計算し、アプリを閉じても計算を続ける。ジョブの一覧・詳細・ログ、停止と計算再開（中断したツールパス生成は続きから計算する）、取り消し・再計算・まとめて削除、進み具合のバーと残りの目安、タスクトレイと終わったときの知らせ、保存先の変更、画面の言語（#1076〜#1079、#1156、#1235、#1317）
- 工程リスト（画面の下）と、工程の設定・手順の設定のダイアログ。加工工程を加える・複写する・消す・並べ替える・名前を変える。工程ごとの計算の状態（未設定・条件エラー・計算待ち・計算中・計算済みなど）と、計算・再計算・計算停止・全工程を計算（#1195、#1200、#1204、#1238、#1242、#1246）
- ツールライブラリ（`.rrtl`）。工具（ツールセット）を登録し、工程の工具をライブラリから選ぶ。共有のフォルダに置いて、複数の PC から使える（#887）
- モデルファイル（`.rrm`）。製品形状・加工手順・加工工程・取り込んだ CL を 1 つのファイルに保存し、開き直すと前に計算した結果をそのまま取り込める（#1165〜#1167、#1080）
- STEP ファイルの読み込み（AP203・AP214・AP242 の B-rep）。アセンブリを展開し、部品の出現ごとに配置した位置に加える。シェルの面（NURBS 曲面の上の面を含む）を加工の対象にできる（#1324、#1353、#1379、#1351、#1417）

### Changed

- 切削シミュレーションは、加工の順に、前の工程の後の素材から削る。前の工程を変えると、後の工程の切削シミュレーションは計算し直し待ちになる（CL は今の条件のまま使う）（#1081）
- 計算の前のツールパスの大きさの見積もりと、工程の条件の確かめで加工の対象の形状を作る処理を、別のスレッドで行い、STEP の形状でも画面を止めない（#1234、#1442）
- 加工の対象を、面の表示から切り離した。見るために面を隠しても、加工の対象は変わらない（#1275）
- ジョブの保存先を、利用者だけが読み書きできるこの PC のフォルダに限った（#1248）
- アプリとジョブマネージャーのログを、前の 5 回分残す（#1252）

### Fixed

- 大きな製品形状・大きな CL を表示すると、GPU のバッファーの上限を超えて異常終了していた（#1254、#1268）
- Windows で、ファイルを選ぶ画面で「PC」「ダウンロード」を選ぶと、中身が出なかった（#1441）
- フラットエンドミルの走査線の仕上げで、ほぼ鉛直な壁の近くの CL が 1 点だけ壁の下まで下がることがあった

### Security

- 依存クレート url の既知の脆弱性（RUSTSEC-2026-0592）を直した

## Breaking Changes

- 加工条件のウィンドウ（`Shift+M`）は、工程リストと、工程の設定・手順の設定のダイアログに分かれた。メニューバーの「加工」から加工手順を開く
- 計算は、アプリと同じフォルダのジョブマネージャーとランナーで行う。ソースからビルドするときは `cargo build --release` で 3 つをビルドする
- 加工条件のウィンドウの「投入したらすぐ実行する」と `Shift+R` はなくなった（計算はジョブマネージャーが投入の順に行う）

## Migration Guide

- v0.1.3 には保存のファイルがないため、移すデータはない。製品形状を読み込み直し、加工手順を組み直す
- v0.1.3 のジョブの結果は使えない

## English

### Summary

This release makes machining manageable. Toolpaths and cutting simulations are calculated by a job manager separate from the app, and the app screen does not stop during the calculation. A machining sequence can have several machining operations, and tools are registered in a tool library and selected from operations. The cutting simulation cuts from the stock left by the previous operation. STEP shapes can be loaded and used as the machining target, and product shapes and machining sequences can be saved in a model file (`.rrm`).

It cannot be used for real machining yet (no NC output). This is a preview for trying machining management and the cutting simulation.

### Highlights

Added:

- The job manager (`redring-job-manager.exe`) and the runner (`redring-batch-runner.exe`). They calculate toolpaths and cutting simulations outside the app and keep calculating after the app is closed. Job list, details and logs; stop and resume (a stopped toolpath calculation continues where it stopped); cancel, recalculate and bulk delete; a progress bar with the remaining time; the tray icon and notifications when jobs finish; changing the store folder; the screen language
- The operation list (at the bottom of the screen) and the operation settings and sequence settings dialogs. Add, duplicate, delete, reorder and rename machining operations. The calculation state of each operation (not set, condition error, waiting, calculating, calculated, and so on), with calculate, recalculate, stop and calculate all
- The tool library (`.rrtl`). Register tools (toolsets) and select the tool of an operation from the library. A library can be placed in a shared folder and used from several PCs
- The model file (`.rrm`). Saves product shapes, machining sequences, machining operations and imported CLs in one file. After reopening, results calculated before can be imported as they are
- Loading STEP files (B-rep of AP203, AP214 and AP242). Assemblies are expanded, and each part occurrence is added at its placed position. The faces of shells (including faces on NURBS surfaces) can be used as the machining target

Changed:

- The cutting simulation cuts in machining order from the stock left by the previous operation. Changing a previous operation makes the cutting simulations of later operations wait for recalculation (the CL of the current conditions is reused)
- The toolpath size estimate before calculation and the shape building in the operation condition check run on another thread, so the screen does not stop even for STEP shapes
- The machining target is separated from the face visibility. Hiding faces to look inside does not change the machining target
- The job store folder is limited to a folder on this PC that only the user can read and write
- The app and the job manager keep the logs of the previous 5 runs

Fixed:

- The app crashed when a large product shape or a large CL exceeded the GPU buffer limit
- On Windows, choosing "This PC" or "Downloads" in a file dialog showed no contents
- In flat end mill scanline finishing, a single CL point near an almost vertical wall could drop below the wall

Security:

- Fixed a known vulnerability in the dependency url (RUSTSEC-2026-0592)

### Breaking Changes

- The Machining Conditions window (`Shift+M`) is split into the operation list and the operation settings and sequence settings dialogs. Open a machining sequence from the "Machining" menu
- Calculations run in the job manager and the runner in the same folder as the app. When building from source, build all three with `cargo build --release`
- "Run immediately after submitting" and `Shift+R` in the Machining Conditions window are removed (the job manager calculates in the order of submission)

### Known Issues

- No NC output (v0.4.0). No air cuts or linking moves between passes
- The screen stops while a STEP file is being loaded (v0.3.0)
- The toolpath calculation does not consider what the previous operation has cut
- The cutting animation plays only the segment of the selected operation. There is no comparison of the result of the whole sequence
- Operations skipped in a calculation are not shown. Recalculating while a job is waiting or running adds jobs to the job manager list
- The package is for Windows only. The executable does not have a code signature yet, so SmartScreen shows a warning the first time you start it
- See "Known Issues and Troubleshooting" in the manual for the rest
